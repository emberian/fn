# Registered render window terminal source

This is an internal, uninstalled source component. It does not establish a
served release path or a new admission policy. The normal include cohort,
actual acquisition and native epilogue remain open.

`fn-rh-window-terminal-step(fuel, RH, MIO, pool)` returns status, receipt,
remaining fuel, MIO and the same pool. RH is read-only. It derives the full
query from RH and its segment address from that query, checks the current
registered slot, and reads the current input context. It accepts no host
root, row, cursor, physical address or joined observation.

The new context is fixed10, preserving its old prefix and storing the
fixed12 receiver custody row in field9. Custody field11 retains the physical
window holder. Its protocol is root7, then cursor12 retaining that same root,
then receipt7. A root names the full issued window token, immutable source,
original recipient, selected query, origin and assigned worker identity.
The receipt preserves those same references. A supplied tuple or a returned
flag is not a producer of that receipt.

The current implementation only advances an already-installed cursor. Scan
consumes one binding row; rebuild consumes one retained prefix cell. The
cursor retains the original binding graph, captured revision, immutable
root, intent and receipt through every yield. Fixed custody/context wrappers
are reconstructed at the current slot. Missing registry children are checked
before GET; raw default-creator lowering remains a separate runtime question.

Old context9, root7 and unsupported phases are unavailable. Stale slot,
query or captured revision returns stale. A ready cursor returns
`:commit-unavailable` without rebuilding or changing current storage. The
component never emits a receipt, removes an actual binding, debits the pool,
clears the query input or completes an allocating turn. Fuel bounds scanner
actions; it is not allocation authority or a physical return observation.

Actual acquisition must check the current holder before spending a replacement
PRS identity. A live root/cursor yields busy and retains that holder; the
literal OVER ONE requires one outer scalar borrow. Callers needing overlapping
windows require distinct retained holders. A peek does not complete the outer
borrow merely because it leaves a cursor unchanged.

The actual epilogue must derive the recipient-bound terminal recipe from the
registered holder after worker return or definite join, dynamic bindings and
last sanctioned aliases have returned. Persist that receipt before clearing
query input. Renderer plan progression and outgoing-window return remain
separate: an initial plan is not compared for equality with its current
remainder, and a socket write does not establish settlement.

Revision publication requires the complete binding-mutating producer cohort,
a represented nonwrapping domain and retained intent/fault handling. The old
DATA5 keeper is not migrated by this component. Original and partial graphs,
permanent capacity U and cumulative allocation A remain accounted; logical
cursor completion does not imply heap reclamation or a refund.
