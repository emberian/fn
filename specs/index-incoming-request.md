# Incoming index query begin

PRF-1172 / SCN-1058: additive source candidate, not activated.

`fn-owner-index-incoming-begin(fuel,mio,arena,pool,state)` returns
`erp,status,indexToken,left,mio,pool,state`. The public ABI supplies no
holder, context, Message-ID, publication, demand, control or native job token.
It reads actual retained context and sole STATE freshness, rechecks authority,
and reads actual current publication through the exact registered live/current
generation. Continuous owner exclusion spans recheck, adoption and attachment;
each resumed call rechecks again. Publication registration alone is not the
root-owned durable STATE C/F/arena correspondence.

The internal incoming issuer uses the SAME request pending/free/highwater and
shared PRS ledger. PRS debit precedes request/receipt/control construction.
Receipt retains OLDNEXT as spent identity, nonce is OLDNEXT+1. Incoming request
and receipt tags differ from reader requests; no RC/pin-specific reserve or
pending-range adapter is invoked. Distinct incoming scratch marker prevents
double debit, and records exactly-once registered generation retention.

Generic child adoption receives a bounded internal compatibility projection
only after incoming eligibility; original incoming receipt is retained in
context field4, payload is field5. ZERO additional scratch is passed because
the pending receipt already includes D+S. No projection creates runtime or
source authority. Address advance/clear occurs only after adopted delta1 and
actual QPG token. Attachment changes phase1/queryToken11 only; custody fields
2–10 remain the original borrowed refs/scalars. Failure after adoption retains
the token and original roots for recovery rather than a standalone setter.

Actual runtime constructor and scratch issuer are absent. Their source seam
returns unavailable even for a runtime-shaped provider object. The positive
internal suffix and constructed fixtures cannot be cited as public activation.
All guard/refinement/teeth and matched bounded source evidence are still open.

If lower child adoption returns recovery-required, it may already have
registered the query. The incoming wrapper retains the returned ledger and
attempted query token, fences the marker as generation-retained-uncertain,
and leaves pending receipt/address custody intact. The host propagates that
uncertainty with the token and preserves saved authority roots; it does not
attach a query or retry adoption from that marker.
