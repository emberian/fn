# C foundation gaps (recorded when encountered)

## GC1 — A: bounded pool comparison primitive
Needed exact Message-ID equality without byte-list conversion (STORAGE-DESIGN.md:6; FILTERS-2026.md:26-30; EXECUTION-MODEL.md:20, one pool). Pool exports at `fn2/books/pool.lisp:344-366` expose scalar read/write but no resumable range comparison. Sprint workaround is `fn2/sprint/c/runs.lisp:103` (`fn2-sc-compare`): at most 250 byte-pair comparisons (500 pool reads) per identity, charged against a 4096-byte lookup budget. Stored ranges and query ranges are live workspaces owned by the explicit shared sprint owner (250,0,1); no implicit owner bypass. A range primitive with two explicit owners should replace it.

## GC2 — B: commit installation and run lifecycle absent
Needed sealed run roots installed only through B's durability protocol (C brief:6-9; STORAGE-DESIGN-ASTRA.md:462-496). `fn2/books/machines-a.lisp:93` ends with scribe and closes the machine registry without a commit kind; `fn2/books/merkle.lisp:1` and `fn2/books/alloc.lisp:1` supply digest/frontier and allocation models, but no B3 commit machine, recovery, checkpoint, or cleaner exists in the checkout. `fn2/sprint/c/seal.lisp:1` builds and hashes an in-pool run page and calls its state `:sealed-volatile`; this is explicitly not durable publication. Pinned workspace handles replace physical object leases for the duration of fixtures. B3 must accept the dependency page, fence, atomically install roots, and retain retirement obligations.

## GC3 — B/C catalogue seam: schema-specific run layouts absent
C brief:6 requires run pages and exact identity schema; STORAGE-DESIGN-ASTRA.md:343-347 requires schema header, ordered entries, offset directory and checked continuations. B's format catalogue `fn2/books/format.lisp:280-321` has page-header/membership-entry but no run schema header or identity entry layout. These are legitimately C-designed schemas; the gap is the extension seam in B's closed list, not a claim that B should design C's schema. Sprint `fn2/sprint/c/seal.lisp:9` declares those data layouts beside B's real page header; B's single layout interpreter encodes them. No codec or declaration macro is duplicated.

## GC4 — A: native u64 column kind not yet present
ROUND2-ASTRA.md:151-157 gives persistent identities/positions and resource widths as u64 words; the binding A-WIDTH-PER-COLUMN ruling permits a u60 interim destination until R5a. `fn2/books/columns.lisp:31-34` only recognizes u8/u16/u32/u60/bool widths. `fn2/sprint/c/runs.lisp:8-10` therefore uses u60 group/number/tag/generation columns and returns `:bounds` instead of wrapping or narrowing a value that does not fit; `fn2/sprint/c/seal.lisp:57-61` uses fixed fixture history/incarnation/epoch/allocation values 1. This is not a full-width persistent namespace implementation. R5a's native u64 columns should replace the interim destinations when the real C persistent identity schema lands.
