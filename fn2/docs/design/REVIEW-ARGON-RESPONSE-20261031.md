## Confirmed defects (routed)

- **§9.8 / §9.13.4: the turn's work bound is stale.** `*fn2-turn-transition-max*` (executor.lisp:6) is the max over listener, echo and scribe (4,128); the cursor's budget is 8,192 and the txn's 16,384, and `fn2-turn-work-room-p` (executor.lisp:137) uses the stale bound, so a turn can overrun its declared work. The bound and the label list must be derived from the registry over every registered kind. **Form seat (A's executor), now; part of P4's open per-kind run rewrite.**
- **§9.9 bug 2: equal versus behind in the consumer ack.** `folds.lisp:38` has `:when (< position to) :unless-when :unchanged`, so an ack with `to` equal to the recorded position and an ack with `to` below it both answer `:unchanged`, and E maps `:unchanged` to `behind`; the port's contract is equal → accepted with no write, lower → behind. **E's arm decides:** read the position before staging; equal answers accepted with no transaction; lower answers behind; only greater stages, and an `:unchanged` after the stage (a race) re-reads the position and answers by the same rule. C changes nothing.
- **§9.9 bug 1: a retry after grant narrowing.** `e-surface.md` §3.3 left "an outcome(op) lookup of the principal's own retry table" owed; Argon shows Mini's recovery cut c2 hits it. **Ruled:** the append handler reads `fn2-outcome(principal, op)` before the target stream's write grant; reading one's own recorded outcome needs authentication only. E records it in §6's order (principal, then the outcome lookup, then grant, then meter).
- **§9.9 bug 3: v2 cursors refused when their fields fit v1.** Friction with no safety value. **Ruled:** a node issues v1 while fields fit and v2 beyond, and accepts either form from a client; the cursor's bytes are compared exactly against the server's own encoding of the same fields (no HMAC today). E's §3.1 is rewritten accordingly.
- **§9.7: `:rank N` beside an ordered list.** The rank is the position; the hand number only causes renumbering churn (three renumberings today). **D: `fn2-resource-rank` = 1 + position in `*fn2-resource-order*`; the `:rank` keys and the length pin go; the certify checks stay.** The twin tables `*fn2-resource-bundles*` / `*fn2-resource-releases*` are derived from the machines' `:holds` and `:effects` once every kind is in the form (they are the pre-form record; D deletes them at the conn port).
- **§9.7: the uncertain wedge.** An `:uncertain` transaction holds its row, upload, window, reservation and claim until recovery; later offers of the same Message-ID park behind the claim; with two uncertain batches nothing new can commit, so uploads pile up behind claims. Not a cycle, a liveness wedge. **Ruled:** once any batch is `:uncertain`, the node's serving posture is `:draining` (D9's `ServicePosture`, brought forward): new POST/append/IHAVE are refused by word (`:unaffordable` with the uncertain reason) at admission, not parked; existing work drains; recovery resolves. **D and B** (the commit kind signals the posture; the txn kind reads it).

## Design points, ruled

- **§9.10: feed state transitions must not be durable per reply.** A durable commit per CHECK/TAKETHIS reply per peer multiplies the single commit stream by 1 + 3P. **Ruled:** an outbound feed keeps only its durable consumer cursor plus an in-memory sliding window of in-flight offers on the connection row; the cursor ack is held until the contiguous prefix of the window has terminal replies and is batched every N articles or T ms; on reconnect it resumes from the durable cursor and re-offers by CHECK. `e-surface.md` §13.3's feed-entry transitions are rewritten to this; the feed-entry record keeps only what survives a restart (the terminal disposition per delivery identity, written once). **E, when peering starts; no code now.**
