## What the guide covers (both parts, the AI part terser)
1. The logic and the prover: what ACL2 is (first-order, total functions, the waterfall), why proofs fail, how to read a failed proof (checkpoints, the key checkpoint, :hints, :use, :cases, :expand, induction schemes), rewriting discipline (loop-stoppers, free variables, forward chaining, type-prescription, linear), the theory (enable/disable, local, in-theory), books and certification, the local/non-local boundary, `include-book` closure and certification cost.
2. Modelling: records vs stobjs vs abstract stobjs (defabsstobj: the correspondence/preservation obligations, when it pays, when it traps you, with fn's catalog as the worked example), MBE and guard verification, defexec, fixed-width arithmetic (u64, bit vectors; FGL/GL for bit-blasting), arrays and single-threaded objects, with-local-stobj, memoization, stobj-let and nested stobjs, how to model I/O and the OS (fn's byte-store crash model; where it is weaker than hardware; what a tougher model looks like, from the papers), state machines and step functions, refinement proofs (the pattern that worked in fn's recovery refinement), functional instantiation and generic layers (def-loop), teeth (a theorem must have a mutant that bites; keystones).
3. High-performance software in ACL2: the executable/logical split (mbe), static allocation and fixed-size stobjs, no consing on hot paths (how to find consing: profiling under SBCL, `(time ...)`, the fn hot-path checker's idea), batching and group commit as modelled state, one executor loop, TigerStyle's rules translated to ACL2 (assertions as guards, bounded everything, no allocation after init, deterministic simulation), and code generation: Kestrel's ATC (ACL2 to C) and APT (program transformation) as the route to a tiny shipped core; what a metaprogramming layer (a record/column DSL, a machine DSL, a command-grammar DSL) buys and costs.
4. Process: statement-first, the premise/teeth/satisfiable discipline, what to prove early vs late (semantics-first: build the implementation, test it classically, then prove what you want assurance from), how not to drown in checkers and ledgers (fn's third sin), how to size proofs, when to skip-proofs honestly, how to run ACL2 as a REPL from an agent (one session, certify a changed book yourself, host and cache pitfalls).
5. For AIs specifically: a pitfalls-first checklist (the ten ways an agent wastes a day in ACL2, each with the fix), the form shapes that work (copy them, don't guess), how to read the manual via XDOC from a shell, how to batch verification instead of one-statement loops (ember's words: "iterating across the whole system and using mental simulations ... without wasteful rerun loops").
