## 6. Laws every layer keeps
- **The derived path is the only path** (DSL-METATHEORY, the law of §1): everything a declaration's kind generates is generated by the declaration; nothing of that list is hand-written beside it. In a machine: `:do` calls only defcost'd operations and the range primitives (a kind needing a new primitive declares it with defcost in its own book); hand `defthm`s in a kind's book are refused unless they are about a declared operation (ember 10-30: "yes, vital"); a kind's capacities are profile values or declared bounds, never literals.
- **Assert, never absorb** (REVIEW-SINS-20261028). A result is routed or the core stops with a named reason; no discarded return code, no setter that silently does nothing, no reader that returns 0 for invalid input, no clamp, no `assert$?` where the logic and the executable can disagree.
- **The DSLs generate meaning, not storage.** Enums by declared name, fields by name, packed handles, layouts compiled to codecs, one named sentinel; a generated `mv` over a collection nests from its first version (the 32-value limit is the generator's problem, never a kind's).
- **Layers meet at seams.** A layer reaches another's state only through a registered seam (core children, the machine registry, the pool's exports, defcost'd operations).
- **One representation for bytes.** Handles over pool ranges; the octet list only in the logic; any `(coerce ... 'list)` on a served path is a red; per-octet exports exist only in the logical reference.
- **Bounded everything, simultaneously; exhaustion is a continuation.** No compile-time ceilings and no arbitrary stored-data ceilings (ember); representation never drives semantics.
- **Keep the eventual proof in mind.** Every machine and format comes from a declaration that can emit its obligations; the keystones are written as `defthm-owed` with teeth (statement first, a satisfiable pre-state and a refuting mutation) and recorded in OWED.md; 0 proved is ember's ruling, not a debt to pay now.
- **The one-minute rule** (ember 10-28: "no book should be over 1m"), as a number the nightly reports: a book over 60 s is its owner's to fix, by proving the shape once generically, splitting along a real boundary, disabling what the proof does not need, or a cheaper statement of the same contract; never by raising a step limit or weakening a statement. A continuation records a book's time only when it crossed a minute (the number and the fix).
- **No pricing** (ember 10-29: "pricing isn't something we usually bother to do. it doesn't actually help us complete the project"). Plans state what they do, what accepts them and what they wait on; a piece that does not close in two sessions is investigated (scope, capacity or design, named), not pushed.

- **Detached runs.** A detached run (certify, driver, sweep) starts in its own session and its PID file holds the group leader: on Linux `setsid sh script & echo $! > X.pid`; on macOS (no setsid binary) `nohup perl -MPOSIX -e 'POSIX::setsid(); exec @ARGV' CMD ... & echo $! > X.pid`. Check `kill -0 $(cat X.pid)` and that `ps -o pgid= -p $(cat X.pid)` equals it before launching the next. Stop it with `kill -- -$(cat X.pid)` and nothing else. A PID file naming a dead wrapper is how every orphan of 10-30 happened.
- **Disk.** Under 60 GiB free on the laptop, or any disk pressure anywhere: stop writing, report BLOCKED with `df` and the ranked `du` of your own trees, wait; delete nothing to make room.

## Stopping processes: PID file or nothing (incident 2026-10-10)

A subagent ran `pkill -f "cat" -u ember` to clear its own stuck `cat`. `-f` matches the whole
command line, every app lives under `/Appli**cat**ions`, and 44 of my apps and agents got SIGTERM.
- **Never kill by pattern.** No `pkill -f <anything>`, no `pkill -x <bare word>`, no `killall`, no `kill -u`.
- **A process you started is stopped by the PID in its PID file**, and only that. Every detached job
  writes one (`nohup ... & echo $! > job.pid`). No PID file, no kill: tell me instead.
- If you must look first, `pgrep -fl` and read the list; it is never the argument to a kill.
- Every subagent brief you write quotes this block verbatim.

And: never `git stash`, never `git add -A`, named paths only; Codex never pushes; hbox builds under `swarm-build`; never an unfiltered test suite; the secrets check before every push.
