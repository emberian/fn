## What to decide and write (`/Users/ember/dev/fn/build/coordinator/fn2/DSL-METATHEORY.md`, saved after each section)
1. **The notion of declaration.** One: a presentation `(kind, name, signature, laws, provenance)`; kinds: data (columns, layout, shape), behaviour (machine, callback, Decide/command), relation (projection, port, migration, summary, correspondence), obligation (owed, square). What every declaration generates, as a fixed list per kind: the carrier (SoA stobj or flat form), accessors and updaters with bounds in guards, the codec, the logical view (never executed), the registry entry, the obligations it emits into the square table (which G0/G1/G1q/G2 schemata, with their contracts named), the simulator hooks (what checker reads what), the owed stubs, the ATC lowering. Nothing a declaration does not generate may be hand-written beside it (nanodregg law 1: a second shape is a defect).
2. **The registry.** One world table schema that every kind writes into (defcolumns' `fn2-columns`, defmachine's `fn2-machine-kinds`, defcorechild's children, the owed table, B's layouts, and the planned projections/ports/migrations) and that the assembly, the reference generation, the checkers, the owed export and the later proofs read from; the dependency order it induces; how a book declares without instantiating (library) and the assembly instantiates once.
3. **The obligation table and its consumers.** Each declaration emits squares; the simulator's generator mode (COHERENCE §5) enumerates them; the owed export lists the ones not yet proved; the proof route (SOFT/functional instantiation for the generic ones, propagate-iso for representation changes) discharges them. Show with the 39 G1 schemata of layer A: which declaration each belongs to, and what today is hand-written that the table would replace.
4. **The generic lemma library.** The certify-time fix made systematic: which per-declaration theorem families are instances of one second-order theorem (SOFT) or one functional-instantiation template; the cost model (linear in fields, constant per kind) stated and how it is kept; what R5a's third pass did by hand that this does once.
5. **The existing forms as instances.** For defcolumns, defmachine, defmachine-callback, defcorechild, deflayout, defthm-owed: what changes (signature, generated list, registry entry), what stays, what is deleted; the migration of the current books (a convergence, not a rewrite: one macro at a time, each step certifying, the full driver unchanged). For the planned forms (defprojection, defport, defmigration, defshape, the command grammar): their declarations in the same notion, so they are instances by construction.
6. **The guards against the old sins** built into the macro: refuse a declaration whose obligation list is empty or names nothing; refuse positional field access in generated code; refuse an enum compared as an integer; refuse `:extra-fields` without `:why`; refuse a callback that forwards fields positionally (R5e's flaw); refuse a layout interpreted at run time.
7. **The refactor plan for A**, sized in quests of a readable diff each, ordered so every step certifies and the driver stays green; which steps R5e already does; the certify-time table expected after each step; and what B and the sprint's C/D code must change.
