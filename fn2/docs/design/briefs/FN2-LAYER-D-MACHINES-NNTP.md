## Ruling from layer H (2026-10-29, HV 095433a9f)
COMPRESS is advertised and accepted only after authentication (NNT-054 in the spec corpus; fn1 answers 480 before auth). The earlier obligation to advertise COMPRESS while inactive is withdrawn; D's connection machine follows the spec line, and H's differential is the oracle.

## Ruling from layer H (2026-10-29, HZ3 335878b2b): the pinned access rule
fn1 bug W01: on a connection left open across an `account access` change, LIST ACTIVE applies the new rule but POST keeps the old one, so a post lands in a group the login can no longer read. D's served path owes the pinned rule: one access rule per connection, pinned at authentication and re-read only at a declared re-authentication, applied identically by every command.

## Spec pins from layer H
fn2/docs/h-harness.md on dev carries a section "Spec pins read by layer D": each pin is one reply and one connection outcome where the spec allowed two; D's grammar and machines follow them and H's model is the oracle. First pin (22de14c4d): a command line that is not UTF-8 is malformed whatever else is wrong, 501 and close; whitespace on a valid UTF-8 line is 501 and the connection stays open. Also observed in fn1 and modelled: AUTHINFO USER, SASL and XREDEEM share one pending slot, so starting any replaces the others.

## Contract
0. **The resource acquisition and release protocol** (EXECUTION-MODEL §7a item 2; `fn2/docs/d-machines-nntp.md` §"acquisition", **merged before D3 starts**): as tables, not prose: (a) one total order over every resource kind a transition can hold: connection row, RX/TX ranges, listener accept credit, upload row, chunk windows, identity reservation, transaction row, batch membership, cache pins, read/write/fence slots, TLS handshake slot, wait row, subscription edges, control-output reservation, outbox credit, result cells, service work; (b) per transition, its complete admission bundle (acquired whole or not at all; on refusal the transition holds a continuation and has acquired nothing); (c) what a machine may hold while waiting, per phase (held-resource restrictions); (d) release and rollback: what is released on refusal, on cancellation, on close, on a failed result, and in which order; (e) protected reserves for cancellation, close, fence and recovery, and the system reserve for control; (f) how notification debt is transferred out of a committed batch so that two slow recipients cannot occupy both batch slots; (g) why the order excludes cycles (every bundle acquires in the order). Tests: exhaustion and cancellation at every acquisition boundary of every bundle (a scenario per bundle, tiny profile, exhaustive) before any dependent machine is accepted.
1. **The machine DSL** (`fn2/books/machines.lisp`, growing A4's phase integers into a declaration): `defmachine KIND (:phases (...)) (:fields ((name kind) ...)) (:accounts (...)) (:budget (:bytes N :steps N :actions N)) (:arms ((phase event) → body) ...)` generates, through A1's `defcolumns`, the row table (the common fields of ROUND2 §B.1: `phase:u8, generation, principal-slot:u16, account-ref:u32, ready-prev/next:u32, wait-reason:u8, deadline`), the named phase enum, the per-run dispatcher with explicit fuel (singly recursive, finite tags, ATC-shaped per ROUND2 §A.3), the continuation record (what a run keeps when a budget is exhausted), and the obligation stubs of RELEASE-PLAN §4.3 as `defthm-owed` forms at declaration time **for a restricted, metered vocabulary of arm bodies** (field reads and writes, pool and queue operations, reservations from D0's tables, the §D actions): phase totality, the emitted cost function and `cost ≤ cap`, continuation preservation, frame, account conservation per declared entry; a body that calls outside the vocabulary declares that call's cost and frame contract or the declaration is refused. A4's echo, null and scribe machines are re-declared through it (the twin is deleted: the derived path is the only path). **The machine ownership matrix** (`d-machines-nntp.md` §"catalogue"): every kind of ROUND2 §B.2 with its owner, phase enum, retained fields, capacity (§B.1) and simultaneous budgets (§B.3): listener/connection, TLS admission, upload, transaction, query cursor, consumer wait, **cache/storage job** and the **timer/grant/wake services** (yours), commit batch, cleaner, checkpoint, recovery (B's; B migrates them into this DSL after D1 merges, scheduled by main).
2. **The command-grammar DSL** (`fn2/books/grammar.lisp`): `defgrammar NAME` over pool ranges (never lists): a command line as keyword plus typed arguments (number, range `n-m`, Message-ID, wildmat, keyword), the 512-octet initial-line cap, CRLF framing, pipelining, dot-stuffed multi-line blocks (article and TAKETHIS bodies) with the long-header-line limit, discard-to-terminator, and the two boundaries where the grammar hands the bytes elsewhere: STARTTLS (nothing framed during the handshake) and COMPRESS (E). Emits: the incremental parser as a bounded continuation over `[parser-offset, fill)` of the connection's RX range (at most 4 KiB per run), the reply renderer into the TX range, the generator and mutator for RELEASE-PLAN §2.4's fuzzer (syntax only: the oracle is the independently authored fixtures and the model; the fuzzer ships with mutation controls that must catch a wrong acceptance, a wrong reply and a dropped effect), and the obligation stubs: totality under the connection row's guard over arbitrary octets (no well-formedness premise), linear consumption, fragmentation invariance, bounded retained input, reply typing. Quarry: `books/protocol-table.lisp` and the wire family (QUARRY "wire grammar and article parser", 31 books, LIFT WHOLE): take the table and the framing rules, polished, over ranges.
3. **The listener/connection machine** (`fn2/books/conn.lisp`; ROUND2 §B.2 row 1): phases `accepting, greeting, command, article-input, reply, upgrading, closing, draining`; the capability token, RX/TX ranges, parser offset, command ordinal and selected view (the pinned logical version: STORAGE-DESIGN §4 decision 2, a version plus object leases, never an old root), authentication and configuration references, active request references, outstanding-use count; single-shot receive/send (A's ABI); the timers: first-command, idle, send deadline, through `ArmWake`; anonymous principal until authenticated; capacity and per-address refusals as the 400 lines of `specs/nntp.md` NNT-031/043.
