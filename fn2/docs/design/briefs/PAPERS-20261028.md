# Papers for fn2: proof automation, program logics, crash models, code generation (2026-10-28)

Ember, verbatim: "We also need to be sending a subagent that uses ~/.scry-key and/or kagi and ~/paperbin and downloads papers about proof strategies, program logics, proof automation etc etc that we can be using to do fn2 with as little manual work as is possible. like, we're not convinced that our crash model is actually an appropriate model of the OS or hardware, and we should make sure that our crash model is 'more tough.'" Context: fn2 is a bottom-up, semantics-first rebuild of an ACL2-verified NNTP/store node, meant to become "a high performance database node" (a generalized redis/postgres for ember's data models) and someday run on the robigalia OS (seL4-based). The proofs come after the implementation works; the aim is minimal manual proof work when they do.

## What to find (aim for the best 40-80 papers, not everything; prefer the ones with artifacts)
1. **Crash models tougher than ours.** fn's model (`/Users/ember/dev/fn/books/byte-store.lisp` header; read it first) has inodes, directories, pending ops, per-inode fsync, torn writes at write units landing as written/zeros/garbage, explicit EIO/ENOSPC, and fsyncgate semantics. Find what it misses: Pillai et al. "All File Systems Are Not Created Equal" (OSDI 14), Bornholt et al. "Specifying and Checking File System Crash-Consistency Models" (ASPLOS 16, Ferrite), Alagappan et al. "Protocol-Aware Recovery for Consensus-Based Storage" (FAST 18), Rebello et al. "Can Applications Recover from fsync Failures?" (ATC 20), Bairavasundaram et al. on silent disk corruption, "Crash Consistency: FSCK and Journaling" background, Zheng et al. "Torturing Databases for Fun and Profit" (OSDI 14), the TigerBeetle storage-fault model docs and VOPR, Sigurbjarnarson et al. "Push-Button Verification of File Systems via Crash Refinement" (Yggdrasil, OSDI 16), Chen et al. FSCQ (SOSP 15) and DFSCQ, Chajed et al. Perennial (SOSP 19) and GoJournal (OSDI 21) and DaisyNFS, Ileri et al. "Proving confidentiality in a file system" (SFSCQ), "SibylFS" (SOSP 15), Amani et al. BilbyFs (CoGENT, ASPLOS 16), memory-ordering/persistent-memory models if cheap (PMDK, "Persistency semantics" Raad et al.). Note for each: what failure the model admits that ours doesn't.
2. **Proof automation and program logics that reduce manual proof.** Iris and its crash extensions (Perennial again), Verus (Lattuada et al. OOPSLA 23) and Dafny/Boogie as automation benchmarks, F*/Low* (HACL*, EverCrypt) for verified high-performance code, Prusti/Creusot for Rust, CakeML, seL4's proof methodology and cost papers (Klein et al.; "Comprehensive formal verification of an OS microkernel"), Ironclad/IronFleet (SOSP 15), Armada, "Verified Software Toolchain", Vale, Cogent (code generation + proof), rely-guarantee and ownership logics; ACL2-specific: ACL2 Workshop papers on defabsstobj, stobj-let/nested stobjs, FGL and GL bit-blasting, the x86isa model, Milawa, "ACL2 at Centaur", Kestrel's APT (program transformation) and ATC (ACL2-to-C) and ATJ, "Rewriting with equivalences", the Codewalker/"Mechanized formal reasoning about programs and computing machines" (Moore), def-loop-style generic instantiation papers, and anything on ACL2 proof automation (e.g. `make-event` tooling, "tau system", "arithmetic-5"). Also LLM+ITP: recent papers on LLM proof search/repair (Lean, Isabelle, Coq, ACL2 if any) 2024-2026, and on agents driving provers.
3. **High-performance node design.** TigerBeetle's design docs/talks (TigerStyle, VOPR, static allocation, batching), "Redis internals", LMDB (Chu), "The Design and Implementation of Modern Column-Oriented Database Systems" (Abadi et al.), log-structured storage (RocksDB/LevelDB papers, "The Log-Structured Merge-Tree"), io_uring and thread-per-core designs (Seastar, "Scalable I/O"), group commit (Hagmann; "Scalability of write-ahead logging"), ARIES, "Database Cracking" if relevant, CRDT/replication only if fast to find.
4. **Metaprogramming for succinct systems**: papers on DSLs that generate both the implementation and its proof obligations (Cogent, Ivy, P language, Dafny-based generators, "Verified compilation of DSLs", Kestrel's synthesis), and on deriving executables from specs (Isabelle code generation, Coq extraction, Lean's compiler, ACL2's ATC/ATJ).
