# fn2 sprint ahead into C and D (2026-10-28): a scout in Sol, judged by Astra

Ember, verbatim: "i wonder if we could use some sol agents to 'sprint ahead' into C/D/etc? in a write-only kinda way, like they read a lot of files to understand what to do and then do a huge burst of writing (all into one shared worktree) and then they try a few examples thru the repl and hammer it into a shape that they pass up to an astra that reviews and considers if it's good to integrate or if we should wait to 'do it the way we were gonna do it'".

## What a sprint is
A scout, not the layer. It runs on the REAL foundation (origin/fn2/main: layer A's defcolumns/defmachine, the pool, the vocabulary, the simulator; layer B's formats, allocator and Merkle log from fn2/b-durability) and writes a first cut of layer C (the ordered-run metadata engine) and the first verbs of layer D (connection and parser machines through defmachine; GROUP/ARTICLE/POST over B's journal and C's runs) in one shared worktree, branch `fn2/sprint-cd`, under `fn2/sprint/c/` and `fn2/sprint/d/` (never under fn2/books, fn2/sim, fn2/host). Its products, in order of value: (1) `fn2/sprint/FOUNDATION-GAPS.md`: every place the foundation lacked something the sprint needed (a DSL kind, a pool primitive, a vocabulary event, a format field, a simulator fault), each with the file:line where the sprint worked around it; (2) the code, hammered through the ACL2 REPL (`fn2/tools/certify.sh` and the simulator) until a few real examples run: a run sealed and looked up by Message-ID, an XOVER-shaped range cursor, a GROUP/ARTICLE/POST exchange under the simulator; (3) Astra's verdict per piece: INTEGRATE (the layer monitor takes it as the quest's starting point, read whole), HARVEST (specific findings or files go into the layer brief or the foundation's next quest), or DISCARD (compost; the layer is built as briefed). The layer monitors (C when it starts, D after) read the sprint's gaps file and verdict before their first quest; nothing from a sprint merges into fn2/main except through a layer's own reviewed quest.

## Method (the Opus monitor's)
Worktree `git -C /Users/ember/dev/fn worktree add build/lanes/fn2/sprint-cd -b fn2/sprint-cd origin/fn2/main`; merge `origin/fn2/b-durability` into it (B's formats are needed; conflicts are read, never stashed). One Codex session, model Sol (`-m gpt-6.1-sol`, multi-agent on by default: tell the top-level Sol to spawn one sub-agent for C and one for D, disjoint directories, and to use the slack to try the REPL examples), workspace-write sandbox, detached with a PID file and a waiter, resumed by session ID on capacity or auth errors. Its prompt names, as ground truth to read first: FN2-ORIENTATION.md, EXECUTION-MODEL.md and ROUND2-ASTRA's tables, STORAGE-DESIGN.md and STORAGE-DESIGN-ASTRA §3, FILTERS-2026.md, INBOX-DELIVERY.md §4-5, the C and D layer briefs, fn2/docs/*.md on fn2/main and fn2/b-durability, fn2/books/machines.lisp and machines-a.lisp (the declaration shape), fn2/books/pool.lisp's exports, fn2/books/vocab.lisp, and the guide's ai/00 and ai/01. The burst: write, then certify and run, then fix, in as few rounds as it can; the gaps file is written as it goes, not at the end. Then a second Codex session, model Astra, read-only sandbox: the verdict document `fn2/sprint/ASTRA-VERDICT.md` (per piece: integrate/harvest/discard, the reason, what the layer brief should change), against the decision documents. The monitor reads both outputs whole, commits by named files on the sprint branch, pushes the sprint branch, writes `/Users/ember/dev/fn/build/coordinator/fn2/lanes/sprint-continuation.md`, and reports READY to main with the gaps count, the examples that ran, and the verdicts.

## Rules
Never kill a process by pattern (PID files only); never git stash or git add -A; Codex never pushes; nothing touches fn2/books, fn2/sim, fn2/host or any layer branch; the laptop ACL2 only, one certify at a time, PID file for anything over a minute; disk under 60 GiB free means stop; secrets check before the push.
