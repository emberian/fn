# fn2 as the persistence substrate of an operating system (widest-role council, vantage: robigalia on seL4; 2026-10-28)

One voice in the council (`briefs/WIDEST-ROLE-20261028.md`), grounded in the documents that brief names.

## 1. The world from this vantage

On robigalia, nothing is saved. There is no save button, no `fsync` in application code, no serialization library, no `/var/lib`. A process holds capabilities; some of those capabilities name **ports**, and a port is a stream with a declared fold, a command grammar and a protocol table. Every durable object a process can hold (a file, a directory, a mailbox, a configuration, a table, a window layout, a half-typed message) is the fold of a stream at a position, and the process's own volatile state is an **external checkpoint**: an opaque content-named page set plus the range of input it has consumed since. fn2 is the thing that makes both kinds durable, ordered, accountable and transportable. It is KeyKOS's checkpointer and space banks, Plan 9's file servers, Venti, the Nix store and a DSU runtime in one executor whose only write is an append.

The layering is the four planes, applied to a whole machine. **seL4 and its device drivers are the fast plane**: IPC, scheduling, interrupt handling, page-fault delivery and DMA run at microsecond grain and never wait on a commit (PLANES L1-L3). **fn2 is the slow and projection planes** for the machine: the journal per commit domain, folds, obligations, Names, signed checkpoint claims. **The live plane** carries the machine's transient chatter (presence of a session, a progress bar, a cursor position in a shared editor, a driver's telemetry) in the same streams as durable items, interwoven per item (the addendum). **The host primitives** are, on robigalia, literally the block-device queues (virtio-blk or NVMe submission/completion rings mapped into fn2's protection domain, with FUA and flush as the barrier vocabulary of EXEC rule 8), the network device's rings, a clock, an entropy source, and one primitive new to this vantage: **frame grant**, handing a range of fn2's byte pool to another protection domain as a read-only or copy-on-write mapping.

A Tuesday on a robigalia workstation.

At 09:00 ember opens the laptop. There was no shutdown last night; the battery died at 02:14. Boot runs seL4, the root task, and fn2's recovery (intact / torn tail / damaged / unknown, EXEC rule 8). fn2 finds the last **machine cut** (a durable vector of commit positions, one per domain, sealed together with the external checkpoints that cover it), rehydrates the capability spaces of every process from the durable capability fold at that cut, maps each process's checkpoint pages back into fresh address spaces by frame grant (lazily: a page fault on an unmapped page becomes a range lease on the Name), and replays each process's recorded input suffix where the process declared one. The editor reappears with the cursor where it was at 02:13:58. The chat client reappears with the 02:14:03 message that arrived after the editor's last checkpoint, because the message was durable in its mailbox port the instant the node acknowledged it to the sender (L3: the sender was told "delivered" only after the commit).

At 10:30 a build runs. The compiler reads source files: each `open` is a pinned version of a file port (`exactly-at(p)`, UNIVERSAL §0 item 1), mapped by frame grant, never copied. Its outputs are Names: content-addressed, deduplicated with every previous build on this machine and every peer, retained by obligations (the build cache pins them; a release generation pins them; when neither does, reclamation takes them, STORAGE §1).

At 14:00 ember wants to try a kernel-driver patch. She **forks the machine**: a new set of commit domains whose prefixes are the old domains' prefixes at the current cut, by reference; every process resumes in the fork; every capability is re-minted with a new incarnation; every outstanding external obligation (an unsent mail, a lease on a peer's work queue, a payment) is assigned by the fork decision to exactly one side. The fork runs the patched driver. At 15:00 she diffs the two machines' folds, keeps the fork, and the original becomes a retained branch until its pins lapse.

At 18:00 she walks to the other machine. `migrate session` moves the commit domains of her desktop session: the lease on each domain is transferred with a fencing incarnation bump (UNIVERSAL §6.3), and the only bytes that cross the wire are the Names the desktop does not already hold (have-ranges as a merge-capable fold, PLANES §5.1). On the wire, between the two machines: log segments, Merkle checkpoint claims, content-named blocks, lease transfers, all as BP bundles over TCP on the LAN and over whatever DTN convergence layer exists when the laptop is on a train. Durable: events, pinned Names, capabilities, obligations, checkpoint claims. Live: presence, cursors, progress, telemetry. Fast: everything seL4 does between two commits.

## 2. Ten things it would build or subsume

1. **The filesystem** (replaces ext4/XFS/APFS and the POSIX file API; composes with ZFS-style send/receive users already love). A file is a fold of an edit stream (whole-object replace, range write, append) and a directory is a Span from names to ports, so snapshots, clones and point-in-time reads are positions, not features; ZFS users switch because `zfs send` is just transport of a cut, and every file now has an exact history with `exactly-at` reads.
2. **9P namespaces** (composes with Plan 9's 9P2000 and replaces FUSE). Every port renders as a 9P tree from its protocol table, a per-process namespace is a versioned Span composite (`bind` and `mount` are span composition and union, Pike et al., "The Use of Name Spaces in Plan 9"), `Twalk` is span traversal, `Tread` at a qid version is an `exactly-at` read, `Tclunk` releases a lease; Plan 9 users switch because every 9P server becomes durable, versioned and capability-scoped without reinventing storage (Fossil/Venti did it for one filesystem).
3. **Process checkpoint/restore** (replaces CRIU, DMTCP, and EROS's whole-system checkpoint). A process image is an external checkpoint record (PLANES §4.5: executor, incarnation, tick, digest, snapshot Name, input range, predecessor), taken per process on its own cadence instead of KeyKOS's global five-minute stop (Landau, "The Checkpoint Mechanism in KeyKOS", 1992); CRIU users switch because restore rehydrates durable capabilities fn2 already holds instead of reconstructing kernel objects by best effort.
4. **VM snapshots and live migration** (replaces QEMU/KVM migration, Firecracker snapshots, Remus). Guest memory is a Name with an outboard tree, dirty pages are delta Names, pre-copy is have-range transport and post-copy is range leases served on fault; Remus's output buffering (Cully et al., NSDI 2008) is exactly L3 output gating, so operators get Remus-grade failover with per-message gating instead of per-epoch buffering.
5. **Durable IPC and service activation** (replaces POSIX message queues, D-Bus, systemd socket activation, launchd). A service's inbox is a mailbox port; a sleeping service holds no thread, only a subscription edge, and is started when the edge's frontier moves (the wake is a hint re-checked against the frontier, UNIVERSAL §9.2); D-Bus users switch because messages survive the receiver's crash with a cursor and an ack, and because "who owes a reply" is an Obligation, not a timeout.
6. **The system and package store** (replaces the Nix store, OSTree, Windows component store). Packages are Names; a system generation is a pinned version of the root namespace fold; rollback is moving a Frontier back; garbage collection is evidence-gated release of obligations (Dolstra, "The Purely Functional Software Deployment Model", 2006); Nix users switch because the store, the generations and the GC roots stop being three ad-hoc mechanisms and become one retention rule, and because the store replicates by the same transport as everything else.
7. **Durable capabilities and revocation** (composes with seL4's capability derivation tree, replaces the persistence seL4 does not have). seL4 capabilities vanish at reboot; fn2 keeps a durable capability fold (object, rights, holder, incarnation, derivation parent) and rehydrates CSpaces at boot, with revocation a committed event that cascades down derivation edges and fencing that refuses a stale incarnation by name; KeyKOS and EROS users (and anyone who read Shapiro, Smith and Farber, SOSP 1999) get persistent capabilities back on a verified microkernel.
8. **The system journal and audit** (replaces journald, auditd, syslog, Windows Event Log). Every OS event is a typed item on a stream, durable or transient per item, with audit queries as projections and tamper evidence as signed Merkle checkpoint claims; auditors switch because the log can prove its own completeness through a frontier and its own integrity through a witness, which no text journal can.
9. **Configuration and reconfiguration** (replaces /etc, systemd units, the Windows registry, etcd for single-machine use). Configuration is a fold, a reconfiguration is a committed event with a precondition (Decide) and an observable postcondition, so ember's sentence 7 ("formal statements about server reconfiguration events") holds for the whole machine; administrators switch because every configuration has a history, a diff, a rollback and an authenticated author.
10. **The application database** (replaces SQLite, Core Data, IndexedDB, and on the AS/400 the database integrated into the single-level store). Tables are folds and Spans in the one ordered-run engine, queries are projections with stated read strength, transactions are Decide at a domain's head; the AS/400 lesson (Soltis, "Inside the AS/400") is that a database inside the single-level store removes the memory/storage mismatch, and developers switch because their data model is the persistent model, with no ORM and no `serde` (ember's sentence 10).

## 3. What the kernel must contain

The pruned kernel (Log, Decide, Fold, Name; Binding, Span, Frontier, Obligation) is the right algebra for one node's data. For a machine whose every object lives in it, it is too small in six places, and two primitives must be added.

**Log must become cheap and countable in the millions.** A robigalia machine has a commit domain per process, per file that is independently writable, per mailbox: 10^5 to 10^7 domains. A domain must be a row in the ordered-run engine (its head position, its head state's root, its owner lease), never a file, never a resident structure (EXEC rule 9 already says persistent namespaces are paged). Many domains share one physical commit stream and barrier; "one atomic mutation, one domain" stays.

**Frontier must gain a durable, named machine cut.** Whole-machine restore, fork and migration all need a consistent vector of positions across domains, retained as a version. On one node with one executor a cut is free to compute (the executor's state between two transitions is a consistent cut; Chandy-Lamport is needed only across nodes), so the primitive is **Cut**: a record `(cut-id, node incarnation, vector of (domain, position), external checkpoints covering it, predecessor cut)` committed through the ordinary commit machine and pinned like any version. A Cut is the unit of restore, fork, migrate and backup.

**Name must gain structural sharing as a law.** Memory images and VM disks change by pages; a checkpoint must cost its dirty pages, not its size. Name becomes a catamorphism over a declared tree with **delta Names**: `Name(parent, patch)` whose outboard tree shares every unchanged subtree with the parent, with the law that verification of a range in the child touches only the patched subtrees plus the path. This is Venti (Quinlan and Dorward, FAST 2002) and BLAKE3's tree mode taken as an interface law, and it is what makes per-process checkpoints at second-scale cadence plausible.

**Obligation must gain derivation, attenuation and confinement**, becoming **Grant**: a capability is an obligation-shaped record with a holder, an incarnation, a rights value in a declared lattice, and a derivation edge to its parent. Laws: a child's rights are at most its parent's (attenuation); revoking a parent discharges every descendant in one Decide over the derivation Span (seL4's CDT, made durable); a holder's authority is defined at commit and fenced by incarnation (UNIVERSAL §6.3); a **factory** (KeyKOS's confinement mechanism, Lampson's confinement problem) is a Grant whose product's outward capabilities are enumerable from the derivation Span, so confinement is checkable as a Π-read over a versioned fibre (UNIVERSAL §3.2). Space banks are EXEC rule 5's principal accounts with Grants for sub-banks; destroying a bank is revocation plus evidence-gated reclamation.

**Fold must gain revisions (DSU).** The versioned executable world needs two axes: program revision and execution history. A fold declaration and every event schema carry a **revision**; a **migrate** event commits a declared migration between revisions (a functor between fold schemas in Spivak's sense, Σ/Δ/Π, UNIVERSAL §2.5) at a position; reads at `p` interpret events under the revision current at their own position; an observation records the revision it was made under. Kitsune (Hayden et al., OOPSLA 2012) and Ginseng (Neamtiu et al., PLDI 2006) needed state transformers written by hand and run at a quiescent point; fn2's quiescent point is a commit boundary and its transformer is a fold migration whose adequacy has the same local certificate as a summary rule (UNIVERSAL §2.2). Positions become `(domain, revision-epoch, seq)` under L5.

**Log must admit fork by reference.** A domain's genesis may be `fork-of(domain, position, cut)`: its prefix is the parent's prefix, shared, never copied, and its suffix diverges. Merging back is never automatic: it is Decide (rebase onto the parent's head, or a named refusal) or a merge-capable fold the application declared (UNIVERSAL §2.3).

The two added primitives:

- **Port**, a DSL form (`defport`): stream kinds and their admitted durability classes, the fold (with revision), the command grammar and the protocol table (UNIVERSAL §0 item 10), the Grant rights lattice the port honours, and its 9P rendering. Files, directories, mailboxes, configurations and tables are five `defport`s, not five subsystems. The three DSLs (records/columns, machines, command grammars) are exactly the material a `defport` is written in.
- **Image**, the external checkpoint made first-class for processes: `(process, incarnation, cut, page-set Name, register file, capability-space reference into the Grant fold, input range, nondeterminism mode)`. The nondeterminism mode is the process's choice: `image-only` (restore loses everything since the image), `recorded` (every nondeterministic input it receives through a port, every clock read and entropy draw, is a durable item, so restore replays to the exact pre-crash state, rr's record-replay discipline, O'Callahan et al., USENIX ATC 2017), or `output-gated` (the process's externally visible outputs wait for the image that covers them, Remus/EROS-style).

Host primitives grow by three: **frame grant** (map a pool range into another protection domain, read-only or copy-on-write, with the lease ending when the mapping is revoked), **dirty-page harvest** (the fast plane reports which granted frames a process wrote since the last image, via seL4 fault handling or a hypervisor's dirty log), and **page-fault service** (a fault on an unmapped range becomes a range-lease request to fn2). The byte pool's ownership algebra (UNIVERSAL §8) extends with one state, `mapped(pd, rights)`, whose release waits for the unmap completion exactly as zero-copy send does today (EXEC rule 6).

## 4. The one capability that would make it epic

**A forkable machine with linear external obligations.** Every system that forks machine state (VM snapshots, `fork(2)`, CRIU, Firecracker clones, ZFS clones) forks bytes, and so forks every promise those bytes made to the outside world: the cloned VM re-sends the email, re-acquires the lock, re-spends the payment, answers as the same TLS session. fn2 can fork a whole machine at a Cut and guarantee that every outstanding external obligation is held by exactly one side afterwards.

What a builder starts with:

1. **The Cut record** (§3), with the executor's quiescent point between transitions as the consistency argument on one node.
2. **The fork decision**, one Decide in a node-level domain: input a Cut and a **disposition** for every outstanding Obligation and Grant at that Cut, each one of `parent | child | refuse | split(evidence formula)`; the decision is refused unless the disposition is total over the obligations outstanding at the Cut (a Π-read over the versioned obligation fibre, UNIVERSAL §3.2), so linearity is checked, not hoped. Defaults are declared per port: network ports and peer leases default to `parent`; local files default to shared-by-reference (they are not obligations, they are positions); work-queue claims default to `parent`; a mailbox port defaults to `parent` with the child getting a read-only fork of the history.
3. **Re-minting**: every Grant assigned to the child is reissued with a new incarnation and a derivation edge to its pre-fork self; fencing (UNIVERSAL §6.3) then refuses by name any commit by the other side's incarnation. A peer that receives a commit from the child for an obligation it gave the parent answers `fenced`.
4. **Domains by reference**: every domain in the Cut gets a child domain with genesis `fork-of(domain, position)`; images get child Images whose page Names are the parent's (delta Names make the first child checkpoint cost only its dirty pages).
5. **Revision as a fork parameter**: the fork may name a different program revision for any process or fold, with a committed migration (§3). This is the counterfactual: *run this machine's last week of recorded inputs under the patched driver, as a fork, and diff the folds.* The diff is exact (folds are functions of positions) and semantic (folds are typed).
6. **The simulator scenario that refutes it**: fork at a Cut with a lease outstanding, crash both sides at every death point, and check (the CONSUMER and HISTORY checkers, EXEC rule 10) that no external party ever observed two holders.

This is the versioned executable world made physical: execute, edit (a revision), migrate (a fold migration or a machine move), materialize (a Cut and its folds), fork (with linear obligations), each a checked transition, each a record in the log. KeyKOS had persistence, Remus output gating, Nix content-addressed generations, rr recorded replay; none could fork the promises.

## 5. What it must never do

fn2 must never sit on the fast plane's critical path: no seL4 IPC, scheduling decision, interrupt or DMA completion may wait on a commit, and a process that wants a durable fact pays for it explicitly through a port, never implicitly through every store instruction. It must never silently restore a shorter or older machine than the one it acknowledged: a rollback it cannot rule out without an independent witness is reported as `unknown` (A-INDEPENDENT-FRONTIER), and a restored or forked process never acts on an external obligation it does not hold under the current incarnation. It must never become a second kernel: authority it records is enforced live by seL4 capabilities it rehydrates, the policy of what a process may do stays in Grants and ports the user can read, and the substrate itself holds no application semantics beyond the folds, grammars and revisions applications declare.
