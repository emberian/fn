# The machine form, redesigned (2026-10-30; main's statement for ember to amend, then Astra reads, then one DSL seat implements)

Ember: "we need to fix the machineform shit URGENTLY ... it doesn't matter or not if the software is working if the way we are building it is so trash and contrary to our earlier standards." The standard is DSL-METATHEORY's own law (line 63): *everything a declaration's kind generates is generated by the declaration; nothing of that list may be hand-written beside it.* The machine form today violates it in six ways; this document says what the form becomes so that it does not.

## 1. What is wrong, with the evidence
1. **The declaration and the body say the same thing twice, and the body is hand Lisp.** An arm is a contract line (`:cost :writes :tables :next :uses`) in `defmachine` AND a separate `defmachine-callback` whose body re-states it: `fn2-machine-with-work 512 ...` restates the cost; `fn2-conn-put-core id (phase ...) (tx-off 0) ...` restates `:writes` and `:next`; every call restates `:uses`; every `(if (not (eq code :ok)) (fn2-machine-refuse-phase ...))` restates the refusal policy. conn.lisp's greeting arm is a 4-line contract and a 20-line body for "unbook if refused, run the greeting, set seven fields, go to :reply". The arm language (arms.lisp) is a CHECKER that the body matches the contract; the metatheory asked for a GENERATOR. Six kinds carry 93 hand arms, about fifteen each, 800-1,600 lines per machine book.
2. **One assembly re-proves every kind.** `assembly-index` includes every kind's book and runs the index, directory, core-init, access and dispatch events over all of them; each kind's arms materialize in section books that include the whole chain. No kind certifies alone; adding the sealer's six children put eight assembly books over the minute (CPU, not load), and the day was spent splitting books by hand. The core's well-formedness was made per-child (867e87a23) and it worked: the same must hold for init, access, dispatch and the reference copy, by construction.
3. **The calling convention leaks the target.** Row fields travel as positional values through `mv`; ACL2's 32-value limit bit twice (whole-row snapshots; 33 core children) and was patched twice (read sets; nested groups). A kind must never see a 32.
4. **Refusals and stops are a convention, not a construction.** Every operation result is routed by hand; B's commit kind has 27 `assert$?` sites where the executable aborts and the logic absorbs; twelve arms are `:language :unchecked` because the checker could not read them. If the generator emits the routing, an absorb cannot be written.
5. **Octets move one at a time.** Arm bodies call the pool's per-octet exports (upload-feed streams a block octet by octet; the identity bind copies octets) because the handle vocabulary's range operations exist (pool-ranges.lisp: scan, compare, fold, drop-prefix) but copy-by-range was demoted and none is the arm language's default. The envelope's POST floor is two copies.
6. **Evidence is hand-built per kind.** Each kind's contract row, teeth, mutation site and four-way control harness were written by hand this week (q1-contracts-{a,b,c,d}); the catalogue labels and Q1 cases are generated but the controls are not. A form that knows every arm's reads and writes can emit the positive and negative fixture and the mutation hook itself.

7. **Representation drives semantics, which is backwards.** Astra's read (REGROUND-ASTRA-20261030.md) found two: read-retry on misdirected I/O was omitted from recovery because the row's 24 fields were full (b-durability.md:1112), and the transaction hardwires six cross-post groups to fit successor slots (txn.lisp:28) against "no arbitrary stored-data ceilings". A form whose row width is the target's limit will keep doing this. In the new form a kind's capacities are profile values or declared bounds, never literals, and the row's representation is the generator's.

## 2. The form (statement)
One `defmachine` is the whole of a kind. It contains only what cannot be derived:
- `:phases`, `:fields` (typed, with widths), `:budget`, `:holds` per phase over D0's kinds, `:admission` or `:taken`, `:observes` (event → handler), `:capacity`, `:initial`.
- `:arms`, each an arm in the arm LANGUAGE, not a callback: a `:when` guard over the row and the event, a `:do` sequence of calls to declared operations (defcost'd) binding their results, a `:set` list of field assignments, a `:next` phase (or a `:case` over a result code to phases), an `:on-refusal` policy (`:refuse`, `:stop REASON`, or `:retry`), and nothing else. The language's primitives for octets are the range operations by handle (copy-range, scan, compare, fold, drop-prefix, hash-range); per-octet read and write exist only in the logical reference.

The arm language must be able to say what the seats' arm tables found it cannot (C's sealer table, c-continuation.md): dispatch on an operation's answer code (`:case`); park on a D0 wait kind with the waker named (a constrained predicate attached by the kind that knows, as :sealable is); stop the core from inside an arm with a named reason (`:on-refusal :stop REASON`, and `:stop` as a `:case` target); a machine whose row carries an inner state machine (the seal row's idle/build/filter/install) declares it as a machine or a sub-machine, never hides it under one defcost; genesis writes are an arm of a declared `:genesis` phase, not code outside any arm; the owner triple is a declared field the generator fills from the index; a kind that issues nothing declares cap 0 (A's frame lemmas make that provable).

From that one form the generator emits, into the kind's own book, everything the kind is:
- the columns table, PUT/PUT-CORE, the snapshot and the calling convention (the representation of a row's read set is the generator's business; nesting past any target limit is by construction);
- the callbacks, with the cost DERIVED from the called operations' defcosts and the budget, the writes DERIVED from `:set`, the next phases DERIVED from `:next`/`:case`, the uses DERIVED from `:do`, and the refusal routing DERIVED from `:on-refusal` for every non-:ok result (so no arm can absorb a refusal; `assert$?` has no place to exist);
- the run-time certificate (charge, next phase, holds) and the per-arm owed rows (bound, frame, totality) with their teeth: a positive fixture from a satisfiable pre-state and a negative that an undeclared write is refused;
- the catalogue labels and Q1 cases, and the kind's shared-handler mutation hook (one named site per arm the harness may mutate), so the four-way control is generated per kind and only its oracle is named by hand;
- the kind's per-child facts: wfp, init, access readers, dispatch entry, reference copy, each stated for THIS child only, so the assembly is a registry (name → position) and an index of per-child facts, never a proof over all kinds.

A kind's book certifies alone against the forms and its declared operations, in seconds; the assembly certifies the registry once and does not grow with kinds. The arm tables the seats are writing tonight (reads, writes, effects, costs, next, refusals per arm) are exactly the input: an arm table IS the arm in the new form.

## 2a. Four requirements from the measured anatomy (A5r seat, a-continuation.md "The measured anatomy of an assembly book's cost"; dev cee416335)
Every generated family (row readers, cross-kind field dispatchers, admit/take/reclaim, fn2-core-preserves TYPE/WFP, the with-work kind case split, the init groups, the reference view) re-proves across kinds because it is proven over the whole core recognizer. So, in the new form: (1) every per-kind artifact is proven against the kind's own table child and its declared :tables, never against fn2-corep whole; (2) per-child frame theorems per operation replace the per-core ones; (3) every dispatcher gets a per-kind rewrite so no guard case-splits over kinds, and issues export that the directory's kind is unchanged (which is also C's cap-0 ruling); (4) each child's init guard comes from its own profile predicate. The same section lists every generated mv site and every per-octet export site by file:line: the migration's checklist.

## 3. What this is in the metatheory's terms
DM4 (the column and core kits) and the machine kit, finished: the K-forms as kits (`?rd ?wr ?len ?rows ?wfp ?typep ?fitp` and the row-step/countdown kit) instantiated per kind in the kind's book, so the generic facts are proved once and each kind inherits them by instantiation, never by re-proof. R7 built the checker over hand bodies; this builds the generator and deletes the checker's reason to exist (the body cannot disagree with the contract because the body IS the contract).

## 6. The generator (form seat, 2026-10-30 night; statement before build)

### 6.1 Why a kind cannot certify alone today (read from the code, dev cee416335)
Every arm, every helper an arm calls (`fn2-machine-park`, `-issue-result`, `-with-work`, `-finish`, `-refuse-phase`, the field dispatchers) and every core operation (`fn2-issue-*`, `fn2-core-reserve/-release/-reset`) is a function over `fn2-core`, and `fn2-core` is a `defstobj` made in `assembly-core` from every registered child (22 today, B/C/D's library children among them). So no arm can exist before every kind is registered: that, not the book splits, is defect 2. Two facts keep it there: (a) the row-control fields (`generation principal-slot account-ref ready-prev ready-next wait-reason deadline`, plus `phase`, `pending`, `stopped` that generic code reads through dispatchers) are columns of EVERY kind's table, so a park writes its FIFO neighbour's `ready-next` in another kind's table (the 399-case dispatchers exist for this); (b) the operations an arm calls are written over the whole core though each touches one to three children (`fn2-core-issue`'s body is already a `stobj-let` of pool and ops). Neither is semantic. Grep at cee416335: no book reads a row-control column directly (every use is a `ROW-` reader, a `PUT-CORE` or a dispatcher, all generated), so moving them is the generator's business.

### 6.2 The declaration
```lisp
(defmachine K
 :phases (P ...)                       ; was :states (both accepted until the last kind ports)
 :fields ((F TYPE) ...)                ; declared fields only; the row-control fields are the directory's
 :budget (:bytes B :steps S :descriptors D)   ; D = 0 is cap 0: a path that issues is then refused
 :holds ((P KIND ...) ...)  :capacity FORM  :initial ((F VALUE) ...)
 [:admission (...) | :taken (...)]     ; unchanged
 [:genesis (STEP ...)]                 ; run once per row by the engine's init, as an arm (C gap 5)
 [:sub ((NAME :field F :phases (Q ...) :arms ((Q STEP ...) ...)) ...)]   ; an inner state machine (C gap 4)
 [:subarms ((NAME STEP ...) ...)]      ; shared step sequences, reached by (:goto NAME)
 :arms ((P [:on-refusal (STEP ...)] STEP ...) ...)          ; exactly one per phase
 :observes ((EVENT [:from (P ...)] STEP ...) ...))
```
The step language (everything an arm may say; nothing else is accepted):
| step | meaning | emitted as |
|---|---|---|
| `(:let V E)` | bind a value | `let` |
| `(:do (V ...) (OP ARG ...) [:accept (CODE ...)] [:case ((CODE ...) STEP ...) ... ])` | call a declared operation (a `defcost` row; rule 2) and bind its non-stobj results | `mv-let`; stobj formals and results appended from the world (`stobjs-in`/`stobjs-out`), owner formals `okind oslot ogen principal` filled from the row |
| `(:set (F E) ...)` | write own fields | `K-PUT-CORE` (one checked write) |
| `(:next N)` | the row's next phase: `P`, `(:if E N N)` or `(:case V ((CODE ...) N) ... (:otherwise N))` | `(phase ...)` in the path's last write |
| `(:cond (E STEP ...) ... (t STEP ...))`, `(:if E (STEP ...) (STEP ...))`, `(:case V ((CODE ...) STEP ...) ... (:otherwise STEP ...))` | branch | `cond`/`if`/`case` |
| `(:issue (OP ARG ...) :bytes E [:ok (STEP ...)] [:refused (STEP ...)])` | issue one descriptor | `:ok` steps, then pending 1 / wait :completion / charge (E, mailbox, 1); `:exhausted`: `:refused` steps, then park on :operation; any other answer: `:refused` steps, then the arm's `:on-refusal` |
| `(:park WAIT [ARG])` | park on a D0 wait kind; the waker is the wait kind's (operation FIFO, admission FIFO of ARG, pool class ARG; an attached kind such as :sealable names its ready/grant pair where it is declared) | the kind's park op, then the parked charge |
| `(:charge [:bytes E] [:steps E] [:descriptors E] [:runnable E])` | end the run, reporting work | `K-FINISH` (no kind dispatch) |
| `(:stop REASON)` | stop the core with a named reason (C gap 3) | `fn2-core-stop`, the refusal charge |
| `(:halt)` | stop the row (stopped 1, wait none): the retained R6 posture | as today's issue-result |
| `(:goto NAME)` / `(:idle)` / `(:yield)` | a sub-arm (fresh row reads); the idle/yield runs | a call |
| observation terminals `(:wake)` `(:nowake)` | the handler's wake | `(mv id core)` / `(mv none core)` |
Expressions: arm primitives (arms.lisp's list), `id budget`, `ROW-F` (the row's value at arm entry; a read of `ROW-F` after a write of F on the same path is refused, so no stale row exists), bound variables, phase names as `:P` inside `:next` only, the observation payload `event outcome reason count aux0 aux1`, and calls of declared pure operations (stobj input, none output; e.g. `fn2-machine-pool-capacity`).

### 6.3 Derived, and the checks that make an absorb unwritable
Per arm, by walking its paths: **cost** = max over terminals of the charge forms' bounds (nat, constant, `min`/`max`/`+`/`-`/`if`/`nfix`, a `:let` var by its expression; an unbounded charge is refused, not guessed); **writes** = `:set` fields ∪ phase if any `:next` ∪ the row-control fields the terminals write ∪ each op's `:own-writes`; **tables** = ∪ ops' `:tables` ∪ K's table; **next** = the `:next` leaves, and P itself on a path without `:next`; **uses** = the ops; the **posture** of each refusal path (its next phase and the holds it gives up) for D0's resource check (`fn2-arm-resource-problem`, kept). Checks, all macro refusals: every path ends in exactly one terminal; an op that declares `:answers` (new defcost key: the codes it can return) has every answer routed (`:accept` continues, `:case` arms, anything else goes to the arm's `:on-refusal`; no `:on-refusal` and an unrouted answer is a refusal); `:do` of an op with no defcost, or of a per-octet export (`fn2-core-read/-write`, `fn2-pool-read/-write`), is refused (the octet vocabulary is the range primitives by handle; rule 2); the cost within the budget, D = 0 with an `:issue` refused; no hand `defthm` in a kind's book except about a declared operation (rule 3). The run-time certificate (`K-ARM-OK-P`) stays: it is now a check of the generator, not of a hand body. `fn2-arm-walk-list` (the body checker) is deleted with the last hand callback.

### 6.4 Emitted per kind
The columns (declared fields only), `K-PUT-CORE`, per-field readers `K-ROW-F`, `K-FINISH` with K's caps (the `with-work` preflight is statically true for a K row once the cost is checked, so it is not emitted: that removes the kind case-split from every arm guard, the "callback guards" family of the anatomy), one function per arm and per handler (`K-ARM-P`, `K-ON-EVENT`, `K-SUB-NAME`) with the derived contract in the registry, `K-RUN` and `K-OBSERVE` (a `case` over phase / event, no kind case), the certificate and teeth (today's generators, fed derived data), the per-arm owed rows (bound, frame, continuation; totality), the catalogue labels (unchanged: `(:run K P)`, `(:observe K E)`), the mutation sites (the arm functions, recorded as `:mutation-sites` in K's row, so q1-controls names a site per arm and only the oracle by hand), and K's per-child facts.

### 6.5 Placement (what makes a kind certify alone)
- **P1, the cross-row fields in the directory.** The row fields generic code writes in rows other than the running one, `ready-prev ready-next wait-reason` (the resource FIFOs' links and the wait reason the grant service clears), become columns of `fn2-machines` indexed by global id (`*fn2-machine-directory-fields*`); a kind's `:columns` (its row) is unchanged and its table (`:table`) is the rest; `K-PUT-CORE` checks the whole batch and then writes K's table and the directory; `K-ROW-F` and the dispatchers `fn2-machine-F` for these three read and write the directory with no kind case; parks and grants therefore touch the directory and no kind's table. The other row-control fields stay in the kind's table because only the row's own arms write them (`generation`, `principal-slot`, `account-ref`, `deadline`, `phase`, `pending`, `stopped`; the admission's copies are a registry arm, the listener's principal setter is setup) and two of them have per-kind initial values (`generation`, `account-ref`). Behaviour identical; a kind's `:initial` may restate a directory field's default only.
- **P2, operations over the children they touch.** Each core operation an arm may call gets its body over its declared children (`fn2-core-issue` over pool+ops returning a stop reason; the pool range ops over the pool; parks over the directory; `fn2-core-stop` over control; the ledger's ops over accounts); the `fn2-core` faces are generated wrappers (one `stobj-let`), used by the executor and the not-yet-ported kinds. A layer's own operations (B's commit batch, C's seal step) are written the same way in its own books.
- **P3, arms over declared children.** The arm functions take K's table and the stobjs their operations take (read from `stobjs-in`), never `fn2-core`; the frame "children not in :tables are unchanged" is then true by the signature, and type/wfp are each child's own recognizer. The owner triple is `(kind-of id, id, generation)` read from the directory at run time, so no kind constant is needed before the index (C gap 6). K's book includes A's library and its operations' books, and certifies alone.
- **P4, the assembly is a registry.** It assigns kind codes and partition ordinals, makes `fn2-core`, and per kind emits `K-RUN` over `fn2-core` (one `stobj-let` of K's children, its type/wfp by the per-child facts of 867e87a23) and a per-kind rewrite `(implies (equal (fn2-machine-kind id core) *K-KIND*) (equal (fn2-machine-run id budget core) (K-RUN id budget core)))` so no guard case-splits over kinds; init per child from its own `:profilep`; the reference copy per child. **Registry arms**: an arm whose `:do` names a registry operation (the listener's `fn2-machine-admit`, a `take-K2`) is emitted in the registry section, proven against the children of the kinds that operation dispatches to, not all kinds. The assembly's cost then grows by one wrapper and one rewrite per kind.

### 6.7 What a layer changes in its arm table to port
Each table row becomes `(P STEP ...)`: "reads" are `ROW-F` in expressions; "writes" become `:set`; "next" becomes `:next` (codes via `:case`); "effects" are `:do` of declared operations (each with `:answers` if it returns a code); "refusals" become `:case`/`:accept` routes or the arm's `:on-refusal`; "cost" is not written (it is the max of the `:charge` terminals, which state what the body charged before). An op the arm table names that is a hand defun over `fn2-core` stays as a declared operation (defcost with `:answers`) until P2 moves it to its children. B: the 27 `assert$?` become `:case` routes to `(:stop R)`; C: the seal row becomes `:sub`, the park `(:park :sealable)`, the genesis `:genesis`, D = 0; D: every `fn2-machine-refuse-phase` after a code test becomes a route.

### 6.8 Astra's read (lanes/form-quests/astra-design.md), what it changed
