## 1. Layer A books [main]

### 1.1 Silent absorption: refusals that nobody reads, writes that do not happen

The core's house style is "validate every scalar at run time and return a keyword". That is right at the adapter boundary. Inside the core it has become the opposite of TigerStyle: impossible states are not asserted, they are absorbed, and the absorbing code then discards the keyword.

| # | Sev | Sin | Where | Remedy |
|---|---|---|---|---|
| A1 | **RED** | `fn2-core-issue` reserves, leases, then calls `fn2-op-set-range`, `-set-capability`, `-set-storage`, `-set-cancel-target` and `fn2-op-enqueue` binding every result code to `?ignored`, and returns `:ok`. If `enqueue` ever refuses (its own preconditions at `vocab.lisp:387-389` are wider than `fn2-core-outbox-ready`'s), the caller is told the op was issued, the row stays `reserved` holding a credit, and the pool lease is outstanding forever. Nothing proves the ignored codes are `:ok`; the owed refusal theorems cover only `code ≠ :ok`. | `books/core.lisp:233-241` | Prove the post-reservation calls cannot refuse (guard them with the facts the reservation established) and delete the dead branches, or turn a non-`:ok` into a stop with evidence. |
| A2 | **RED** | `fn2-harvest-one` drops the result of `fn2-pool-complete-in`, `fn2-pool-release-out` and `fn2-op-finish`. A refused `complete-in` (lease identity mismatch) leaves the slot `leased-in` while the machine is told `count` bytes arrived; a refused `release-out` leaves a borrow that never ends; a refused `finish` (`:exhausted` from recycle) strands the op row. This is the byte-fill boundary, the one place the design says bytes become core-readable. | `books/core.lisp:340-355` | Each of the three is either proved `:ok` under the harvest's own validation or stops the executor with a named corruption signal; no `?ignored` on this path. |
| A3 | **RED** | Generated setters silently ignore a value that does not fit: `fn2-machine-set-FIELD` returns the core unchanged when `(not (unsigned-byte-p width value))`; so do the scalar directory setters and every `fn2-exec-set-*`. | A9 | AMBER | Readers that lie about invalid input: `fn2-op-kind`, `-phase`, `-gen`, `-owner`, `-range` ... return 0 for an out-of-range slot (0 = `:accept`, phase 0 = `:free`); the generic machine field getters return 0 for an invalid id; `fn2-pool-read` returns byte 0 beside its refusal code; `fn2-recovery-byte` returns 0 past the end. ## 2. The simulator and its checkers [main]

| # | Sev | Sin | Where | Remedy |
|---|---|---|---|---|

### What is solid (so the remedies do not break it)

### The three architectural sins

1. **Absorb instead of assert.** Validation is everywhere and invariants are nowhere. Every internal call re-validates its scalars at run time and answers with a keyword, and the internal callers then discard the keyword, setters drop values that do not fit, readers return a valid-looking 0, counters clamp, and a corrupt FIFO head turns into a livelock. TigerStyle's point, that an assertion turns a correctness bug into a liveness bug the operator sees, is inverted here: correctness bugs become silent liveness bugs nobody sees. The remedy is architectural, not local: name the boundary (host-supplied observations and descriptors: `fn2-post-result`, `fn2-post-clock`, `fn2-outbox-ack`, the adapter's scalars), validate there only, and inside the core let guards and `mbt` carry the invariants, with any residual impossibility stopping the executor with a reason the simulator asserts on. (A1-A10, B8, S5)

2. **The DSLs generate storage, not meaning.** `defcolumns` and `defmachine` emit the stobjs; the meaning of what is stored lives in hand-typed integers and positions: enums generated and then compared as `0..3`, enum counts typed as `14`/`12`/`13`, 17- to 34-parameter positional functions, positional tuples in models and checkers, field ordinals in the format checker, magic word offsets in the Merkle table, `defmachine` pasting code that captures the generator's variable names and listing obligations it never emits, and [B]'s layouts interpreted byte by byte on the served path because no generator turns them into code. The derived path the laws require stops at the `defstobj`. Remedy: every DSL emits the names its consumers need (constants and counts, field indexes, put/snapshot/preserves, per-kind run bindings, per-layout codecs) and records itself in the world, and consumers use only emitted names (a world-reading lint can refuse an integer literal compared to a declared enum column). (A13-A18, A23, B1, B3, B7, B9, B12)

3. **Layers reach into each other's representation instead of through seams.** The scheduler includes the probe machines and stores the scribe's id; the shared machine directory carries the echo/null mode flag, the null free list and a singleton pool-wait; the core stobj's shape is generated from the application's machine table, so every D machine recertifies the layer-A world; the TRACE reference runs the implementation's machine code; [B]'s format checker receives its arguments in rows `≥ 96` of the decoder's scratch table and stashes the decoder's cursor; [B]'s codec waits on A's range primitives through a per-byte shim. Remedy: each layer exports a small interface over its own stobj child and owns its scratch; the probe machines move to tests; the only cross-layer coupling is the declared core-children list and the functions each child exports. (A24, A26, A27, S2, B2, B4)
