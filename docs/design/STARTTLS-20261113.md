# Configured STARTTLS

Status: implementation in progress (Codex, 2026-11-13). The served path still
refuses STARTTLS until the complete slice below is integrated and exercised.
This extends D7/E1; it does not replace their remaining product requirements.

The existing connection answers 580 in `conn-answer.lisp`; its declared
`:upgrading` arm stops the machine. `TlsStart`/`TlsResult` exist in the action
vocabulary, but no machine issues the operation and the native adapter fails it.
The old native STARTTLS tests describe expected behavior, not current fn2 support.

## Served slice

ACL2 admits a handshake through a bounded `tls-admit` machine partition before
rendering 382. It retains the connection's parser position, flushes the entire
382 response and its loan, then transfers the retained RX ciphertext to the
handshake operation as a validated outgoing range loan. No further NNTP framing
runs during upgrade. The admission row is a held token; the connection owns its operation and
scheduler deadline. Refusal, cancellation, failure and success drain the token
and all loans. A deadline cannot reclaim a token before terminal harvest.

A successful TLS result resets selected group/current article/pin and pending
authentication, updates the connection's TLS state, and resumes ordinary command
framing over decrypted Receive results. Duplicate STARTTLS and disallowed states
answer the grammar's 502. CAPABILITIES advertises STARTTLS only where ACL2 admits
it. A configured but temporarily exhausted handshake partition refuses without
starting an unaccounted handshake. The timer uses the scheduler's bounded scan,
not host wall-clock policy or a busy polling connection.

The initial supported transport is OpenSSL 3, TLS 1.2 minimum and TLS 1.3
negotiation when the client supports it. Other library/version profiles remain
explicit work. The host keeps OpenSSL state attached to the physical capability incarnation.
Bounded BIO pairs retain ciphertext; every input, output and TLS call is bounded
by the supported execution profile and yields on insufficient space or readiness.
The host copies only descriptor-validated spans. OpenSSL never parses NNTP or
chooses an identity, reply, deadline, admission or grant. Cancellation and Close
free TLS state exactly once; stale capability generations cannot reuse it.

The external TLS implementation and OS remain assumptions. ACL2 obligations
cover framing, ownership, admission, bounds, observation interpretation and
state transitions; they do not prove encryption or certificate authenticity.
OpenSSL's nonblocking handshake and BIO-pair contracts are the mechanism:
https://docs.openssl.org/3.1/man3/SSL_do_handshake/
https://docs.openssl.org/master/man3/BIO_s_bio/

## Gates and outstanding breadth

Use ephemeral local test keys/certificates only. Exercise a real encrypted
CAPABILITIES/read exchange, duplicate upgrade, failed handshake, pipelined
ClientHello suffix, slot exhaustion, stalled handshake timeout, cancellation,
and subsequent slot reuse. Assert 382 flush order and no plaintext command
execution across the barrier. The simulator supplies transport observations;
only native socket tests establish that the OpenSSL adapter actually runs.

Remaining E1 work stays explicit: implicit TLS listener, trusted PROXY handling,
protected-only policy, reload/config generations, self-signed operator surface,
exporter connection to SCRAM-PLUS, postquantum-preferred policy and associated
interoperability/resource tests. Completing this slice does not mark E1 done.
