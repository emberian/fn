# Configured STARTTLS

Status: implementation in progress (Codex, 2026-11-13). The served path still
refuses STARTTLS until the complete slice below is integrated and exercised.
This extends D7/E1; it does not replace their remaining product requirements.

The existing connection answers 580 in `conn-answer.lisp`; its declared
`:upgrading` arm stops the machine. `TlsStart`/`TlsResult` exist in the action
vocabulary, but no machine issues the operation and the native adapter fails it.
The old native STARTTLS tests describe expected behavior, not current fn2 support.

## Served slice

ACL2 admits a handshake through a bounded `tls-admit` machine partition before
rendering 382. It retains the connection's parser position, flushes the entire
382 response and its loan, then transfers the retained RX ciphertext to the
handshake operation as a validated outgoing range loan. No further NNTP framing
runs during upgrade. The admission row is a held token; the connection owns its operation and
scheduler deadline. Refusal, cancellation, failure and success drain the token
and all loans. A deadline cannot reclaim a token before terminal harvest.

A successful TLS result resets selected group/current article/pin and pending
authentication, updates the connection's TLS state, and resumes ordinary command
framing over decrypted Receive results. Duplicate STARTTLS and disallowed states
answer the grammar's 502. CAPABILITIES advertises STARTTLS only where ACL2 admits
it. A configured but temporarily exhausted handshake partition refuses without
starting an unaccounted handshake. The timer uses the scheduler's bounded scan,
not host wall-clock policy or a busy polling connection.
A separate positive-u32 `:tls-handshake-turns` profile budget (default65536)
is initialized once per capability. Before each handshake transport turn,
`fn2-host-tls-next-turn` admits and strictly decreases it; exhaustion produces
a failed TLS result before further BIO or SSL work, followed by ordinary drain.
Thus a stalled clock cannot authorize unbounded handshake transport turns.
The bound is on calls and explicit buffers, not on OpenSSL internal CPU or heap
use per call; those remain supported-library contracts requiring evidence.

The initial supported transport is OpenSSL 3, TLS 1.2 minimum and TLS 1.3
negotiation when the client supports it. Other library/version profiles remain
explicit work. The host keeps OpenSSL state attached to the physical capability incarnation.
The ACL2 profile also reserves one transport staging window per admitted
connection, each exactly the class-zero RX capacity selected by the connection
admission generator. `fn2-tls-seed-reservation-bytes` states the aggregate
capacity (connection count times RX capacity), and `fn2-host-tls-settings`
supplies that capacity to the host. This window belongs to the live connection,
not the transient handshake token. TlsStart copies its validated retained span
into staging in bounded chunks before returning its loan. Subsequent encrypted
operations feed staging before reading the socket. This avoids deadlock when a
final handshake record is followed by more application ciphertext than the BIO
can hold; no extra input cap or truncation is introduced. Close/cancellation
reclaims the staging with the capability's TLS state. The connection-count to
native-allocation correspondence remains an explicit proof/runtime gate.

Bounded BIO pairs retain ciphertext; every input, output and TLS call is bounded
by the supported execution profile and yields on insufficient space or readiness.
`fn2-host-tls-span` and `fn2-host-tls-stage-span` decide each physical
copy/feed/read/send span from the descriptor, profile quantum and observed BIO
room. Their registered bounds include whole-antecedent and hypothesis-removal
controls. Raw wrappers reject a refused span before I/O. The host copies only
descriptor-validated spans. OpenSSL never parses NNTP or
chooses an identity, reply, deadline, admission or grant. Cancellation and Close
free TLS state exactly once; stale capability generations cannot reuse it.
TLS selection remains attached to the capability even after cancellation frees
its SSL retry state, so a later operation cannot fall back to plaintext.
A fresh capability incarnation begins with a fresh transport selection.

The external TLS implementation and OS remain assumptions. ACL2 obligations
cover framing, ownership, admission, bounds, observation interpretation and
state transitions; they do not prove encryption or certificate authenticity.
OpenSSL's nonblocking handshake and BIO-pair contracts are the mechanism:
https://docs.openssl.org/3.1/man3/SSL_do_handshake/
https://docs.openssl.org/master/man3/BIO_s_bio/

## Gates and outstanding breadth

Use ephemeral local test keys/certificates only. Exercise a real encrypted
CAPABILITIES/read exchange, duplicate upgrade, failed handshake, pipelined
ClientHello suffix, slot exhaustion, stalled handshake timeout, cancellation,
and subsequent slot reuse. Assert 382 flush order and no plaintext command
execution across the barrier. The simulator supplies transport observations;
only native socket tests establish that the OpenSSL adapter actually runs.

Remaining E1 work stays explicit: implicit TLS listener, trusted PROXY handling,
protected-only policy, reload/config generations, self-signed operator surface,
exporter connection to SCRAM-PLUS, postquantum-preferred policy and associated
interoperability/resource tests. Completing this slice does not mark E1 done.

## Connected transport pilot (in progress, served_names)

The comparison snapshot is `d1069b21f`: four OpenSSL primitive controls pass,
including prompt-free key refusal and retrying identical plaintext from a moved
buffer. It is not a qualified native STARTTLS image.

`books/tls-transport.lisp` now selects each handshake copy/feed/drain/send/receive/
SSL action and consumes its raw return once, matching capability index/nonce, operation
slot/generation and action serial. `host/tls.lisp` executes that selected action;
`fn2-n-tls-handshake-ready` calls this path. A bounded action budget prevents
serial wrap. The concrete table has one row (`defcolumns :rows-bound 2` is an
exclusive bound). Handshake completion transfers retained staging to the record
path through a matching, once-only logical handoff; partial BIO input is retained.

The terminal operation envelope stays `(slot gen kind event len code count aux
word now fault)`. It does not describe the inner primitive effects. Raw signed
code, count and errno remain separate ledger fields, before normalization. SSL
WANT_READ/WANT_WRITE may mutate hidden library state and generate output; no
proof assumes these are effect-free. Crypto, hidden SSL transitions and exact
physical byte-prefix effects need explicit primitive contracts and their native
connection, not an assumption that the entire adapter is correct.

The actual next/observe functions preserve the concrete staging invariant;
initialization establishes it, and each selected physical action spends one
budget unit and advances its serial. Both preservation obligations have passing
whole-antecedent and hypothesis-removal witnesses. The handshake handoff checks
the same capability/operation epoch, copies the exact staging coordinates into
the record path and can succeed only once. These are numeric ownership and span
facts; the exact physical-byte relation is still owed.
