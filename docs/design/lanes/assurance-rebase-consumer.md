# Directory base and sufficient-summary consumption

Owner: Codex Sol, `lane/assurance-rebase-consumer`.

The live master now reaches actual pending-summary consumption between bank
publication and C-source release in source. It remains inactive and uncertified.
The cold installer is a distinct leaf for the boot coordinator's selected C0.

`fn2-directory-rebase-step` scans one exact batch at a time from the previous
base through installation J. Every prefix batch through C must retain its actual
canonical journal allocation under the completed checkpoint's dedicated source
edge. The scanner records seal C, checks event continuity and covers all C+1..J
rows, including J>C+1. The owner, allocator freeze, base and installed/published/
proposed frontiers must stay unchanged through the whole scan and consume.

`fn2-directory-rebase-consume` requires complete pending row1 authority for that
same descriptor/namespace/cut/owner and exact scanned seal. One fixed bounded
installation copies descriptor/frontier/seal into active row0, installs base C
and its predecessor seal and only then clears pending row1. The live Merkle
frontier at J, suffix rows, old C catalog/query leases and every allocator edge
are preserved. This is directory publication, never physical release permission.
The retained canonical root3 journals still carry historical, retry, peer,
identity and obligation observations; sixty frontier peaks are not a replacement.

`fn2-directory-cold-install` rechecks the actual cold-source predicate, complete
active0 authority and exact projected phase4 owner. It starts a pristine runtime
root at C0 and restores its real event frontier and predecessor seal. The boot
coordinator owns when this leaf is invoked and when suffix replay begins.

Source gates: exact directory rewrite fixtures, complete-authority/suffix
mutation controls, actual master state/arm/hold shape, named-file secrets and
Lisp parsing. `tests/checkpoint-directory-consume-unit.lisp` contains actual
allocator/scan/consume calls for a C=1,J=3 positive, retained old holds and
incomplete/owner/interleaving/missing-source/seal refusals. These ACL2 assertions
have not run: this lane has no ACL2/native/remote computation grant.

Remaining work owned here: connect the next live root3 producer to the prior
retained canonical directory instead of assuming absolute resident batch rows;
update event proof/read consumers accordingly. Wrap admission remains closed.
The parent owns selected boot orchestration/activation; the allocator lane owns

grants FREE. The decisive two-checkpoint test with physically reclaimed/reused

The retained event catalog now uses two disjoint stripes of the existing
`fn2-checkpoint-restore-events-work` layout: cold scratch below the physical
extent count, retained canonical source rows above it. Control row0 belongs to
investigation; row1 belongs to retained catalog transfer/consumption. Both image
and nonimage profiles reserve these lifetimes: two metadata and 32-byte seal
stripes, two control rows and one additional 32-byte descriptor. Profile checks
cover the row and seal address representation. Cold scratch bounds uniformly use
the first stripe capacity, preserving old source behavior when initialized at
logical capacity N. No later candidate scan may address retained rows.

`fn2-event-catalog-cold-begin/step` bind the same actual final cold source as the
base installer and copy one authenticated source entry/seal per turn. Every step
rechecks source generation, descriptor and the exact phase4 owner. The caller
cannot mint catalog readiness or supply source facts. The parent must insert
this transfer after completed cold authority and before cold base installation.
Six source/mutation controls and three transformation identity/rejection
controls pass; the explicit scratch-overwrite/retained-stripe ACL2 assertion is
added but unrun. Actual live append and producer/read routing remain owned here.

The live master now has a separate bounded archive pass after the prefix/suffix
scan. `fn2-event-catalog-live-step` derives each next source from the exact tagged
resident batch, checks the checkpoint-owned canonical source hold and appends one
fact/seal to a previously empty retained row. Existing catalog rows stay
immutable. The old catalog generation is retained; it is not compared to the
new live snapshot token. The pending descriptor/cut and master token own the
in-flight control. Consumer publication now requires the complete pending catalog
subject before it swaps active authority/base, making that catalog current only
at the successful join. Source-scanned alone cannot publish it.

Shared parameterized subject readers serve active0 and pending1; the active
wrapper additionally binds the runtime base. Structural transformation fixtures
check the actual reader against its prior active0 source. The C=1,J=3 ACL2
fixture now calls the real archive append and concludes exact retained seal and
current catalog as well as old source/suffix retention; it remains unrun.
Actual next-root3 pack/read routing and live C adoption remain outstanding. The
summary owner owns the C adoption terminal and master stage insertion; activation
must stay closed until their terminal is part of the consume antecedent.

The actual next-root3 source cone now reads retained canonical rows at or below
the active base and exact mapped resident rows afterward. The same event-entry
codec, pinned block-read operation, physical format verifier, member scanner and
Merkle append primitive remain the source path. Reader and verifier compare the
retained fullRef with actual allocation identity and exact owned protection.
Expected and predecessor archive seals use two separately reserved digest rows;

Readonly source carriers are explicit through the generated child boundary;
structural call/guard/projection rewriting and actual arity controls cover the
changed cone and its existing runnable fixtures.

`tests/event-catalog-read-unit.lisp` uses the real C1/J3 consume/archive fixture,
aliases the old directory row and replaces its resident seal, then invokes the
actual packer and verifier seal resolver. It checks exact archived metadata/seal,
zero genesis predecessor, retained allocation and descriptor/generation refusals.
These are source/metadata controls, not physical canonical-byte authentication
or a second checkpoint's successful native execution; all ACL2 assertions remain
unrun. Full-prefix canonical journal retention is still an intermediate format.
Physical reclamation still needs the parent-owned bank/archive contract and
actual live C adoption, plus the decisive two-checkpoint reclaim/reuse control.

The canonical-byte archive now composes the immutable physical run loader from

shared physical cursor/fullRef/owner binding and grants no descriptor authority.
Five structural controls compare both transition bodies with the original source,

Schema20 is reserved for internal canonical member bytes and the actual shared
phase3 leaf digest; schema21 remains reserved for future real carry-node output.

The common physical engine no longer imports cold catalogs or boot orchestration.
Its actual harvest observer moved unchanged into the lower I/O book. Boot's whole
configuration declaration and geometry word/copy/load bodies moved unchanged into

exports. The structural extraction accepts the integrator's current declaration,
including future fields, and preserves unrelated bank/recovery forms. Four source

ASTs, and the real include closure; six engine controls also compare harvest.
No loader body, source authority, parser, hash, or completion semantics changed.
