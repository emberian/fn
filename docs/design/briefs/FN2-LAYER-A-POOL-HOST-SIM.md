## Contract
1. **The byte pool** (`fn2/books/pool.lisp` and its DSL support): one stobj region of fixed capacity allocated at start; slots with `(generation, offset, length)`; ownership states free / workspace(owner) / leased-in(op) / leased-out(ops, count) / handed(from, to); handles `(slot, generation, offset, length)`; exports: reserve, release, lease-in, complete-in (makes the written range readable), lease-out, release-out (borrow ended), hand, accept-hand; every export checks generation and bounds; no allocation after init; the octet list exists only in the logic (an abstract view, never materialized on the served path). The ownership rules are EXECUTION-MODEL rule 6 and ROUND2-ASTRA §B.1 encodings. Write the records/columns DSL seed here: a `defcolumns`-style macro that declares a struct-of-arrays table with typed fields and widths and generates the stobj, accessors, bounds-checked updaters, and the logical view; the pool's slot table is its first user, the machine tables (layer D later) its second.
2. **The event and action vocabulary** (`fn2/books/vocab.lisp`): ROUND2-ASTRA §D.2 events and §D.3 actions as fixed-width records (finite tags, `OpRef`, `MRef`, `Range`), the outstanding-operation table with reserved result storage (§D.1 capacities as parameters of the profile, not constants), the outbox; reservation before submission; exhaustion as a returned condition.
3. **The host primitive set** (`fn2/host/`): the 21 primitives of ENVELOPE-AND-HOST §2 with the signatures there, as one SBCL adapter for Linux: sockets (epoll first; io_uring behind the same interface later), one preallocated direct-I/O data file for storage reads/writes/flush with the backend barrier contract of STORAGE-DESIGN-ASTRA §E.3, timers, clock, entropy, TLS as a stub that refuses until layer E, cancel, signal. The adapter consumes the outbox, acknowledges a consumed prefix, submits, and delivers completions into the reserved result storage; it never decides anything (EXECUTION-MODEL §7a item 3 is yours to specify precisely: queued vs submitted, when bytes become core-readable, death cuts at the handoff). Target ≤ 3K lines.
4. **The simulator** (`fn2/sim/`): the same 21 primitives implemented over an in-memory model with a seeded PRNG; faults from the papers table: torn writes at write units, lost writes after a successful flush, corruption at rest, misdirected reads and writes, reordering of in-flight writes, slow and failing devices, partial sends and receives, connection drops, clock jumps, process death at any action boundary and during recovery; records profile, seed, observation order, fault choices, revision; the eleven checkers of ROUND2-ASTRA §F.1 as a framework with OWN, WORK, TRACE and ACCOUNT implemented now (the others arrive with their layers); the first scenarios: pool ownership under every fault, queue exhaustion (§F.2 scenario 12), counter exhaustion and stale events (19), unfinished cancellation (10).
5. **The executor loop** (`fn2/books/executor.lisp`): `fn2-turn` as the plain bounded loop of ROUND2-ASTRA §A.1 over a trivial machine table (an echo machine, then a null connection machine), with the harvest/turn budgets of §C.3, the calendar scheduler of §C.2 over an empty principal table, and the "wait only when nothing eligible" rule of §C.4. Layer D fills the machine tables; you make the loop run and the simulator drive it.
