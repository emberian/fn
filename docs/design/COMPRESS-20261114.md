# COMPRESS serving contract

This is the target serving contract. The integrated pure policy does not yet
enable the connection upgrade.

COMPRESS preserves the authenticated principal, selected group and article cursor.
Only an authenticated connection, a supported DEFLATE algorithm, no active
compression layer and an enabled supported profile can admit the upgrade.
The 206 reply finishes through the current carrier before the compressed carrier
starts. Retained input after the command belongs to the new carrier and is never
framed under the old one. TLS may already be active underneath compression.

The shared codec ledger owns capability incarnations, borrowed spans, selected
actions, cleanup and exact observed input/output prefixes. Compression supplies
policy through `fn2-compress-plan` and `fn2-compress-observe`; it does not keep a
second set of native cursors. Both primitive spans are bounded per call. NNTP and
consumer framing, lengths and charges see application octets after decompression.
The external zlib implementation remains a native byte-effect assumption.

The supported profile explicitly supplies `:compress-enabled`,
`:compress-input-quantum`, `:compress-output-quantum`,
`:compress-expansion-ratio` and `:compress-expansion-burst`. Enabled profiles
require positive u32 settings, output quantum at least seven and at most the burst. Missing
enablement disables compression; missing enabled settings refuse the profile.
There is no lifetime compressed-input, article-size or connection-size ceiling.

The seven-octet encoder minimum follows zlib's documented Z_SYNC_FLUSH
precondition: each call needs more than six output octets to avoid repeated
flush markers. The pending encoder selector must write only into an empty full private
output window, with count exactly the configured output quantum. It must drain
that window over as many lower-carrier writes as needed before another codec
call. Socket room and receive expansion credit never shrink that flush span;
a turn unable to reserve it yields. Decoding still supports one-octet
application windows. The generated encoder selector now enforces this per-call invariant in source;
its full-window theorem author-passed, while the composed record guards and
native byte-effect gate remain pending. Primitive controls exercise encoder capacity seven and
ordinary capacity twenty-nine, including persistent duplex streams.

Expansion admission is a token bucket, deliberately stricter than a lifetime
ratio. Its resident credit begins at the configured burst; a validated transform
consuming U compressed octets and producing M application octets changes it to
`min(burst, credit + ratio*U - M)`. A transform can request no more output than
its existing credit. Unobserved input grants no speculative credit. Saturation
at the declared burst discards surplus replenishment, preventing an attacker
from saving unbounded expansion allowance with an incompressible prefix. The
one-step inequality `next-credit + M <= credit + ratio*U` composes to the lifetime
bound `total-output <= initial-burst + ratio*total-input`; the bucket also bounds
burst expansion at every prefix.

Zero credit is an explicit `:limit` decision and closes the connection. It never
issues an output window of zero or waits indefinitely for input credit that the
codec cannot acquire. BFINAL and malformed compressed input likewise close;
neither starts a second raw-DEFLATE stream. Ordinary window exhaustion yields
and resumes using retained spans.

Concrete configuration, generated compression lifecycle/selector and connection
upgrade routing are integrated as source. The connection drains its 206 reply
on the old carrier before issuing the retained-input loan, then waits for the
matching result and loan release before activation. Reset uses the existing
`:io` saved-result code; an issue/take/stage/save/post fixture covers success
and reset. The new roots are registered for normal selection. Exact logical
gates, native dispatch/stacking and actual served roundtrip/refinement gates
remain pending. Compression is not yet
served. Zero-credit close and BFINAL handling above are requirements on that
composition, not claims established by pure policy or primitive tests.

The internal native producer candidate loads `host/compress.lisp` from the
adapter, obtains startup scalars solely from `fn2-host-compress-settings`,
schedules `CompressStart` as bounded local work, and routes selected application
operations through the upper controller before TLS. Close retires TLS first,
settles any selected private child, then frees compression; deferred Cancel
uses the retained logical operation even after the socket is closed. Decoded
public input emits the shared accepted `:input-prefix` receipt. This is source
composition, not a served claim: public enablement remains disabled, and actual
record/closure/host guards, load/interface checks, socket roundtrip and stacked
byte-effect controls are still required.
