# Exact C binding debt before B publication

The actual B member retains transaction slot/generation and bind state; its
batch row counts pending claims. Typed admission requires the actual LIVE
successful EMIT tuple and idle actual C binding engine. The shared scanner
rejects schema mutation input without that claim. The normal transaction face
still accepts its supported non-schema records; lifecycle producers retain
separate source-specific admission. No encoded record or caller readiness flag
can manufacture C bind authority.

`fn2-commit-admit-successor` installs actual membership and registers its exact
pending subject without yielding. The upper C producer must claim its retained
binding continuation in the SAME call before yielding. The typed B operation
is an internal half of that composition, not an independently scheduled host
step. Source generation, EMIT provenance and upper producer migration belong
to the C binding implementation.

Completion requires the actual C BOUND/COMPLETE terminal, original LIVE EMIT
identity and exact member length. It decrements once and wakes the B owner;
an exact repeat cannot decrement twice. Cancellation instead requires the
actual C OPEN/CANCELLED tuple and actual B DROPPING with no issued write,
pending operation or live fence. Prior COMPLETE cancellation does not subtract
a second count. An uncertain B row retains its member and resources.

Actual root installation/publication swap and settlement refuse nonzero debt.
The two actual install/publish arms yield while pending; completion supplies
an event-driven wake. Drain cannot free unresolved ownership. START cannot
reuse a FREE row with pending debt; each actual member insertion clears stale
terminal fields before typed registration.

bounded C cursor runs, before unprepare or refusal settlement. The C kernel

earlier dropping batch parked behind a later binder wakes. The operation has
at most two wake calls; completion itself has one. Do not overwrite the active
binder receipt to service another batch.
