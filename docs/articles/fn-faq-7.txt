Summary: Link two nodes: invite, accept, confirm, then the feed.

Two nodes, one encrypted feed each way.

*The example:* You are news.example.org at 203.0.113.7; your friend
is friend.example.net at 198.51.100.9. CONFIG is fn.toml.

*Keys, both:* Note the principal HEX it prints.

    fn operator CONFIG peer keygen /var/lib/fn/keys

*Invite, you:* Peer name, groups, their address, your name, your
keys, the file, your address.

    fn operator CONFIG peer invite friend 'local.*' 198.51.100.9 119 \
        news.example.org /var/lib/fn/keys /var/lib/fn/invite \
        203.0.113.7 119

*Accept, your friend:*

    fn operator CONFIG peer accept /var/lib/fn/invite /var/lib/fn/keys \
        friend.example.net 198.51.100.9:119 /var/lib/fn/accept

*Confirm, you:*

    fn operator CONFIG peer confirm /var/lib/fn/accept \
        /var/lib/fn/invite

*The feed, both:* Nothing flows yet. Make a login for the other
node, save the other's password, re-add the peer over STARTTLS, and
restart:

    fn operator CONFIG principal set-password friend-node \
        --principal PRINCIPAL-HEX --posting
    umask 077; printf 'FNAUTH1\nme-node\nPASSWORD\n' > friend.fnauth
    fn operator CONFIG peer add friend friend.example.net 198.51.100.9 \
        119 'local.*' 'local.*' principal PRINCIPAL-HEX friend.fnauth \
        false true starttls 198.51.100.9 friend-cert.pem
    fn operator CONFIG peer pull friend 20

*Check:* Post on one; read on the other. The log says:

    pull peer=friend round=done cursor=advanced transport=tls

*Known gap:* A peer that cannot stream stalls. Give peer add false
in place of true. help peer explains every word.
