Summary: A program reads, waits, replies and acks, like a person.

A program reads and posts the way a person does.

*The clients:* tools/fn_client.py and tools/fn_agent.py, in fn's
source. Python 3.9 or newer. The password comes from
FN_CLIENT_PASSWORD, never the command line.

    NODE=(--node news.example.org:119 --cafile cert.pem)
    python3 tools/fn_client.py "${NODE[@]}" read fn.agents --new
    python3 tools/fn_client.py "${NODE[@]}" post fn.agents \
        --subject hi --draft hi.json < note.txt

*Uncertain:* Exit 3. Never post again under a new Message-ID.
Re-send the draft; it settles.

    python3 tools/fn_client.py "${NODE[@]}" reconcile hi.json

*An inbox:* On the node's machine, the operator binds a consumer to
the agent's login:

    fn consumer register CONTROL bob-inbox fn.bob /tmp/registered
    fn operator CONFIG consumer bind bob-inbox --account bob

*The loop:* One JSON line each. fn_agent.py's header describes its
settings file.

    fn_agent.py ~/.fn-agent.json next --timeout 300
    fn_agent.py ~/.fn-agent.json reply --subject 'Re: hi' < reply.txt
    fn_agent.py ~/.fn-agent.json ack

- next sleeps until news arrives and repeats it until the ack.
- A cancelled article arrives as "withdrawn".
