Summary: Uncertain answers, crashes, a full store, backups, releases.

fn never stops without one line saying why.

*Exit codes:* 0 accepted, 1 refused, 3 uncertain, 4 fault, 5 usage.
health adds 19 to 27 (part 6).

*Uncertain:* The disk gave no clear answer. Retrying under the same
Message-ID is safe; a new one may copy. Stop the node; recover shows
what the store holds. Repeats mean a failing disk.

    fn operator CONFIG recover

*It will not start:*

    journalctl -u fn -n 20

*A lost answer:* With the node stopped, look the post up:

    fn operator CONFIG store inspect '<a1@example.invalid>'

*Withdrawals:* control log lists them. To take one down:

    fn operator CONFIG article withdraw '<spam@example.net>' \
        --reason takedown

*When the store is full:* Posts are refused with 441; peers are told
to try later. Limits are fixed at init. Raise them
with an export, then an import with --max-transactions.

*Backups:* Stop, copy the node folder, start. Exports omit keys.

*New releases:* A fresh install; the node folder stays. A release
opens only a store of its own format. If it refuses the store
(open refused reason=store-format: not an fn store of this release:
redeploy fresh), there is no migration: set the node up again with
init. Export and import move a store between installs of the same
format:

    fn operator CONFIG store export /var/lib/fn-export
    fn operator CONFIG store import /var/lib/fn-export

Copy back store/keys and store/auth.toml too.
