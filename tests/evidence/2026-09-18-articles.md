## Added evidence

| Area | Established scope |
| --- | --- |
| Article syntax | Bounded octet/header/line/field parsing; exact folded and unknown fields; opaque body bytes; explicit malformed framing and resource-limit results |
| Source preservation | `fn-article-successful-parse-preserves-source`: every successful parse reconstructs its exact input octets, with no additional caller hypotheses |
| Release safety | `fn-retain-release-preserves-statep` for a valid ledger and arbitrary release arguments; independent pins and known obligation identities are preserved |
| LISTGROUP | Current/explicit group, bounded numeric ranges, inclusive/open/reversed ranges, sparse and empty results, sorted available numbers, and group-wide summary/cursor behavior |
| Session property | `fn-nntp-listgroup-unknown-preserves-session`, alongside fixed expected transcripts and socket coverage |
| Independent client | CAPABILITIES, both configured GROUPs, STAT, ARTICLE, BODY, LISTGROUP, LIST, QUIT against CLI-persisted/recovered bytes |

The LISTGROUP probe verifies that a range excluding every article still selects
the group's first article, and that a subsequent no-argument listing returns the
current group's numbers. `nntplib` has no public LISTGROUP helper; the probe uses
its generic multiline command parser for response/framing independence.

The article theorem is proved by scanner partition and parser reconstruction
induction. It is stronger than a constructor identity or a few byte examples.
It establishes preservation, not that every valid RFC article is accepted or
every successful result satisfies the complete RFC article grammar.

## Remaining boundaries

- The syntax parser does not implement required-field semantics, full field
  grammars, article injection, provenance, signatures, MIME validation, or POST.
  Its general output-recognizer theorem and work/allocation bounds remain open.
- Release authorization and committed evidence are inputs to the abstract
  retention ledger. These theorems do not validate signatures or implement
  durable node-level release/deletion. Charges remain abstract units.
- LISTGROUP coverage does not complete the RFC READER bundle or prove general
  session refinement. The reader still advertises only VERSION/IMPLEMENTATION,
  serves a locked snapshot, and accepts no network posts.
- The physical store/journal correspondence, qualified power-loss behavior,
  raw-execution guard verification, native signing format, and deployment
  guarantees remain open as described in the storage evidence.
- This batch adds the installed `std/lists/rev` community book dependency.
  Local source auditing does not audit the complete installed system-book
  closure. No proof-skipping, added axioms, or trust tags establish these results.
- Wildmat and later work are outside this historical source set. New files
  created concurrently after the selected batch began do not expand its scope.

No broad milestone or proof target is closed by this component checkpoint.
