## (d) in detail: the overlay

`tools/hbox_native.sh --image-set SHA --overlay REV MODULE...` (docs/testing.md
"Overlay").  `tools/native_overlay.py plan` diffs every file the images load,
form by form, and refuses by name what a definition swap cannot carry; `build`
restarts the published core into ACL2's loop, admits ACL2 forms by
redefinition (re-proving unchanged theorems that name a changed function),
loads raw forms, checks raw-dispatch targets, traps and `:raw-with`
declarations, and save-execs a derived core.

| case | run | result |
|---|---|---|

| cold-start fix 7303e8a12 as an overlay | hbox loops-green-owner | 1 failure + 1 error (test_raw_owner_entries_answer_as_the_counterpart, test_two_client_uncertainty_fences_before_later_mutation), 136 s; the image cycle at d5b0b9100 (set-coldstart1) leaves the same two |
| same overlay, reader_clients + state_checkpoint | hbox loops-green-rc | reader_clients 10/10 OK (as set-coldstart1); state_checkpoint 1 failure, see below |
| ACL2 host change (equivalent rewrite of fn-cfg-host-creations-loop) over d5b0b9100 | lat1 t1-owner | admitted by redefinition, fn-cfg-host-creations-loop-is-rev-onto re-proved, core in 14 s, test_native_owner as on the published set |
| ACL2 host change that breaks that theorem | lat1 t2-owner | REFUSED at the re-proof, no core left in build/, status 3 |
| live owner from the overlay core (`native_overlay.py live`) | lat1 | init + owner + REPL socket in 0.35 s; REPL eval in the owner; NNTP greeting, MODE READER, LIST; `fnn-dev-load` of a new definition; clean stop |

Known divergence: an overlay core is behaviourally the base plus the
change, not timing-identical.  test_native_state_checkpoint's
test_a_running_owner_answers_the_request_and_the_offline_verb_is_refused
stops the owner right after an asynchronous compaction request; a no-op
re-save of the published production core loses that race 3 of 3 and the
published core wins it 3 of 3; with a 2 s pause before the stop both pass.
Root cause not pinned (the module's other timings are no slower).  The
test races by construction; a red that depends on timing is confirmed on a
built image.

(284a95ab1 alone was 351-383 s cold: the index took each fresh verdict in
its own transaction; 2654d5c6d batches them.)  lat1's cache is a fresh
single-origin copy with an 8 MB memo, so it shows the floor, not hbox's

roots, over a many-origin cache with a 386 MB memo, went 680 s -> 36-46 s
with the same output.  The hbox acquire itself waits for the next image
set built with these tools (the integrator's).

## What a loop still costs, and the next cuts

- (a') a fresh REPL session is ~7 s of ACL2 include plus ~5 s of Python
  set selection; a session kept live answers in a quarter second.  Keep
  sessions live (`--idle-timeout`).
- (b) the narrow certify's remaining Python is lane_edges' walk of every
  book (~20 s) and the audit's first run per tree.
- (e) check-lane: interface_emit, keystone_emit, green_check, hot_path and
  coverage each read the tree on their own; the ledger read cache is now
  shared, the analyses are not.
- (f) a fresh worktree waits on the laptop cache: warm it from the
  integrator's runs (certificates are toolchain-bound: the laptop's ACL2 is
  bf681d75, the cached pairs for those 15 books were fcedce7e's).
