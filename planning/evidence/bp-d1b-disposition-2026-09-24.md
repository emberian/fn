# Disposition of `implement/bp-d1b` (worktree `build/lanes/bp-d1b`)

Read-only comparison of branch `implement/bp-d1b` at `846b5d13` (clean
worktree) against `dev` at `03948c39`/`904257d9`. There are no BP source
changes between those two dev commits. Merge base: `66bf9e55` (2026-09-23
15:06). No ACL2, farm or native run was made. Nothing was applied.

**The branch has 34 commits, not 15.** Sixteen commits from 15:14 to 16:34 are
the A3 application-delivery series. Eighteen commits from 17:13 to 19:31 are
the fragment-family and D1b deletion-report series. `git cherry` reports 32 of
the 34 as `+`. That is because `dev` has a linear history and the
ledger/proofs/manifest files differ between the two lines. The code is on
dev.

## Method

1. For each branch commit, I looked for a dev commit with the same subject.
   Then I compared the two patches line by line, excluding
   `planning/ledger.*`, `proof-events.json`, `proofs.json`,
   `requirements.json` and `planning/evidence/manifests`.
2. For the A3 series, which has no same-subject twins, I compared the trees
   of the branch checkpoints with the dev integration commits, limited to BP
   books, host, tests and spec.
3. I extracted every `defun`/`defthm`/`defconst`/... name that the branch
   diff (`dev...implement/bp-d1b`) adds under `books/`, `host/` and
   `tests/acl2/`, 372 names in all, and ran `git grep` for each one on dev.
4. For every file the branch touches, I compared the tip bytes with dev and
   noted which side the extra lines are on.
5. For every book the branch adds, I checked which of its functions dev's host
   calls through `fnn-core '<name>`, and which dev books call the rest.

Results. Every file the branch adds or changes exists on dev. 58 of the
non-ledger files are byte-identical at the branch tip and on dev. Where a file
differs, dev has more lines (for example `bp-fnbs-family-codec` has 1 line
only on the branch and 86 only on dev; `bp-node-fragment-guards` has 9 and
63). 371 of the 372 new definition names exist on dev. The exception,
`fn-bpah-select-oldest-at-not-expired`, was replaced on dev by
`fn-bpah-select-oldest-at-is-live` in `cff71dd3`.

## Books and tests the branch adds

The branch adds 23 books, all present on dev: `bp-app-handoff`,
`bp-app-handoff-time`, `bp-clock-domain`, `bp-fnbs-{deletion,delivery,family}-{codec,publication}`,
`bp-fnbs-{delivery,family}-replay`, `bp-fnbs-inspect`, `bp-handoff-status`,
`bp-node-fragment-{guards,plan,replacement,step}`, `bp-node-report-step`,
`bp-report-{author,deletion,guards,observe,outbox}`. It adds 20 ACL2 test books
and 3 native test files, all present on dev.

None of the branch's added books or tests is missing from dev. On dev, the
theorem subjects are host-called in one of two ways:

- **Called directly by dev's host:** the publication authorizers (delivery,
  family, deletion), the clock-domain planner, `fn-bpnf-inspect-*`,
  `fn-bpah-outbox-effective-status`, `fn-bpah-outbox-view-after`,
  `fn-bpnf-family-next`, `fn-bpn-report-outbox-next` and
  `fn-bpn-report-observe-next`.
- **Called under `fn-bpnp-step`** (`books/bp-node-progress.lisp`, host
  `bp-service.lisp:172`): the tombstone kernel, the report proposal and persist
  steps, the held-expiry decision, and the family plan and apply. Their
  guard/premise books on dev are `bp-node-progress-{guards,premises}`.

The assurance-rule question for these (AGENTS.md, "the theorem subject is the
function the host calls") therefore belongs to dev's progress machine. It does
not depend on anything on this branch.

## What dev lacks for P11 from this branch

Nothing. Every P11-relevant piece of the branch is on dev. On dev, the sender
obligation is discharged only by the application receipt: `bp-handoff-status`,
`fn-bpah-outbox-effective-status` at `bp-node.lisp:298,328`, and the
`cfg`-bound `fn-bpah-receipt-trustedp`. Delivery goes through the node machine
(`fn-bpnp-step`). The remaining D1b and P11 gaps on dev are recorded in
`specs/bp-node-machine.md` (D1b paragraph near line 2428): a source-matched
native image, the death-after-kind-10 native test, and broader policy
qualification. The branch holds none of these either: its native test file
differs from dev's only by 6 older signature lines.

Parts of the branch must not be applied because dev replaced them with a
different design (class b):

- Receipt trust over a `configured-peer` string (`7ad230b5`), replaced by
  channel-profile session admission (`76567b87`).
- Direct host calls to `fn-bpah-pending-decision-at`,
  `fn-bpn-report-author-step` and `fn-bpnf-host-eventp` (`d6e9fa17`,
  `9bd0d454`). Dev routes these through `fn-bpnp-step`/`fn-bpnp-host-eventp`
  (`ee11a335`). Restoring the direct calls would bypass the progress machine
  that P11's "only through the node machine" clause depends on.

- The two stale ledger refreshes (`8fb2f09e`, `760f4929`).
