## What changed

- **Record kind 19** (`books/bp-node-rotation-codec.lisp`): the checkpoint
  `(:bpnr-checkpoint generation held handoffs prior next-arrival covered)` is
  the exact accumulator of the ordered received-FNBS replay plus the
  generation and the credit it retires. File: `FNBR`, version 1, kind 19, u64
  payload length, a depth-bounded tree codec payload, and the 32-octet frame
  trailer (`fn-frame-trailer`). The decode budget
  (`fn-bpnr-depth-budget`) and the read bound (`fn-bpnr-read-bound`) are
  functions of the profile's `max-jobs`/`max-octets`: work bounds, no data
  constant (D27). Outcomes are not in the checkpoint: recovery already clears
  them (not a durable kind), so the checkpoint holds what replay produces.
- **Generation namespace**: generation 0 is `lifecycle/`; generation g > 0 is
  `lifecycle-g<20 digits>/`. The selection file `bp-generation.fnb` names the
  generation through its checkpoint. `fn-bpnr-next-generation` never reuses a
  number (greater than the selected one and every directory observed).
- **Transition** (`books/bp-node-progress.lisp`, `fn-bpnp-step`):
  `(:rotate g ck)` → `fn-bpnp-rotate-step` proposes
  `(:persist-checkpoint epoch 0 g)` only from a quiescent recovered state (no
  operation since recovery, nothing issued, no legacy outbound record) and
  only when `ck` is the state's own projection (held rows, handoffs, arrival
  frontier, credit, an operation frontier from an earlier epoch) whose file
  fits the read bound; `(:persist-result e op r)` on an issued `:checkpoint`
  → `fn-bpnp-rotation-persist-step`: `:durable` sets the record count to 0
  and answers `(:generation-selected g)`; `:refused` changes nothing;
  anything else is uncertain and fences until recovery.
- **Verb** `bp-node checkpoint JOURNAL NODE-ID [WALL WALL-ERROR]`
  (`host/native/bp-node.lisp fnn-command-bp-node-checkpoint`). The
  publication program `fnn-bps-publish-generation`
  (`host/native/bp-service.lisp`) follows ACL2's phase driver
  `fn-bpnr-publish-action/-step/-outcome`: the new generation directory with
  its and the root's barriers, then the Store marker program's three steps
  (stage + file barrier, rename over `bp-generation.fnb`, root barrier). The
  Store's own ACL2 driver `fn-cpp-marker-driver-*` is not in the DTN image's
  closure, so the BP driver is a twin with the same phases and outcomes,
  plus the directory step; K0's byte-store model is not instantiated for it.
- **Open at recovery** (`fnn-bps-open`): `fnn-bps-selection-plan` reads the
  selection file under the profile's read bound, `fn-bpnr-selection-plan`
  answers `(:none)`, `(:selected ck)` or `(:damaged)`, the lifecycle
  directory is the plan's (`fn-bpnr-plan-directory`), and the recovery event
  is `fn-bpnr-recover-auto-event` (was `fn-bpnf-family-recover-auto-event`;
  equal on `(:none)`, theorem below). A damaged selection faults the replay
  (`:generation-authority`), so recovery fences. The clock-domain gate now
  takes `fn-bpnr-clock-domain-evidence`: a selected or damaged checkpoint is
  retained evidence, so N07's fresh-domain branch still means nothing
  retained.

## Theorems

- `fn-bpnr-dec-of-enc`, `fn-bpnr-checkpoint-decode-of-octets`: every file
  `fn-bpnr-checkpoint-octets` writes decodes to exactly its checkpoint.
- `fn-bpnr-family-replay-aux-append` (`books/bp-fnbs-replay-append.lisp`):
  replaying `prefix ++ suffix` is replaying `prefix` and then `suffix` from
  its accumulator (or the prefix's fault).
- `fn-bpnr-replay-from-checkpoint-chains`: replay from the checkpoint of a
  ready replay equals replay of the concatenated rows from the older
  authority.
- `fn-bpnr-recover-without-checkpoint-is-family-recover`: on `(:none)` the
  host's new event function is the old one.
- **Keystone** `fn-bpnr-recover-from-checkpoint-equals-full-recover`: for any
  non-damaged authority `plan0` whose rows' replay is ready, and the
  checkpoint `ck1` of that replay at any generation whose octets exist,
  `fn-bpnr-recover-auto-event` on `(fn-bpnr-selection-plan t octets budget)`
  and any later rows equals the event over `plan0` and the concatenated rows
  with field 5 (the row count) set to the later rows' count. Host line:
  `fnn-bps-open`, `(fnn-core 'fn-bpnr-recover-auto-event ...)`.
- **Crash keystone** `fn-bpnr-rotation-crash-recovers-old-or-new`: for every
  phase of the publication driver and every old/new choice of an atomic
  rename, the visible selection is the old or the new file; before the rename
  may have been issued it is the old one; under the old one the plan is the
  old plan; under the new one recovery with no rows equals the old
  authority's recovery with its row count 0. Premise not modelled: the new
  generation's directory holds no record at any cut (the verb admits nothing).
- `fn-bpnp-rotate-step-proposes-only-own-projection`: a proposal implies
  `fn-bpnr-checkpoint-of-statep`, quiescence, and existing octets.

Teeth (`tests/acl2/bp-node-counterexamples-tests.lisp`, N16 section): the
positive trace through `fn-bpnp-step` (recover with A, rotate, durable reset
to 0, reopen from the checkpoint equals the event with count 0, new work gets
arrival 1 and a later epoch, a stale completion of the rotating epoch is
inert); must-fails for a non-quiescent state, refused projections (no held
row, wrong credit), refused/uncertain/stale answers leaving the count, and
one per hypothesis of the recovery keystone (damaged plan0, octets absent,
unready prefix) and of the crash keystone (no new file before the rename).

## Continuation (second agent, 2026-09-25)

- **Bridge**: the four rotation effects are the node's own publication
  effects, neither `:release` nor `:receipt-prepare`, so they are inside
  the confined set by `fn-bpnpb-effects-confinedp`'s definition; the red
  was two missing quiet lemmas, `bpnpb-rotate-step` and
  `bpnpb-rotation-persist-step`, now in `bpnpb-step-confined-lemma`'s
  theory. Keystone `fn-bpnp-step-emits-no-release-and-no-receipt-prepare`
  unchanged.
- **Subject** (`books/bp-node-rotation-step.lisp`, 5.1 s):
  `fn-bpnp-step-rotate-is-rotate-step` (for every state: the step on
  `(:rotate g ck)` is `fn-bpnp-rotate-step` unless the issued operation is
  uncertain, where it answers nothing), 
  `fn-bpnp-step-rotation-result-is-rotation-result` (while the issued
  operation is a checkpoint, the step on `(:persist-result e op r)` is
  `fn-bpnp-rotation-persist-step`), and
  `fn-bpnp-step-rotation-resets-credit-only-on-durable` (over a true-list
  state with a checkpoint issued, the record count after the answer is 0
  exactly when the checkpoint is pending, `(e op)` matches and `r` is
  `:durable`, and unchanged otherwise). Prover steps in an hbox session:
  89, 219, 1260. Each opens only `fn-bpnp-step`'s dispatch.
- **Teeth that evaluate**: the N16 section had never run: ACL2 ignores
  attachments inside `defconst`, and the checkpoint file's trailer calls
  the attached digest, so `*bpcx-n16-octets*` could not be admitted. Every
  value that writes, reads or proposes a checkpoint is now a zero-argument
  function. Added: witnesses that the trace is the rotation arms' answer;
  the uncertainty fence (the step answers nothing where the arm refuses
  aloud); a must-fail without the `:checkpoint` hypothesis (a receipt's
  persist, which the step completes); a must-fail without `true-listp`
  (an improper tail refuses the reset). All eight N16 must-fails were
  evaluated one by one and return NIL (not an evaluation error).
- **Finding N16-F1 (open)**: the checkpoint's operation frontier is the
  replay's, from before the rotation, and the publication's own id
  `(e 0)` enters no durable record, so a reopened node's epoch is
  1 + max(initial, prior) = the rotating epoch and its first operation is
  the rotation's id. The trace now asserts this instead of the claim it
  made ("a later epoch; a stale completion matches nothing"), which was
  false. Not a host input (the verb answers the publication synchronously
  and exits) but spec §11.1's N16 row says "no identifier reuse". Repair:
  the checkpoint's `prior` is the rotation operation's id and the
  recovery keystone is restated with the event's epoch field.
- **Two host defects the native run found** (both invisible to the
  theorems):
  1. Neither image loaded `books/bp-node-rotation`
     (`host/native/build.lisp`, `build-dtn.lisp`), so every `fnn-bps-open`
     faulted with "ACL2 executable counterpart missing:
     FN-BPNR-SELECTION-PLAN": 23 of 23 native BP node tests red on the
     first image of this branch. Both build files now include it.
  2. `fnn-bps-open` passed the *namespace* plan (bound by
     `multiple-value-bind` a few lines above) to
     `fn-bpnr-recover-auto-event` instead of the generation selection
     plan, so a reopen after a completed rotation replayed the empty new
     generation without its checkpoint: held=0. The keystone's host line
     named the right function with the wrong argument. It now passes
     `(fnn-bps-plan service)`.
  Also: `FN_BP_ROTATION_TEST_STOP` was not a registered developer
  selector (`host/native/io.lisp`), so every cut faulted (exit 4); the
  test now reports the process's stderr when a cut marker is missing.
- **D27 note**: `*fn-bpnf-received-max-records*` (8,192) was a cap on the
  data one journal holds; with rotation it bounds the work of one
  generation's replay, which is D27's permitted kind, and it says so in
  `books/bp-node-rotation.lisp`.

## Open

- Finding N16-F1 (above): identifier reuse of the rotation's operation id
  after reopen.
- Filling a journal past 8,192 received finals natively, with a rotation
  in between: not run. The machine holds at most 64 jobs, so a fill needs
  8,193 delivered (not held) receptions, each a separate `tcpcl send`
  process and an A3 delivery; at the 20 to 30 s this module's tests spend
  per few receptions that is hours, not a lane step. It needs a
  multi-bundle sender or a profile-set record limit.
- The empty new-generation premise of the crash keystone is not modelled
  (the verb admits nothing while it runs).
- Spec §3.6's four-authority table, kinds 19 chunks plus kind-20 manifest,
  the `:quiesce` event and obligations 3 to 6 are not implemented; this
  lane uses one atomically renamed file (the rename is the selection) and
  an offline verb in place of in-service quiescing.
- Housekeeping of old generation directories is not implemented (they are
  kept as evidence), nor is removal of a killed rotation's stray staged
  selection file (`.bp-generation-<pid>-<hex>`), which the next open does
  not read.
- Octet lists on the codec path (D27 concrete twin not provided).
