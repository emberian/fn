# Effective BP receipt handoff projection

The A3 kind-7 replay leaves the handoff row `:owed`. `books/bp-handoff-status.lisp` derives an effective `(:handed-off sequence)` only from that exact `(receipt-id, held-key)` row, a receipt ADU supplied by recovered FNRJ, and a durable base FNBS job at the trigger-specific key with the same peer and payload. An absent job, a contradictory payload or peer, an invalid view, or a different arrival trigger cannot end the handoff. The return bundle's transport ACK is not used.

The keystone `fn-bpah-host-outbox-status-binds-fnrj-and-carrier` is about the projected API `fn-bpah-outbox-effective-status(st, view, receipt-adu, peer)`. Its explicit FNRJ premise is that `receipt-adu` equals `fn-bpr-receipt-adu` of the recovered receiver state for this request; the model does not infer physical FNRJ durability from a Lisp byte vector. Branch and job-match lemmas keep the BP ADU decoder and job recognizer closed in the composition proof. `tests/acl2/bp-handoff-status-tests.lisp` builds a committed FNRJ receipt and kind-5/kind-7 byte replay, verifies live and restarted projections, wrong-payload/peer/missing-job negatives, and two arrivals with one receipt ID and different return-job keys. It has must-fail missing-job, wrong-ADU, and wrong-peer cases.
