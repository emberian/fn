# Current-source preservation and clone packet

The preservation packet was ported from its finite E2 branch onto coherent integrated Store commit `632653a86e21b30efbd1dca54d9e78d9828b7640`. That base already has the E2 durable publisher (`fnn-owner-consumer-commit`) and the T10 exact-source accepted-event/verdict projection. The port keeps both the newer local consumer control functions and the checkpoint clone-phase/bootstrap helpers in `host/owner-host.lisp`; generated ledger conflicts were resolved by regeneration. Its six commits are `e0e98e41`, `6a822ae1`, `3b4c0e00`, `1215d96a`, `8638d087`, and `90e3f2a7`.

`fn-cpa-store-auxiliary-agrees` compares the recovered live consumer projection, dense identity sequence, historical verdicts and enrolled keyring snapshots against exact completed Store history before a selected checkpoint can report differential equality. The node summary alone is not treated as complete state. A cold writable clone copies exact selected-pack bytes while the source Store is locked, publishes a durable fence before the copied directory, and uses an ACL2-constructed consumer rollover event before serving. A refused or uncertain rollover keeps the destination fenced. Recovery after the publisher closes independently checks the event in the authoritative journal before removing the fence. The source-owned copy depth, entry and byte limits are enforced by the host while walking files; the host filesystem and fsync calls remain the physical trust boundary.
