## What the node says

```
200 fn-nntp experimental server ready
101 capability list follows
  VERSION 2 / READER / POST / OVER MSGID / HDR
  LIST ACTIVE ACTIVE.TIMES HEADERS NEWSGROUPS OVERVIEW.FMT
  IMPLEMENTATION fn-nntp-lab
```

`LIST ACTIVE` is `name high low y`, `GROUP` is `211 count low high name`,
`HELP` is a real multi-line block, `MODE READER` is `200 posting allowed`,
`NEWNEWS` is `500 command not recognized`, `QUIT` is `205 closing connection`.
`LIST ACTIVE fn.*`, `LIST NEWSGROUPS`, `LIST OVERVIEW.FMT` and `LISTGROUP` all
answer. The client reads `LIST ACTIVE`, `GROUP`, `OVER` and `ARTICLE`, and the
field orders it assumes are the ones the node uses: with seventeen articles in
`fn.letters` the node sent `211 17 1 17 fn.letters` and the client reported
first 1, last 17.

## The client defects this found, and the fix for each

Each has a test in `tests/test_fn_client.py` (or `tests/test_node_probe.py`)
that fails on the old code against the fake.

1. **A node that accepts and then closes came out as a traceback on exit 1.**
   `Session.__init__` reads the greeting, so a forwarder in front of a stopped
   owner — exactly the `ssh -L` shape docs/operator.md prescribes — raises
   `Disconnected`, which is a `RuntimeError` and not the `OSError` that
   `Client.open` caught. Witnessed twice for real: the owner died under a large
   POST (below) and the next `groups` printed a Python traceback and exited 1,
   which an agent reads as *the node refused*. `tools/node_probe.py` had the
   same gap at the same seam, and its exit is a deploy gate. Both now catch
   `Disconnected` at connect; verified against the stopped owner through the
   live tunnel, `uncertain could not connect to 127.0.0.1:11340: the node
   closed the connection`, exit 3, and the probe `exit 3` with every step
   undecided. `Session` also closes the socket it opened when the greeting
   fails, instead of leaking the descriptor.
   Fake: `drop_before_greeting`, which is not the `ECONNREFUSED` the previous
   "not listening" case produced.

2. **A node named by its IPv6 address could not be reached.** `--node` was
   split on the last colon, so `[::1]:11340` became the host `[::1]` and
   `::1` became the host `::` at port 1. The tunnel really does listen on
   `::1`, and `[listener] host` admits `::1` (docs/operator.md), so the client
   reported a serving node unreachable — on exit 3, which tells an agent to
   retry forever. `--node` now takes `HOST`, `HOST:PORT`, `[HOST]` and
   `[HOST]:PORT` the way RFC 3986 section 3.2.2 writes them, a bare token with
   more than one colon is the whole address, and the node is written back with
   its brackets. Verified: `--node '[::1]:11340'` through the tunnel served the
   group list, and `--node '::1'` now reaches `[::1]:1119`.
   Fake: a `host` argument, so a test can name a node at `::1`.

3. **A watermark that could not be saved crashed the client on exit 1.** The
   articles had already been printed and the node had already answered; only
   this side's note of how far it got failed, and it arrived as an
   uncaught `PermissionError` under the refused exit code. The commit is now
   guarded: the node's word and exit code stand, and one further line on
   standard error says the watermark was not saved and that the next read will
   offer these articles again. That is the repeat the page already promises
   over a miss, said out loud rather than by surprise.

4. **A negative `--since` was sent to the node.** `--since -1` put `OVER 0-17`
   and then `ARTICLE 0` on the wire; the node answered `501 syntax error`
   twice and a client-side mistake came back wearing the node's refusal on
   exit 1. RFC 3977 section 6 starts article numbers at 1, so this is now a
   usage error (exit 2) that never opens a connection. `--node` also rejects a
   port outside 1..65535 rather than connecting to it.

## What the node did that the client was right about

- **It would have taken the password in the clear.** Run without `--plain`,
  against `--cafile`, the client found no `STARTTLS` in `CAPABILITIES`, asked
  `AUTHINFO USER yue`, and the image answered **`381 password required`** —
  although it advertises no `AUTHINFO` capability and answers `580 can not
  initiate TLS negotiation` to `STARTTLS`. The client stopped there, exit 1,
  `the node answered 381 password required to AUTHINFO USER before TLS: it
  would take the password in the clear, and none was sent`, and no `AUTHINFO
  PASS` reached the socket. This is the single property docs/agents.md exists
  to state, and it is now witnessed against a node that really would have
  accepted the secret.
- **A non-ASCII Subject is refused.** `441 posting failed; the article is not
  valid syntax` (`books/nntp-post.lisp`), on exit 1. A non-ASCII *body* is
  accepted and round-trips exactly. The client reports the node's line and
  does not pre-judge the article: deciding what an article may carry belongs
  to ACL2 and not to a second check in Python. docs/agents.md now says so, and
  the fake can send that 441 line so a test can hold the client to reporting a
  reason it had never seen as a refusal and never as uncertain.
- **An uncertain post is real, and `show` settles it.** The oversize post
  below cut the connection with the article text already sent. The client
  reported `uncertain ... the article may or may not be durable; do not repost
  it. Message-ID <...> -- settle it with fn_client.py show <...>` on exit 3;
  `show` on the restarted node answered `430 no article with that message-id`
  on exit 1, so the article was not durable and the post may be retried. The
  procedure on that page is the procedure that works.

## What the node did that is the node's, not the client's

Neither was touched here; this lane changed no book and no host code.

1. **A POST larger than about 32 KiB stops the owner process.** The log says
   `owner core/store fault; process stopped: plaintext owner read left a
   suffix without TLS` and then `fault operator run`; the process exits and
   the listener goes away. Bracketed by bisection on the plaintext path:

   | article octets | outcome |
   | --- | --- |
   | ~32 250 (450 body lines of 70) | `240 article received OK` |
   | ~33 031 (461 lines) | owner dead, connection cut |
   | ~33 670 (470 lines) | owner dead |
   | ~42 900 (600 lines) | owner dead |
   | ~2 130 000 | owner dead, `Connection reset by peer` mid-send |

   32 768 octets of retained input sits inside that bracket. Any client that
   posts a moderately long article takes the node down with it, and the
   article is not stored. Five owner restarts in this session were this.

2. **Every article accepted during one owner run carries the same `Date` and
   `Injection-Date`.** Articles 13 to 16 of `fn.letters`, posted ten seconds
   apart, all read `Tue, 22 Sep 2026 13:40:13 +0000`; article 17, after a
   restart, reads `13:41:32`. `DATE` returns the same value all run. The
   freshness reading is taken once at owner start and not advanced.

3. **The listener's backlog is 1** (`LISTEN 0 1` in `ss -ltn`).

## What remains untested

- **STARTTLS and AUTHINFO.** The 915 image has neither, so `--cafile`, the
  handshake against the node's own certificate, `AUTHINFO USER`/`PASS` after
  the layer, `281`, `481`, `483` and `480` have still only ever been exercised
  against `tests/fake_node.py`. The only thing this record adds is the
  refusal above: this node would have taken the password in the clear and did
  not get it. Everything else about the protected channel waits for an image
  that has one; `dev` has the books and no qualified image carries them yet.
- **`--credentials`**, for the same reason: `--plain` refuses it.
- **Concurrency.** One client at a time, one connection at a time. Nothing
  here says what two readers and a poster do to this node.
- **Article gaps.** No number was removed from a group, so the `423`/`430`
  hole path inside a read and the `OVER` short block were not reached on a
  real node.
- **Crash and recovery.** The owner died five times under finding 1 and was
  restarted, but no recovery claim is made here and no store was inspected
  afterwards beyond reading it back.
- **A newsreader.** `nntplib` is the only independent client that ran.
- **Anything about proofs.** This is a client exercise. No book was certified,
  no theorem was proved, and the image's own qualification is not re-established
  by anything above.
