## 1. N16-F1 (PKT-057), commit 6591fb74

The machine used to publish the projection checkpoint, whose operation frontier
is the replay's. A reopen then took the rotating epoch E, and its first
operation reused the rotation's id (E 0).

**Change**:
- `fn-bpnr-rotation-checkpoint ck epoch` (books/bp-node-progress.lisp) is the
  projection with frontier `(epoch . 0)`.
- `fn-bpnp-rotate-step` admits the same projection as before. It checks the
  read bound on the published bytes and proposes
  `(:persist-checkpoint E 0 G RCK)`.
- host/native/bp-service.lisp `fnn-bps-publish-generation` writes the
  effect's RCK; it no longer recomputes the checkpoint from the recovery event.

**Keystone** `fn-bpnr-recover-from-checkpoint-equals-full-recover` (restated;
books/bp-node-rotation.lisp). The hypotheses:
- plan0 is not damaged;
- rows0 replay `:ready` from plan0;
- ck1 is the projection of that replay and is a checkpoint;
- E is field 1 of `fn-bpnr-recover-auto-event` over plan0 and rows0;
- the file of `(fn-bpnr-rotation-checkpoint ck1 E)` exists;
- the later rows start after `(E . 0)`.

The conclusion:
- with no later rows, the reopen event is
  `(:recover-fnbs E+1 br sr (update-nth 3 (E . 0) replay) 0)`, so no
  operation after the reopen is the rotation's;
- with later rows, it equals the event over plan0 and `rows0 ++ suffix` with
  field 5 set to `(len suffix)`.

Host line: `fnn-bps-open` passes `(fnn-bps-plan service)` to
`fn-bpnr-recover-auto-event`.

The old statement over the projection is kept as the lemma
`fn-bpnr-recover-from-projection-equals-full-recover`. Two other theorems are
restated for the published file:
- `fn-bpnr-rotation-crash-recovers-old-or-new`: under the new file, recovery
  is the reopen event above.
- `fn-bpnp-rotate-step-proposes-only-own-projection`: the effect's fifth
  field is `fn-bpnr-rotation-checkpoint` of the own projection.

Keystone proof: every step is in minimal theory. The keystone itself proves in
0.03 s; the book's prover time is under 1 s.

**Teeth** (tests/acl2/bp-node-counterexamples-tests, N16 section):
- The trace effect carries RCK. The reopen is epoch 3 with frontier (2 . 0)
  and count 0. New work is at (3 0). A stale `(:persist-result 2 0 :durable)`
  is inert.
- The finding's witness: publishing the projection reopens at 2, and the stale
  completion completes new work. There is a must-fail for this.
- The keystone witness over real kind-5 rows (the publisher's name and frame):
  - row A at (1 . 0);
  - row B at (3 . 0), where equality holds;
  - one must-fail per hypothesis:
    - row B2 at the rotation's own id (2 . 0), which full recovery takes and
      the checkpoint refuses;
    - a damaged plan0;
    - absent octets (budget 2);
    - an unready prefix.
- The `fn-bpnr-checkpointp ck1` hypothesis has no tooth, and this is stated in
  the book. The only field of ck1 that the published file does not already
  constrain is the frontier. The frontier is a pair of decoded u64s for every
  row the codec decodes, so no reachable replay separates the hypothesis. The
  chaining lemma needs it.

## 2. Retirement of old generations (PKT-059), commit 0cceac9c (+ f2f22319)

books/bp-node-retire.lisp:

- `fn-bpnr-retired-names`, after the selection of G > 0, returns:
  - every generation directory below G ("lifecycle" is generation 0);
  - every `.bp-generation-*` stage.
  The selected directory and the selection file are excluded by definition
  (`fn-bpnr-retired-names-never-the-selected-directory`).
- `fn-bpnr-retire-ops` plans the removal: per retired directory its listed
  files, then the directory; a root file is unlinked; one barrier ends it.

**Keystone** `fn-bpnr-retirement-cut-keeps-open-view`. The model is a root
alist (name → file or dir). Hypotheses:
- the selection file selects G;
- no other name the open reads is retired.

Conclusion: for every K, `fn-bpnr-open-view` after `(take K ops)` equals the
view before. The view is the selection plan, the selected directory's entry
and the other names. So every step of the program is a model crash point, and
a partial removal changes no recovery.

Host: `fnn-bps-retire-generations` runs ACL2's ops one at a time. Each step
has a developer cut `retire-K` under `FN_BP_ROTATION_TEST_STOP`. It runs:
- after `:generation-selected`;
- at the start of `bp-node checkpoint` for the current selection, which
  finishes a killed run.

Both build files include the book.

**Teeth** (tests/acl2/bp-node-retire-tests):
- The witness is a seven-name root with a real checkpoint file. It checks the
  exact op list, the remaining names, a half-emptied "lifecycle" after step 1,
  and every cut 0..9, including cuts past the end.
- One must-fail per hypothesis:
  - the program run for 3 while the file selects 2;
  - an open that reads "lifecycle".
- Each must-fail's inner form was evaluated to NIL (not an error).

Native: `test_rotation_killed_at_each_cut_keeps_held_rows` is extended:
- stray stage present after the kills;
- kill at `retire-2`, then held=1;
- a clean rotation to g4 logs `retired name=lifecycle`; only g4 remains; no
  stage remains;
- a second rotation leaves only g5.
