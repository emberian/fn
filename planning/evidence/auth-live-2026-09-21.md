# AUTHINFO on a running node: the one variable that decided it

The v0 matrix at `c3b99f8` found three things together on both of its nodes
([the matrix](v0-matrix-2026-09-21.md), rows `V0-AUTH-ADVERTISED`,
`V0-AUTH-LOGIN`, `V0-AUTH-GATED`): the credential `fn principal set-password`
had just written was rejected with `481`, `AUTHINFO` was absent from
`CAPABILITIES`, and `POST` before any login answered `340`. This file is the
measurement that found the cause, one variable at a time, and the same
measurement after the repair. Nothing here is inferred from reading the books.

## What ran

| fact | value |
| --- | --- |
| host | this laptop, `macOS-26.6.1-arm64` |
| python3 | 3.14.7 |
| ACL2 | 8.7 |
| tree | `w11/auth-live`, worktree `build/lanes/w11-auth-live` |
| before-revision | `4732ace` (dev) |
| after-revision | `cf7ef71` |
| driver | one script, three runs; it inits a store with `bin/fn init`, writes a credential with `bin/fn principal set-password`, optionally writes ONE peer record, starts the service with `bin/fn run` over that `fn.toml`, and drives a raw socket |
| secrets | the store is a fresh temporary directory, removed with the run; `matrix-secret-8f21` authenticates nothing |

The server is started the way an operator starts it — `python3 bin/fn --config
<dir>/fn.toml run` — and not `tools/run_owner.py`, because the difference
between them is where the defect lived.

## The cause

`tools/run_owner.py:576` asks ACL2 to resolve the connection's SOURCE ADDRESS
to a configured peer, and `host/owner-host.lisp fn-owner-peer-name-for`
matches the address and nothing else. The record above names `127.0.0.1`, so
every loopback client is peer `b`, and the owner opens it with
`fn-own-open-peer` rather than `fn-own-open`.

`books/served.lisp:890`, before this lane:

    (defun fn-served-open-peer (archive line-limit body-limit config observation
                                        injection peer node cfg)
      ...
       (fn-auth-open-session archive peer node cfg
                             (fn-auth-open-config) nil)   ; <- a literal

`(fn-auth-open-config)` is `(fn-auth-make-config nil nil nil nil)`: no
credential, no `required` bit, no certificate. So on such a box the operator's
whole AUTHINFO configuration reached no connection at all. Everything else was
correct — the CLI wrote a well-formed verifier, `bin/fn run` passed
`--auth-file`, `load_credentials` read it, `fn-owner-set-auth` accepted it,
and `books/nntp-auth` would have honoured it. It was pinned into readers and
there were no readers.

## Run 3: after the repair, with the peer record AND a policy

`fn-served-open-peer`, `fn-own-open-peer` and `fn-owner-open-peer` take and
pass the operator's `acfg`. The configuration adds `[auth] required = true`
(`fn init --auth-required`, also new). Everything else is run 2.

and the operator log now names the role it gave the connection:

    accepted peer connection=0 peer=b

Read the greeting: `201`, not `200`. Under a policy that requires a login an
unauthenticated connection may not post, and RFC 3977 §5.1.2 says the code is
`201` there. It was `200` before this lane, because `fn-served-greeting` read
the injection configuration alone — so the greeting promised what `POST`
refused. That is fixed in the same commit and
`fn-served-open-greeting-agrees-with-the-post-label` is the statement of it.

## What this establishes, and what it does not

It establishes that on this laptop, at `cf7ef71`, a client logs in with a
credential the operator set minutes earlier on a node started the ordinary
way, that `POST` is refused before that login and permitted after it, and that
`CAPABILITIES` carries `AUTHINFO USER` and then does not.

It does not establish anything about the strength of the digest (A-CRYPTO),
about the secret on the wire — which is cleartext, and is why `[auth]
protected_only` and a certificate exist — or about any client other than the
socket driver above and `tests/test_auth.py`. The independent-client
observation is the v0 matrix's `V0-CLIENT-NNTPLIB` row, which now performs the
login through the Python standard library's own `nntplib` on persvati.
