The three that did not finish are the NNTP reader's, not the convergence
layer's. Each exceeded the runner's `FN_ACL2_TIMEOUT_SECONDS=1800` cap and was
retried, on a box running five other lanes' certifications at the same time
(`w5-owner-followups`, `w6-tcpcl-c4`, `w6-workflow-restart`, the
`dev-6ac2278` gate, and a second tcpcl run); one unrelated ACL2 process on the
box was 2802 s old while mine were 1243 s into their second attempt. Nothing
about the layer caused it and nothing about it is diagnostic of the layer.

**Why this stops the image.** An ACL2 certificate records absolute
full-book-names, so a certificate set is not relocatable and may not be mixed:
installing certificates for the same book from two directories makes ACL2
include that book *from the directory its certificate names*, and
`tools/build_native_host.sh` refuses the image on the resulting `Uncertified`
warning. A first attempt here installed 217 certificates scavenged from every
gate and lane whose book text matched, and the build refused with exactly that
error (`its certificate requires
/home/ember/fn-gates/dev-056b29b/books/acceptance.lisp, but ...
/home/ember/fn-gates/dev-498b766/books/acceptance.lisp ... has been
included`). No single existing directory holds the whole closure: the best,
`~/fn-gates/dev-6ac2278`, matches 57 of 63 and has no tcpcl book at all, and
the only directories holding a matching `tcpcl-session.cert`
(`~/fn-lanes/w6-tcpcl-c2`, `~/fn-lanes/w6-tcpcl-c4`) match 5 of 63. So the
image needs its own closure certified in its own directory, which is what the
farm run above was for.

## What the five scenarios will assert, and how to run them

Once the three books carry a certificate in
`/home/ember/fn-lanes/w8-tcpcl-native/books/`:

```sh
ssh persvati 'cd /home/ember/fn-lanes/w8-tcpcl-native \
  && FN_ACL2=$HOME/fn-tools/acl2-8.7/saved_acl2 nice -n 10 sh tools/build_native_host.sh \
  && python3 tools/tcpcl_lab.py --image build/fn-host --work /tmp/tcpcl-lab'
```

| scenario | the assertion |
| --- | --- |
| `exchange` | contact, SESS_INIT, one two-segment transfer each way inside one session, SESS_TERM both ways, both spools holding the peer's octets byte for byte, both exit codes 0 |
| `refused` | the listener's transfer MRU below the bundle's length: `fn-tcl-send` answers `:exceeds-transfer-mtu`, no XFER_SEGMENT is written, exit 1, nothing staged |
| `keepalive` | an idle established session: at least two KEEPALIVE each way on the negotiated interval, no SESS_TERM, both sides still up |
| `crash` | `kill -9` of the receiver after three acknowledgements inside a 120 KB transfer: the 900-octet bundle it acknowledged earlier is still in the spool and equal to the source, the interrupted one is absent under any name, no `.incoming-*` partial remains, and a reconnect still completes |
| `replay` | the trace the listener wrote, folded back through `fn-tcl-drive` alone by `tcpcl replay`; the two digest streams must be equal element for element |

Each scenario prints one JSON object and the lab prints a summary; the
`tcpcl` scenario of `tools/twonode_gate.py` turns each object into a gate step
with its own verdict.

## dtn7 interop: not attempted

Neither persvati nor hbox holds a dtn7-rs checkout (`ls -d ~/dtn7*` is empty on
both; only `cargo` is present), and `tests/bp-dtn7/bootstrap.sh` clones and
builds the pinned revision from scratch, which is a Cargo build on a box that
is co-tenant with five certification lanes. It was not started. The command
is

```sh
sh tests/bp-dtn7/bootstrap.sh <empty-dir>     # clones and builds pin.json
```

and the honest expectation is worth writing down before anyone runs it: this
layer carries **opaque octets**, not BPv7 bundles. A dtn7 peer would complete
the contact exchange and SESS_INIT against `fnn-tcl-listen`, and then reject
the transferred content as a malformed bundle, because nothing on this tree
turns a `:bundle-received` into a BPv7 bundle yet. An interop attempt is
worth making at the session layer and is not worth reporting as a bundle
exchange.

## Gaps

- **Nothing here was run against a running image.** The layer is code and
  certified books; it has not moved an octet.
- **The served TCPCL path revalidates the whole session per chunk (D3).**
  `fn-tcl-drive`'s guard is `fn-tcl-sessionp`, and `fn-tcl-inboundp` inside it
  runs `fn-tcl-octet-listsp` and `fn-tcl-lists-len` over every octet staged so
  far, so a transfer of n octets costs O(n²/chunk) in guard checking alone.
  This is why the `crash` scenario's bundle is 120 KB. The fix is the one
  `books/served.lisp` already made for the wire: carry the invariant in the
  state and prove it preserved.
- **One host, loopback, one process per side.** No real network, no latency,
  no partition, no second machine's clock.
- **No BP node behind the layer**: a received bundle is a file in a spool
  directory, the barrier is that file's data and name, and no receipt exists.
- **No TLS**, per the clause matrix of `specs/tcpcl.md`.
