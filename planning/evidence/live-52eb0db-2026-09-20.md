# Live deployment: fn as a service on persvati and hbox

Not a gate: these two installations are left running. Each holds one
commit under `~/fn-live`, a store with its own groups, a peer record
naming the other box, and a supervisor that keeps the process up.
Produced by `tools/live_service.py install`.

## The unit that was installed

`packaging/fn.service` relocated under `$HOME/fn-live`, with the
`User=`, `Group=` and the `Protect*`/`Private*` directives a user
manager cannot apply removed. The difference from the packaged
file is here in full rather than asserted:

```ini
# fn as a system service.  See docs/operator.md.
#
# Install layout this unit assumes:
#   /home/ember/fn-live/fn   the repository (bin/fn, tools/, books/, host/)
#   /home/ember/fn-live/fn.toml     the configuration `fn init --config` wrote
#   /home/ember/fn-live/store   the store named by [store] path
#   /home/ember/fn-live/fn.log  the file named by [log] path (omit it to log to the journal)
#
# `fn run` is the service: it holds the store's exclusive writer lock for its
# whole lifetime, so exactly one instance of this unit may run per store.
# SIGTERM is a clean shutdown: the owner's own teardown releases the writer
# lock and removes the control socket before the process exits.

[Unit]
# A service that cannot parse its own command line must stop, not spin:
# five starts in a minute and systemd gives up and says so.
StartLimitIntervalSec=60
StartLimitBurst=5
Description=fn news node (ACL2 core, NNTP reader and posting owner)
Documentation=file:/home/ember/fn-live/fn/docs/operator.md

[Service]
Type=simple
WorkingDirectory=/home/ember/fn-live/fn
Environment=PYTHONUNBUFFERED=1
Environment=FN_ACL2=/home/ember/fn-tools/acl2-8.7/saved_acl2
Environment=ACL2_BOOK_HASH_ALISTP=NIL
# `--config` is a top-level option and must precede the verb: `fn run
# --config X` exits 2 with `unrecognized arguments`, which under
# Restart=on-failure is a restart loop. Found by running this unit
# (157 restarts on persvati, 2026-09-20).
ExecStart=/usr/bin/env python3 /home/ember/fn-live/fn/tools/run_reader.py --store /home/ember/fn-live/store --port 11190 --post

# The owner exits non-zero only on a fault; a clean SIGTERM stop exits 0 and
# is not restarted.  An ACL2 start that cannot reach a prompt is a fault, and
# restarting it is the right answer.
Restart=on-failure
RestartSec=5
KillSignal=SIGTERM
# Recovery replays the journal through ACL2 on the next start; give the
# in-flight shutdown room rather than SIGKILL in the middle of a barrier.
TimeoutStopSec=120

# Hardening.  Every line here has been chosen to leave the ACL2 host runtime
# working: a Lisp image maps writable-executable pages, so MemoryDenyWriteExecute
# is deliberately NOT set, and no syscall filter is applied.
NoNewPrivileges=yes
PrivateTmp=yes
RestrictSUIDSGID=yes
RestrictRealtime=yes
LockPersonality=yes
# ProtectSystem=strict makes everything read-only; name exactly what the store
# and the log need.  Add any path you moved [store] path or [log] path to.
ReadWritePaths=/home/ember/fn-live
# The listener is loopback (see docs/architecture.md); no other family is needed.
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6

[Install]
WantedBy=default.target
```

## What is true of this deployment and what is not

- **persvati**: linger is off for this user on persvati: the user manager, and so the service, stops when the last session closes. `loginctl enable-linger` needs an administrator; until then this is a service for as long as a session exists.
- **persvati**: the peer record $HOME/fn-live/peers/fnB.peer is a file, not a configuration record: no code on 52eb0db reads it, so these two nodes are peers on paper only.
- **persvati**: `fn run` -- the owner, the service this project means -- did not reach a listener on this tree. ACL2 refuses `(include-book "books/owner")` because that book has no certificate here, so the unit runs `tools/run_reader.py` instead: one connection at a time, no writer lock, and no claim about posting durability or concurrency follows from it. This is the same second choice tools/deploy_gate.py makes, and it is the v0.1 blocker, not a deployment detail.
- **hbox**: no certificate landed in $HOME/fn-live/fn: the box's cache holds no pair for this revision's books, so `fn run` would certify inside the service. Run a gate for this commit first.
- **hbox**: the peer record $HOME/fn-live/peers/fnA.peer is a file, not a configuration record: no code on 52eb0db reads it, so these two nodes are peers on paper only.
- **hbox**: `fn run` -- the owner, the service this project means -- did not reach a listener on this tree. ACL2 refuses `(include-book "books/owner")` because that book has no certificate here, so the unit runs `tools/run_reader.py` instead: one connection at a time, no writer lock, and no claim about posting durability or concurrency follows from it. This is the same second choice tools/deploy_gate.py makes, and it is the v0.1 blocker, not a deployment detail.
- A running listener is not a peered network. Both nodes bind
  `127.0.0.1` because `fn run` refuses any other host, so the peer
  records point at addresses neither node can reach; an ssh tunnel is
  how a client (or the other box) reaches one today.
- Nothing here certifies a book. The certificates came from the box's
  cache, which a gate put there; the certificate count per node is in
  the table above and a zero there is a finding, not a detail.
- `fn run` holds the store's exclusive writer lock for its lifetime, so
  one instance per store; a second start fails rather than corrupting.
