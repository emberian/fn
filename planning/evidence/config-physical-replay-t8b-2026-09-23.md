# T8b physical configuration replay, first model packet

The physical Store and configuration journals have independent record sequences. Configuration records carry the next unconsumed Store transaction ID. `fn-cpr-replay` merges those records at recovery by transaction ID, placing configuration before a Store event on a tie and ordering tied configuration records by their own sequence. It checks the configuration at the reservation total produced by the preceding Store events. Its successful-result theorem, `fn-cpr-replay-ok-is-configured`, establishes `fn-cnode-statep` of the result; it does not yet establish native recovery correspondence or live owner adoption.

The [selected ACL2 manifest](manifests/certify-20260923T174240Z-2343070.json) records ACL2 8.7 on `persvati`, toolchain identity `1b4169e9c5825a4e1fc827767f00470ceafc459619e0a4fd522c48f1ba964286`, two selected roots (`books/config-physical-replay` and `tests/acl2/config-physical-replay-tests`), 59 matched cached dependencies from the coherent `takeover-cohesive-store-config-586b275a` origin, and a passing 4.438-second run with two jobs. The source digests are recorded in that manifest. The tests distinguish a valid capacity decrease after a historical high-charge undertaking has been released from a forged decrease before its tied release, and exercise burned transaction-ID gaps, repeated configurations at one transaction ID, and a subsequent article event.

The native open path still replays configuration and Store records separately under final parameters. Store/owner relations likewise replay historical Store events under final domain and capacity. Those callers and a selected-checkpoint suffix need an ordered-history join before live capacity decreases can be admitted safely.
