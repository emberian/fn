It exported the one-event accepted prefix as `package.bin`. The compiled `mini verify-evidence --host HOST --config INDEPENDENT-PIN --package PACKAGE --output RESULT` command consumed `package.bin` using a separate pinned config with empty storage paths and invoked `NativeHostReplay.verifyBytes`; it matched the exact signed call, one-event prefix and original receipt. The resulting 30,067-byte ADU is 2,701 octets under 32,768; this demonstrates codec size only, not BP ingress acceptance, BPA custody, or fn Store retention. Source/binary identity and key enrollment still need the active fn lane's T10 verdict. The final carrier returned by the signer must be durably stored in the consumer outbox before any post; rerunning the signer on retry is not an exact retry.

The package's claimed genesis/profile are compared with the verifier's independently chosen pin; the fixture pins are public test values. The receipt is evidence to compare with re-admission, never standalone proof. Successful verification establishes that the call was historically accepted under that pinned native image prefix. It does not establish current authority to execute it, a physical side effect, fn transport acknowledgement, a fn retention receipt, consumer cursor progress, or an application reply. P0 currently refuses later accepted events and histories beyond its fixed bounds; those require a separately designed bounded witness, not truncation or raised limits. No private/live Mini database was read or modified.
