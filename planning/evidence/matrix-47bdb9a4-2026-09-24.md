## Finding: the duplicate-POST reason depends on the clock second

Both nodes had a Path identity and the same configuration. The driver's
`postcycle` sends the same octets twice, with no `Date` header, on two
connections (`tools/v0_matrix.py` `postcycle`, `article_lines`). The owner
logs show the timing:

```text
a: accepted post … <native-matrix-0226efdea881-a@…> time=2026-09-24T16:55:03Z
a: refused  post … <native-matrix-0226efdea881-a@…> time=2026-09-24T16:55:03Z   → "already stored here"
b: accepted post … <native-matrix-eded62cda592-b@…> time=2026-09-24T16:55:08Z
b: refused  post … <native-matrix-eded62cda592-b@…> time=2026-09-24T16:55:09Z   → "a different article with this Message-ID"
```

The refusal was the same second on A and the next second on B. The
hypothesis, which is not a measurement: fn injects headers from the
connection's pinned clock (at least `Date`), so the stored octets differ
from a later re-injection of the same submission once the second changes,
and the reason is chosen by comparing the injected octets. The row agrees
(refused, 441), and nothing is allocated. But the reason shown to the
poster, "a different article", describes fn's own injection and not what
the poster sent. That makes the W3 reason timing-dependent. It is for the
W3 owner to decide whether the comparison should be over the offered
octets. Nothing here changes the row.

## Matrix-tool repairs (commit `4ba40cf0`)

1. **A dead peer is "not exercised: peer down", not "not built".**
   `transit_direction` now asks `alive()` about both the source and the
   target when the relay gets no answer. If either has died, the 22 transit
   rows of that direction are not exercised, with the blocker
   `not exercised: peer down: … node B's server died during this run: <last
   log lines>`. Two live peers that still give no answer stay not built.
   Tests: `TransitPeerDownTests` (dead target AB, dead source BA, both
   alive).
2. **A violated check never counts as accepted.** `inn_rows` used to map a
   violated finding to the opposite of the row's expected verdict, so
   `V0-INN-LOOP-FN` (expected refused) read accepted when fn's service was
   down. Now a row that expects acceptance reads refused, as before, and a
   row that expects refusal reads **uncertain**. Both disagree. The
   observation says `violated, which is not an acceptance`. Tests:
   `test_a_violated_check_never_counts_as_accepted` (every finding
   violated, no row accepted, none agrees) and the updated
   `test_a_violated_finding_is_the_opposite_outcome_not_a_pass`.
3. **`--publish-current` refuses a run that stopped early.** When the gate
   stops on a `GateError`, `backfill(stopped=error)` gives every unreached
   row the blocker `not exercised: the driver stopped early: <error>`
   (`STOPPED_EARLY`). `publish_current` refuses a document that carries such
   a row, and it also refuses when `main` saw the failure (`stopped=True`).
   So the stopped run is kept as its immutable report, but it cannot replace
   `planning/v0-matrix.json`. Test:
   `test_a_run_the_driver_stopped_early_cannot_publish`.

## What this does not establish

This is one run on one box, over loopback. A row observes a reply, an exit
code or a file. It is not a theorem, and it says nothing about which ACL2
subject the host calls. The uncertain-outcome rows use the developer image's
fault selector. The AUTHINFO session rows run on clear loopback under
`[auth] required`, so the 483 clause is not observed. No row injects a
wire fault, so W1 and W2 are not observed on POST here. The loop and
transit rows observe one Path-identity configuration per node.
