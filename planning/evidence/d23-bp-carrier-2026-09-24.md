# D23 on the BP side: a relayed request and its receipt are accepted under the author's own enrollment

Lane `d23-bp-carrier`, 2026-09-24, on hbox. Source: branch
`lane/d23-bp-carrier` (dev `0e4b318e` plus `306ab221`, `e8e8f0ff`,
`dc27d36d`; the lab fix is in this record's commit). Everything ran under
`/tank/fn/scratch/d23-bp/`. Records, lab outputs and logs are in
[`d23-bp-carrier-2026-09-24/`](d23-bp-carrier-2026-09-24/) with a
`SHA256SUMS`. dtn7-rs is the pinned 0.21.0 checkout `/tank/fn/dtn7/repo`
(`4daf02d7`).

## Result in one paragraph

Through dtn7-rs with one relay and with two relays, fn B's `bp-node serve`
takes custody once, ACL2 decides the request `carried carrier=ingress-boundary
author=sender-author`, the application answers `request-accepted` under the
author's enrollment (its path identity and `fn.test` scope; the relay's
boundary has no inbound scope), B authors the receipt, the receipt crosses the
relays back, A decides it `carried carrier=return-boundary
author=receiver-author`, answers `receipt-accepted`, and A's obligation
becomes `receipted pinned=no`. Before this change the same labs ended
`request-refused` ([m4-app-receipt](m4-app-receipt-2026-09-24.md), finding 1).
The same image with B trusting only the neighbour (no `carries` row) refuses
`reason=source-not-carried`.

## Findings

1. **An anonymous ingress is reported as `reason=generation`.** An
   unadmitted TCPCL session gives the ingress principal nil and generation
   0, which the decision's second clause reports as `:generation`. True but
   misleading; a `:no-principal` reason ahead of it is a one-clause change
   that needs a recertification this lane had no run left for. The channel
   line `BP channel admission refused reason=eid-mismatch` names the cause.
2. **Finding 3 of m4-app-receipt is not the same decision; not changed.**
   `fnn-bpnode-forward-contact` (`host/native/bp-node.lisp`, the
   `fnn-tcl-params node-id peer-id` call) expects the application peer as
   the TCPCL neighbour and selects held jobs by that peer. The carried list
   says which sources a neighbour may bring in; which neighbour an outbound
   job is handed to is routing. Using `carries` as a route would widen an
   outbound session's trust without a decision. The labs forward receipts
   with `bp-contact tick`, which passes no expected peer.
3. **The author's boundary needs a listener port of its own.** Two
   boundaries on one port make the channel ambiguous; the author's port is
   never listened on. A boundary kind with no listener would say this
   without an unused port.
4. `proof_artifacts acquire` refuses when no single cached set covers the
   dtn roots; composing per-book pairs with `certs.py install-partial` then
   `validate` works.
