## 4. Byte identity with the three deleted host copies

The point of the migration is that **no byte on disk changes**. Checked two
ways, both outside ACL2.

**(a) The trailer function against CPython.** `FrameSession.trailer` over a
live bridge, compared with `hashlib.sha256(...).digest()` on the same octets
(Python 3.14.7, scratch script, one ACL2 session):

| octets | wall | equals `hashlib.sha256` |
| --- | --- | --- |
| 32 | 0.001 s | yes |
| 4096 | 0.008 s | yes |
| 32768 | 0.051 s | yes |
| 262144 | 0.497 s | yes |
| 1048576 | 1.710 s | yes |

The wall time is the whole bridge call — the decimal-octet marshalling
dominates it, not SHA-256 (`planning/lanes/HANDOFF-w9-digest.md` measured the
ACL2 function alone at 0.01–0.02 s for 32 KiB on hbox). **Covered scope:** one
laptop, one warm session, five sizes, one sample each; this is an order-of-
magnitude figure, not a benchmark.

**(b) A record on disk.** A scratch store initialised and posted to with the
changed code writes `00000000000000000000.txn`, 365 octets, and
`sha256(raw[:-32]) == raw[-32:]` read back in Python. A store written by the
**previous** code (`store1`, with a peer record) still opens: `peer list`
reads its record back and `recover` reports `transactions=0 articles=0`.

## 6. What was NOT exercised

- **The native host.** `host/native/io.lisp`'s `fnn-seal`/`fnn-digest-of` now
  call `fnn-trailer`, which calls `fn-frame-trailer` through `fnn-core`. The
  native image was **not rebuilt or run** in this lane. The precedent that
  makes this expected to work is `fnn-subject-id`, which has called an
  attached-digest ACL2 function through the same `fnn-core` path since
  `w9/digest`; that is a precedent, not a run.
- **The owner's feed.** `Acl2Owner.trailer` is called by `feed_frames` and
  `feed_replay_frame`. No feed test was run here: `tests/test_feed.py` drives
  `tools/run_feed.py`, which is a different (and unchanged) code path, and
  its feed cases have not passed since BOARD 739/781.
- **Anything about SHA-256's collision or preimage resistance.** A-CRYPTO is
  unchanged. Section 4's equalities are statements about specific octets.
