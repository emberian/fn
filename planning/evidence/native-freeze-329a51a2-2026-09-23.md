Passed on this image: legacy/new stamped journal migration; application
journal; checkpoint; administration; BP obligations; protected native peering;
served and raw process-death/model comparisons; and the old-image selected
checkpoint/pack migration probe. The latter exercises the migration defect
observed with the preceding image. These do not establish physical power-loss
qualification or completion of native A1/A2 receive integration.

Three initial failures are preserved:

- The NEWNEWS test incorrectly required a posting-allowed greeting and
  assumed a legacy article with no later timestamp could be excluded from a
  future-date query even when the reader had no clock. The test-only fix and
  successful rerun on this same image are recorded in
  [the NEWNEWS migration note](t2b-newnews-migration-329-2026-09-23.md).
- The hybrid test used the system OpenSSL CLI, which cannot generate
  ML-DSA-65 keys. Explicitly selecting the qualified OpenSSL 3.5.8 CLI and the
  frozen library pair made both enrollment/submission and portable-carrier
  mutation tests pass. No native source change was made for that rerun.
- The application receipt test expected uncertain release publication but
  returned success: its fault selector no longer reached the canonical
  Store release path. The source fix moves the developer cut after the
  final link and before the Store directory barrier. The assertion is
  unchanged; its rebuilt-image verdict remains pending.

The separately attempted hbox/persvati exchange failed before owners could
start because the saved core retained hbox's absolute OpenSSL path. The
[exact failure](two-host-protected-329a51a2-2026-09-23.md) is a portability
defect, not a peering result. A targeted relocated image is being qualified
while the broader BP, durability, consumer, reader and configuration lanes
continue. This source cut is an integration experiment, not a final v0 freeze.
