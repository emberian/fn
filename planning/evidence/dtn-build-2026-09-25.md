- tools/build_lists_check.py gains the `included` rule: every `fn-` name a
  host file in build-dtn.lisp's `ld` closure calls or names in `:stobjs`,
  when a book defines it, is defined in a book the DTN image has included
  by the time that file is `ld`ed (build-dtn's includes before the `ld`, the
  includes of host files loaded so far and the file's own, closed over the
  books' non-local includes). Static, about 0.4 s, inside `make check`.
  Without the fix it reports exactly two findings (`fn-octets`,
  `fn-pbb-existing-action`, both in host/owner-host.lisp); build.lisp passes
  the same rule with none; no other DTN-loaded host file needs a book the
  DTN image lacks. Limits: definitions are read by pattern (defun, define,
  defstobj, defabsstobj and kin), so a name only a macro defines is
  invisible, and defabsstobj exports are not indexed (the stobj name is).
- Teeth, tests/test_build_lists_check.py: the omission restored gives both
  findings; the includes placed after the `ld` still give both (order
  matters); build.lisp is clean under the rule; a `local` include does not
