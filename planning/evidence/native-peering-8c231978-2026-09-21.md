# Native peering qualification attempt — frozen `8c231978`

The frozen production image was exercised on `persvati` from the private gate
origin `/home/ember/fn-gates/freeze-f7190d69`.  Both intended nodes used
ephemeral stores, Unix control sockets, and loopback listeners.  No installed
service or public listener was changed.

Image identity:

- launcher SHA-256: `6855eba7d15424b1db8f039d1dff777f3bb675eb014662f7394f04ddb2818dd0`
- core SHA-256: `3364a22c75699e7d55161ab06608120e1831a5d0ccc8d4ef4222baa495e7e5ad`
- declared source: `8c231978`
- qualified ACL2 wrapper:
  `/home/ember/fn-gates/toolchains/w25/acl2-literal`

The existing opt-in `tests.test_native_peering` harness was updated to consume
the public operator's bounded `CONTROL` then `LISTENING` readiness sequence.
It was also corrected to request live peer changes after starting the public
operator.  Both tests then stopped at the first peer-add command, before any
article or peer connection:

```text
usage operator action requires native owner callback
```

The command exited 5 for both the two-way exchange case and the durable
requeue case.  The same result was independently reproduced by running
`tests.test_native_admin.NativeAdminTests.test_peer_add_and_remove_use_public_native_admin`
against the exact image and hashes above.  Moving peer configuration before
or after operator startup does not change the result.

This is a qualification blocker in the frozen image: its public operator
grammar recognizes the peer command but dispatches it as `:owner-required`,
while the image does not expose the required owner callback to the separate
operator invocation.  Therefore no outbound-feed, retry, duplicate, loop, or
TLS peering claim follows from this attempt.  Those cases require a new
source-matched image containing the live administration integration.
