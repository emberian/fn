## The join defect

D32 (`694935ab`, merged at `09c0af20`) gave `fn-inj-source-of`
(books/injection.lisp) a third recipe: a record that does not open with
the agent's Path line is read as v3, the v2 inverse of the record with
that line prepended, and `fn-inj-unsplice` (books/injection-path.lisp)
removes the `AGENT!` insertion from the source's own Path content. The
same commit gave `fn-pb-path-agent` (books/poster-bytes.lisp) a second
argument and a block arm (`fn-pb-block-agent`: a v3 record's agent is the
one its Injection-Info line names). It updated books/poster-bytes and not
its D27 concrete twin books/poster-bytes-buffer (`219fd392`, merged after
D32 was cut but before it landed): the twin `fn-pbb-source-index` answered
an index into the buffer, a v3 source is not a suffix of the buffer, so
`fn-pbb-source-index-is-inj-source-of` was false and the book failed
(dtn-build record, hbox manifest `certify-20260925T103652Z-3170879`),
`fn-pbb-path-agent-is-pb-path-agent` no longer typechecked, and no image
built (build.lisp and build-dtn.lisp both include the book).

## The fix (books/poster-bytes-buffer.lisp, prefix `fn-pbb-`)

A source in the buffer is described, never copied. A description `(K A B)`
names st[K..A) followed by st[B..): `K = A = B` for a v2 (or v1) record,
whose source is a suffix; for a v3 record `[A..B)` is the `AGENT!`
insertion, cut out of the Path content. `fn-pbb-descp` is the shape
(naturals, `K <= A <= B <= len`), `fn-pbb-desc-list` its logical value
(`take`/`nthcdr`; never run on the served path).

| Function | Reads | List twin |
| --- | --- | --- |
| `fn-pbb-source-after-path r1` | the walk past the Path line: the Injection-Date field and line, the Injection-Info line, `fn-pbb-source-after-stamp` | the tail of `fn-inj-source-of-v2` after its strip (local `fn-pbb-v2-tail`) |
| `fn-pbb-path-openp i`, `fn-pbb-path-scan i bol` | "Path: " in any case at a line start; the index past it on the first header line at or after I, nil at an empty line or the end | `fn-inj-path-openp`, `fn-inj-path-scan` on st[i..) |
| `fn-pbb-unsplice-at k agent` | the scan from K, then `AGENT!` stripped at the offset: `(list k p b)` | `fn-inj-unsplice` of st[k..) |
| `fn-pbb-source-index agent msgid` | the Path line at 0: v2 walk past it as `(k k k)`; else the walk from 0 and the unsplice | `fn-inj-source-of` |
| `fn-pbb-range-match i n xs`, `fn-pbb-desc-equalp d xs` | XS opens with st[i..n) (the rest of XS, or `:no`); then `fn-oct-suffix-equalp` at B | `(equal (fn-pbb-desc-list d st) xs)` |
| `fn-pbb-line-at i`, `fn-pbb-info-line-agent i`, `fn-pbb-block-agent msgid`, `fn-pbb-path-line-agent`, `fn-pbb-path-agent msgid` | the block walk: 49 past an Injection-Date line, the Message-ID line, 39 past a Date line, the Injection-Info line's agent; the leading Path line's agent, else the block's | `fn-pb-line`, `fn-pb-info-line-agent`, `fn-pb-block-agent`, `fn-pb-path-line-agent`, `fn-pb-path-agent` |

The Path scan conses six octets at each header line start it inspects
(the case-folded "Path: " test on a slice), nothing per octet; the block
walk reads one line (the Injection-Info line) as the first-line reader
already did. The exponent is unchanged: O(L) time, O(lines) conses, no
list of the payload; the v3 compare walks the two pieces of the buffer
against the held source exactly once.

### Theorems (each with hypothesis `(true-listp fn-octets)` and the index bounds; every buffer value satisfies them)

| Theorem | Statement |
| --- | --- |
| `fn-pbb-path-scan-is-inj-path-scan` | `(fn-inj-path-scan (nthcdr i st) bol)` is the buffer scan's index less I, or nil with it |
| `fn-pbb-unsplice-at-is-inj-unsplice` | `(fn-inj-unsplice (nthcdr k st) agent)` is `(cons t (fn-pbb-desc-list d st))` for the buffer unsplice's description D, or nil with it |
| `fn-pbb-source-index-is-inj-source-of` | `(fn-inj-source-of st agent msgid)` is `(cons t (fn-pbb-desc-list d st))` for the buffer's description D, or nil with it: the correspondence the dtn-build run found false, in its new form |
| `fn-pbb-range-match-is-equal-of-append` | `(equal (append (fn-oct-slice-list i n st) tail) xs)` iff the match is not `:no` and its rest is TAIL (a true list) |
| `fn-pbb-desc-equalp-is-equal` | the in-place compare is `(equal (fn-pbb-desc-list d st) xs)` under `fn-pbb-descp` |
| `fn-pbb-block-agent-is-pb-block-agent`, `fn-pbb-path-agent-is-pb-path-agent` | each buffer reader equals its list reader; `fn-pbb-path-agent` now takes MSGID as `fn-pb-path-agent` does |
| `fn-pbb-same-articlep-is-pb-same-articlep` | the buffer compare is the list compare, over the description |
| `fn-pbb-existing-action-is-pb-existing-action` (keystone, statement unchanged) | `(implies (fn-octets-p st) (equal (fn-pbb-existing-action msgid st groups s) (fn-pb-existing-action msgid st groups s)))` |

The subject the host calls is `fn-pbb-existing-action`:
host/owner-host.lisp `fn-owner-prepare-buffer` (line 594) and
`fn-owner-existing-action-buffer` (line 1671), reached from
host/native/owner.lisp `fnn-owner-attempt` after `fnn-octets-fill`. Its
return shape (nil, `:duplicate`, `:conflict`) is unchanged, so no host
line changed. Every executable function is guard-verified (asserted in
the test book).

Proof notes: the bounds facts of `fn-pbb-strip-at`,
`fn-pbb-strip-optional-at` and `fn-pbb-path-scan` are stated a second
time as forward-chaining rules, because a `:use` of the rewrite corollary
rewrites its own `integerp` conjunct away and a sum with the index then
stays unnormalised (the after-path guard); `arithmetic/top` is included
locally; the nil suffix past the buffer's end (`fn-inj-strip` of a cons
on nil is `:no`) is the one list fact the unsplice correspondence needed
beyond the existing twins.

## Teeth (tests/acl2/octets-stobj-tests.lisp)

The v3 witnesses are poster-bytes-tests' (now included): the tin article
(`Path: not-for-mail` first, no Date) injected by the real `fn-inj-decide`
at clocks A and B, the first held by the real Store (`*pbt-tin-store*`).

- **The v3 arm reaches.** The resend does not open with the agent's Path
  line, `fn-inj-source-of-v2` answers nothing, `fn-inj-source-of` answers
  the tin source.
- **The agent, from the block** (`fn-pbb-path-agent-is-pb-path-agent`):
  no Path-line agent; the list and the buffer (a live local buffer,
  `ost-path-agent`) both read `hbox.ember.software`.
- **The description** (`fn-pbb-source-index-is-inj-source-of`): on the
  live buffer, `K < A` (the source's header precedes its Path content),
  `B - A = 20` (the octets of `hbox.ember.software!`), st[A..B) is that
  insertion, and `fn-pbb-desc-list` of it is exactly `*pbt-tin*`, the
  list inverse's source. The v2 arm on the same walk gives `K = A = B`
  and the held source. Another agent reads nothing on either side.
- **The compare** (`fn-pbb-desc-equalp-is-equal`): the tin source in
  place, `t`; its tail, a prepended octet, and the suffix with the
  insertion left in, `nil`. Must-fails: without the true list
  (`(1 2 . 3)`: the buffer reads to its length, the list keeps its tail;
  `ost-t-desc-equalp-without-true-listp`), without the description's
  shape (`K = -1`: the list twin takes from before the buffer;
  `ost-t-desc-equalp-without-descp`), each with the ground witness
  (`ost-r-5`, `ost-r-6`).
- **The keystone over the tin Store**: the resend at clock B is
  `:duplicate` for the list function and the buffer function where the
  byte decision `fn-sn-existing-action` says `:conflict`; the held payload
  itself, `:duplicate`; a changed supplied Path, a Path-less resend and
  other groups, `:conflict`, both functions agreeing. The recognizer
  hypothesis over a v3 record: the resend with an improper tail is
  `:conflict` for the list function and `:duplicate` for the buffer
  function (`ost-t-v3-improper-buffer-reads-to-its-length`), and the
  keystone's instance is `must-fail`
  (`ost-t-v3-existing-action-without-octets-p`).
