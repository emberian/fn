# Bounds P4: carrier v2 (2026-09-25)

Packet P4 of `planning/design-2026-09-25-bounds.md` under D27. Branch
`lane/bounds-p4-carrier`, commits `dd3571a0`, `742eff90`, `e2b17943`,
`3e2b0419`, `35596fbd`.

## What changed

- **Step one.** The v1 signed-source bound is the u16 length's own width,
  `*fn-hsig-v1-max-source*` = 65535, not `*fn-article-max-octets*`. No v1
  preimage byte changes: `fn-hsig-signed-preimage` and
  `fn-hsig-subject-body` have the same bodies. Only the recognizer's bound
  moved.
- **Step two.** Carrier v2: item 1 = 2, domain tag
  `fn-authored-source-hybrid-v2` (28 octets, so the head is still `58 1c`),
  profile octet 2, and a u32 big-endian source length
  (`fn-hsig-subject-body-v2`, `fn-hsig-signed-preimage-v2`). The limit is
  `*fn-hsig-v2-max-source*` = 2^32 - 1, a codec width. ACL2 picks the
  version from the source length (`fn-hsig-source-version`): v1 up to 65535
  octets, v2 above. `fn-hsig-signed-preimage-at` and
  `fn-hsig-authorize-at` dispatch on the version. A received carrier is
  decoded at the source's version (`fn-hc-received-plan` calls
  `fn-hc-field-decode-at`), so a carrier whose item 1 names the other
  version is refused as `:carrier`. A verdict over a v2 carrier records the
  evidence tag `fn-hybrid-v2`, and `fn-stxe-keyring-profile` maps it to the
  one D09 keyring profile.
- **Host.** The subjects are the functions the host calls.
  `fn-hsig-host-preimage` calls `fn-hsig-signed-preimage-at` and
  `fn-hsig-host-authorize` calls `fn-hsig-authorize-at`, both at
  `fn-hsig-source-version` (host/hybrid-signature-host.lisp).
  host/native/signatures.lisp reaches them through `fnn-core` at :324, :333,
  :364, :388 and :414. The signer used to read its source with a literal
  32768 bound (signature-command.lisp:25). It now reads through
  `fn-hsig-host-max-source-octets`, which is the v2 width. The native
  primitive boundary used to refuse any preimage over a literal 34820
  octets. That bound is now `fn-hsig-host-max-preimage-octets`, the v2
  layout's 2054 fixed octets plus the v2 width, named by the books'
  constants.
- **Verifier.** `tools/fn_verify.py` switches on carrier item 1 (u16 or u32
  length, v1 or v2 tag). It refuses a version whose length range does not
  hold the source.

The preimage v2 table is in specs/identity.md "The signed bytes".

## Theorems (names)

The keystones are in books/hybrid-signature-invariants.lisp and
books/hybrid-carrier.lisp:

- `fn-hsig-subject-body-v2-injective` and
  `fn-hsig-signed-preimage-v2-injective`: injectivity restated for v2.
- `fn-hsig-v1-v2-preimages-disjoint`: no v1 preimage equals any v2
  preimage, stated over `fn-hsig-signed-preimage`.
- `fn-hsig-signed-preimage-at-injective`: across both versions, equal
  preimages mean equal version, principal, keys and source.
- `fn-hsig-subject-at-p-names-the-source-version`.
- `fn-hc-decode-at-of-encode-at`: the v2 carrier round trip.
- `fn-hc-decode-at-refuses-another-version`.
- `fn-hsig-signed-preimage-injective`: re-proved by left cancellation of the
  constant tag item, so it no longer rests on the one-item decoder's input
  cap.

The v1 correspondence is two theorems, named for what they are. They state
that on a source of at most 65535 octets, the versioned functions the host
calls equal the v1 functions:

- `fn-hsig-preimage-at-v1-source-is-v1-preimage-by-definition`
- `fn-hsig-authorize-at-v1-source-is-authorize-by-definition`

v1 verification on v1 carriers is therefore the same function as before.

The teeth are in tests/acl2/hybrid-signature-invariants-tests.lisp,
hybrid-signature-tests.lisp, hybrid-carrier-tests.lisp and
stx-evidence-records-tests.lisp. Each keystone has one `must-fail` per
hypothesis. There are 65536- and 65537-octet non-degenerate witnesses, and
a 70000-octet source signs as v2 and not as v1. A v1-v1 "disjointness" is
also a `must-fail`.
