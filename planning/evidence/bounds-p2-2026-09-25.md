# Bounds P2: data constants become codec ceilings (2026-09-25)

Lane `lane/bounds-p2-ceilings` (D27; packet P2 of
[the bounds design](../design-2026-09-25-bounds.md) §2.3). Merged with dev
`70759bfb` at `5d93fdb5`. Head for the evidence below: `b25de18b` (books),
`ad2c72da` (manifests). Packet P1 has not landed, so every named store profile
still has payload field 32 768; the served bounds read that field, and the
ceilings here are the codecs' own widths.

## What changed

- **Record codec.** Every byte string goes through the CBOR bounded API at
  the record width (`fn-record-item-encode`, `fn-record-item-decode`,
  books/records.lisp); the generic entry's 65 535-octet item no longer caps a
  record. Records whose items are at most 65 535 octets keep their bytes
  (`fn-record-item-encode-is-cbor-encode`; the schema-0 golden vector is
  unchanged).
- **Ceilings.** `*fn-record-max-octets*` 2^32-1 (FNST u32 LENGTH);
  `*fn-record-max-payload*` = `*fn-article-max-octets*` 4 261 412 864
  (2^32-2^25); `*fn-record-max-groups*` 65 535; `*fn-record-max-group-name*`
  256 (the configuration label's width; 460, the NNTP wire's, needs
  `*fn-cfg-max-label*` raised in config.lisp, P1's file);
  `*fn-frame-max-payload*`, `-store-payload*`, `-inbound-payload*` 2^32-1.
  The worst-case record at the payload and group ceilings fits the record
  width: `fn-record-encoded-octets-ceiling-within-record-width`.
- **Kept, and why.** Header octets, lines and fields stay as **work** bounds.
  The certified parse work bound is fuel per header line times input length:
  9 006 794 391 183 396 steps at the codec ceiling and 69 261 680 676 at the
  32 768-octet profile bound (tests/acl2/article-work-tests.lisp). That bound
  is quadratic in lines times length, and removing the caps needs a work
  theorem linear in the header. `*fn-frame-max-blob*` 131 072 stays: the
  frame-field lemmas bound a schema by field count times the blob cap, and a
  seven-field journal at u32 blobs overflows the u32 frame
  (`fn-frame-workflow-encode` guard, run f437). **Open:** a per-schema blob
  width. Until it lands, the control socket carries at most 131 072 octets of
  article, and when hybrid control is loaded its frame is 65 536
  (`*fn-nhctrl-max-payload*`, hybrid-* not this lane's).
- **Pinned at their proved bounds until their packets.**
  `*fn-stxa-max-article-record*` 65 538 and `-authored-source*` 32 768 (kind-4
  composite; P1/P4), `*fn-hsig-v1-max-source*` 32 768 (P4 defines the same
  name at 65 535 and replaces it on merge), `*fn-bpa-max-article*` 32 768
  (ADU; P5), `*fn-store-article-publication-figure*` 65 538 (pre-reservation;
  P1 derives it from A and G).
- **Served bounds read the profile.** The owner's POST and control bound are
  `fn-owner-served-post-bound` (host/owner-host.lisp):
  `fn-sbud-payload-bound` of the carried profile. The injection configuration's
  max-octets is the parser's input bound: `fn-inj-decide` refuses `:oversize`
  before `fn-article-parse` walks a longer source. One FNCT control read is
  bounded by the request's field widths (`*fn-nctrl-max-payload*` = two blobs
  and a text, 262 666), not by the article ceiling.

## Theorems (statements kept; restated proofs)

Every existing statement keeps its symbol. The hypotheses `(<= ...
*fn-cbor-max-input*)` were **dropped**, which strengthens these theorems:
`fn-record-groups-prefix-round-trip` and the read-prefix lemmas of
records-invariants and records-canonicality. The following were re-proved
over the bounded decoder: `fn-record-impl-round-trip`,
`fn-record-impl-accepted-input-is-canonical`, `fn-record-read-bytes-encoded`,
`fn-record-read-uint-encoded`, `fn-record-read-bytes-reencode-prefix`,
`fn-record-read-uint-reencode-prefix`, `fn-record-decode-tail-reencode`,
`fn-record-decode-after-header-reencode`,
`fn-record-component-prefixes-compose`. `fn-record-group-encoding-bound`'s
per-group factor is now `(+ 5 *fn-record-max-group-name*)` instead of the
literal 131.

New:
- `fn-record-encode-length-bound`: a seam constraint (records-seam) with its
  impl witness.
- `fn-record-item-stream-bytes-round-trip`: the item round trip at any length
  up to the u32 width.
- `fn-record-encoded-octets-ceiling-within-record-width`.
- `fn-nctrl-article-ceiling-is-the-record-payload-ceiling`.
- `fn-nctrl-max-frame-within-frame-width`.

The design's `fn-record-decode-bounded-of-encode` is not a separate event.
`fn-record-impl-round-trip` is that theorem, because the decoder it names is
now the bounded one. A second name would be a corollary.

**Teeth:**
- tests/acl2/records-ceiling-tests.lisp: a 70 000-octet payload and a
  256-octet group name round-trip; the generic decoder refuses the 0x5a item;
  one must-fail per item round-trip hypothesis, and one for the length bound.
- tests/acl2/injection-tests.lisp: an unparsable source past the configured
  bound gives `:oversize`, and within it gives `:unparsable`. A
  34 000-body-octet article is `:injected` under a 70 000 configuration and
  refused `:oversize` under 32 768.
- tests/acl2/frame-tests.lisp: a 196 609-octet store payload round-trips, and
  the caller's cap refuses it.
- The group-count and group-name vectors in records-, records-shape-,
  codec-seam-, store-budget-naming-, native-admin- and native-operator-tests
  are written from the ceilings.

**Crash model: unchanged.** No transition or crash point was added or moved.
The open still reads each transaction file whole, in one bounded read. The
bound is now `fn-store-profile-read-bound` = frame overhead +
`fn-bs-profile-record-ceiling` of the persisted profile, not overhead + 196 608.
That this read never truncates a committed file rests on two things. First,
`fnn-publish` asserts `fn-bs-publication-admissiblep` on the actual record
bytes before any staging write (host/native/io.lisp). Second,
`fn-profile-upgrade-keeps-publication-admissibility`
(books/store-profile-upgrade.lisp) says an upgraded profile still admits
every record the old one admitted. `fn-bs-read` in the model still returns
the whole inode.

## Findings

1. The oversize refusal at the wire says "the article was not received", not
   the `:oversize` line "exceeds the configured size". The wire machine cuts
   the body at the owner's body limit (the profile bound) before injection
   runs, so the refusal is correct but its words do not name the bound. This
   is a W3 wording question, left as is.
2. The group-name ceiling is bound by the configuration label (256), not the
   wire (460). Before this change, native-admin's typed-delta keystone relied
   on the 128-octet cap.
3. `fn-record-cbor-encode-bounded-of-uint-value` made
   `fn-cbor-encode`'s definition loop in any book that enabled it. It is now
   disabled at the end of records-canonicality.
4. Old tests built witnesses at the constants (`make-list
   *fn-frame-max-store-payload*`, record and article max). At u32 widths those
   witnesses would have allocated gigabytes. Each one is rewritten at a size
   above the pre-D27 value.
5. `tools/fn_verify.py:73` `ARTICLE_MAX = 32768` and
   `host/native/signature-command.lisp:25` are v1-carrier bounds, not article
   bounds. P4 owns both, and this lane leaves them unchanged.
