reaches". On the qualified `1a9dd747` pair, run `20260924T143359Z` of
`tools/v0_matrix.py --backend native-operator` reached 188 of 220 rows and

## Harness defects found and repaired (runs 1 and 2)

1. **Protected witnesses were read only at the start of a line**
   (`tools/v0_matrix.py`, commit `1e119603`). The protected suite runs under
   `unittest -v`, which prints `test_x (...) ... ` with no newline before the
   test body runs. So every `NATIVE-PROTECTED-WITNESS` record after the first
   lands in the middle of a line. In run 1, all five protected tests passed
   on this image (rc=0, both owners observed on the `12ece6cc…` core). Even
   so, `V0-TRANSIT-TLS-WRONG-ANCHOR`, `V0-TRANSIT-AUTHINFO-WRONG` and
   `V0-FEED-ONCE` read not exercised with "witnesses=1". `witness_records`
   now finds the marker anywhere in a line, and a regression test uses the
   `-v` prefix.
2. **The INN lab ran without the image's OpenSSL** (`1e119603`).
   `inn_command` did not forward `--native-openssl-prefix`, which
   `tools/inn_lab.py` accepts. From 1a9dd747 on, `store init` needs OpenSSL
   3.5 for ML-DSA, so the lab stopped at `fn store init` with
   `FNN-HSIG-UNSUPPORTED`. Nine INN rows went not exercised, and
   `V0-INN-INTEROP` faulted with rc 2. With the prefix forwarded, the lab
   held 33 of 33.
3. **`V0-READ-NEWNEWS-SYNTAX` could never agree** (`83cec9b1`). The row
   expects the refusal `501`. The read phase treated every 500/501 as "verb
   not built" before the row saw the reply, so a correct node always read
   not built. That is what runs 1 and 2 recorded: `501 syntax error` on both
   nodes while `V0-READ-NEWNEWS` answered 230. The row had never been
   measured before (it was not exercised on 3f68944). It is now read by
   reply class whenever the well-formed NEWNEWS is dispatched. Three tests
   cover the branches: refused, verb missing and disagreeing.

The test `test_historical_schema_one_matrix_remains_valid` used the
published dashboard as its schema-1 fixture. It would fail the moment any
native run was published. The 3f68944 dashboard is kept byte-identical at
[`v0-matrix-3f68944-2026-09-21.json`](v0-matrix-3f68944-2026-09-21.json),
and the test reads that file.

## Rows not reached in run 3, and why

- `V0-NODE-LOOPBACK`: **declared usage probe.** A wildcard listener gets
  `rc=5 usage operator request (CONFIGURATION INVALID)`, the exact reply the
  row expects (`expected_usage`). It is not a D13 outcome, so the row stays
  not exercised, and it is not counted as faulted.
- `V0-TRANSIT-INDEPENDENT-A/B`: **no native phase.** Only the Python
  backend's `independence` phase emits these rows. `execute_native_acceptance`
  runs `native_seed` but has no presence check.
- `V0-CRASH-CHECKPOINT`, `-KILL`, `-SURVIVOR`, `-RECOVER`, `-ACKNOWLEDGED`,
  `-INTERRUPTED`, `-RESTART`, `-CUT-TABLE`, `-CAMPAIGN`: **no native phase.**
  The native slice runs no process-death campaign. `--no-campaign` was not
  given, but the flag drives only the Python backend. The campaign on this
  image is a separate lane
  ([campaign-1a9dd747](campaign-1a9dd747-2026-09-24.md)).
- `V0-BP-IMAGE`, `-EXCHANGE`, `-REFUSED`, `-KEEPALIVE`, `-CRASH`, `-PROFILE`,
  `-REPLAY`, `-NODE`: **no native phase.** The BP native cases on this image
  are in the qualification record (N03, interrupted fragment).
- `V0-STX-SIGN`, `-ATTACH`, `-CROSS`, `-VERIFY`, `-UNVERIFIED`, `-READER`:
  **no native phase.**
- `V0-MEDIA-EXPORT`, `-VERIFY`, `-IMPORT`: **no native phase.**
- `V0-SCALE-CEILING`: `--scale` was not given, and the native slice has no
  scale phase.
- `V0-CLIENT-SLRN`: slrn is not installed on hbox.
- `V0-AUTH-NEW` (not built): the native operator has no `principal new`.
  The local principal id is derived inside `set-password`
  (`fn-native-auth-admin-principal`).

For the rows with no native phase, the tool's own blocker reads "the run
reached its end without this row; the phase that owns it raised or was
skipped". The wording is generic. What it means for these rows is that the
native slice has no phase for them. No phase raised: the run records no
limitation of that kind.

## What this does not establish

This is one run on one box, over loopback. A matrix row observes a reply
line, an exit code or a file. It is not a theorem, and it says nothing about
whether the ACL2 subject the host calls is the one the registry cites (that
is the audit lanes' column). The uncertain-outcome rows use the developer
image's fault selector, because the production image refuses it. The
AUTHINFO session rows run on a clear loopback connection under
`[auth] required`, not `protected_only`, so no row here observes the 483
clause of P1. The protected rows observe TLS and AUTHINFO only through the
feed's delivery, a 502 on a clear connection, and the two refusals.
