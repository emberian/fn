## What changed

- **Format 8.** `config.json` (FNSM kind 1) is two texts and twelve u64 frame
  naturals: `max-transactions` T, `max-history-octets` H, `max-record-octets`
  R, `max-article-octets` A, `max-groups-per-article` G,
  `max-group-name-octets`, `max-open-suffix` K, and the five namespace counts.
  The dead capacity field is gone. `fn-bs-profile-validp` checks the relations
  one comparison at a time, and `fn-bs-profile-invalid-reason` names the first
  one that fails.
- **Defaults** (`*fn-bs-profile-defaults*`, which `init` writes when no base
  is named): T = 2^32-1, H = 2^40, K = 65536, the namespace counts 2^20, and
  R, A, G and the name bound at min(D27 figure, today's codec ceiling). Today
  those are 196608, 32768, 16 and 128. They rise when P2 raises the ceilings.
- **Format 7** is still decoded, and the store runs under its translation
  (`fn-bs-profile-of`). **Format 6 is no longer opened.** Its 65538-octet
  record ceiling is below the ceiling of the largest event kind.
- **Upgrade.** `fn-profile-upgradep OLD NEW` holds when OLD is admitted, NEW
  is valid, NEW differs from OLD, and none of the twelve fields is smaller.
  The 7-to-8 step is the case where every field is equal.
- **Operator argv** (ACL2, `books/native-operator.lisp`):
  - `init [--profile development|scale|default] [--FIELD N ...] GROUP...`
  - `store upgrade-profile [PRESET] [--FIELD N ...]`. With no preset, the
    base is the store's current profile.
  - N is a decimal below 2^64. A repeated field is a usage error (5). A
    broken relation is refused (1) by the relation's name.
- **Status** prints `profile format=N max-transactions=... ...`
  (`fn-bs-profile-report`) and
  `headroom ... bytes-used=... history-bound=...`.
- **Admission** is `fn-sbud-verdict-at`: fewer than T committed transactions,
  the kind's worst-case record within R, and the committed record octets plus
  that record within H. The owner carries the octet sum as (K . SUM), so each
  record is encoded once per owner process (`fn-sbud-bytes-extend`).

## Theorems

Restated by name, over every valid profile rather than the four tuples:

- `fn-bs-profile-record-ceiling` (now field R), `fn-bs-publication-admissiblep`
- `fn-bs-config-decode-of-encode` (every valid profile round-trips)
- `fn-sbud-budget-is-the-profile-admissibility`
- `fn-sbud-named-profile-article-budgets` (preset witness)
- `fn-sbud-payload-bound-within-record-codec` (now A and G)
- `fn-sbud-post-boundary-refuses-exactly-past-the-profile-bound` (hypothesis
  `group-count <= G`), `fn-sbud-named-profile-payload-bounds` (witness)
- `fn-profile-upgradep`, `fn-profile-upgrade-keeps-txn-observation`,
  `-keeps-replay-bound`, `-keeps-publication-admissibility`,
  `-budget-grows`, `-keeps-verdict` (both gates),
  `fn-profile-upgrade-verdict-writes-only-upgrades`,
  `-budget-after-reopen`, `fn-profile-upgrade-development-to-scale`
- `fn-ccp-profile-upgrade-keeps-reclaim-plan`, `fn-cverb-pack-fits-the-profile-budget`

`fn-bs-profile-program-crash-is-old-or-new` does not change. It is over
octets.

New:

- `fn-bs-profile-validp-codecs-accept`: every field of the profile a store
  runs under is within its codec, and R covers every event kind when the
  profile is admitted.
- `fn-sbud-bytes-used-is-kernel-sum`: a valid carried prefix sum extends to
  the kernel's sum.
- `fn-sbud-verdict-is-the-count-and-history-admissibility`.
- `fn-profile-upgrade-format-7-to-8`: a format-7 tuple upgrades to its
  translation, the verdict writes it, and every kind's budget is unchanged.

Renamed: `fn-cverb-profile-count-within-pack-events` is now
`fn-cverb-preset-count-within-pack-events`. It holds for the presets only.
Under an operator T above 4096, the one-unit pack's 4096-event limit can
refuse compaction (`:exceeds-compaction-unit`). That is a finding for P5.

Teeth are in these test books: byte-store-frame-tests, store-budget-tests,
store-budget-naming-tests, store-profile-upgrade-tests,
store-compact-verb-tests, checkpoint-compaction-preservation-tests and
native-operator-tests. They cover:

- a free-field profile valid and round-tripped;
- one refusal per relation, by name;
- R below the article kind's ceiling, refused;
- the history gate refusing at room+1 while the count admits;
- a wrong cache;
- a shrink refused by field name;
- a 7-to-8 translation that shrinks, refused;
- a must-fail per keystone hypothesis;
- a reachable 129-name counterexample for the reclaim plan.

## Offline procedure for the deployed store (format 7 scale on hbox)

1. Build and install an image carrying P1, as for any image upgrade
   (planning/evidence/node-hbox-da5fd8cb-2026-09-23.md). Do not start it
   against the store yet.
2. Stop the unit. `store upgrade-profile` refuses while the owner holds the
   writer lock.
3. `fn operator CONFIG status` with the new image prints `profile format=7
   max-transactions=4096 ...` and the headroom. The new image serves a
   format-7 store under its translation, so this step is optional.
4. `fn operator CONFIG store upgrade-profile` (no word) writes the format-8
   scale frame. It prints `previous-budget=4096 transactions-budget=4096`.
   Raise fields in the same step if wanted, e.g. `--max-transactions 1000000
   --max-history-octets 1099511627776`.
5. `status` shows format 8. Start the unit. Exit 3 (uncertain) at step 4 is
   resolved by `status`: it reads the old frame or the new one, never a torn
   one.

An image before P1 cannot open a format-8 store: its decoder refuses
`fn-store-8`. Roll back by keeping the old frame (a copy of `config.json`
taken at step 2) and restoring it with the unit stopped.

## Limits and open items

- R has exactly one valid value on this tree (196608). The accepted-statement
  kind's ceiling equals the FNST codec ceiling. R becomes free only when P2
  raises `*fn-frame-max-store-payload*`.
- The relation "R ≥ the article record for (A, G)" uses the kind table's
  figure (`fn-store-publication-ceiling :article`), not
  `fn-record-encoded-octets-ceiling A G`, which exists only on P2's branch.
  Replace it at the P1+P2 merge.
- `operator post` reports only `REFUSED` for a payload past A. The reason is
  the owner's and is not relayed on the control socket.
- The Python store (tools/run_store.py, run_owner.py) was moved to opaque
  profile values and ACL2's `fn-store-profile-summary`, but its test suite
  was not run in this lane (no local ACL2).
- `host/store-host.lisp` `*fn-store-capacity*` (used by checkpoint-host as
  the retention default) and `tools/run_store.py` `MAX_TRANSACTION_COUNT`
  (the Python presets) remain.
- `config.lisp` `fn-cfg-limit-ceiling` needed no change. P2 keeps the
  constant names and makes them the codec ceilings.
- The owner's octet cache relies on committed records growing append-only
  within one owner process. It is reset at profile install. That is stated,
  not proved.
