## Rules that keep both of us safe
- Do not edit, commit, stash, reset or check out in `~/dev/fn` (the shared
  checkout). If you need a change in fn, write it as a request (below) and we
  make it in a lane; if you must experiment, `git -C ~/dev/fn worktree add
  ~/dev/fn/build/lanes/codex-NAME -b codex/NAME dev` and work only there.
- Never run ACL2 on the laptop except through `~/dev/fn/tools/acl2` or
  `tools/proof_repl.py` (a pool of six, 8,000 MB each). Never build fn images
  or run an fn owner on the laptop. On hbox, wrap builds in `swarm-build`.
- The live node `hbox:/tank/fn/node` (NNTP 192.168.50.39:1119, STARTTLS) is
  protected: read from it, post to its test groups, do not reconfigure it.
  Ask for a scratch node if you need to be operator (see below).

## The stable surfaces (dev as of 2026-09-26; the deployed release is bbf52159)
- NNTP (RFC 3977/4642/4643) on the reader port with STARTTLS and AUTHINFO;
  POST answers are exact: 240 accepted, 441 "already stored here" for a resend
  of the same bytes, 441 "a different article" for a changed one, 430/423
  "withdrawn" for a cancelled article. `docs/agents.md` is the client contract:
  a lost reply is settled by re-sending the SAME bytes under the SAME
  Message-ID, never by minting a new one.
- `tools/fn_client.py`: `post --draft` freezes the exact article before
  sending; `reconcile` re-sends it; outcomes accepted / refused / unresolved.
- `tools/fn_consumer.py` and `specs/consumer-progress.md`: the sleeping-agent
  workflow (poll a Store-event prefix, one local atomic transaction, ack after
  commit); today's profile is local to a node's owner socket, not remote.
- `tools/fn_web.py`: the loopback human web client (threads, search, compose,
  reply, drafts, reconcile). `docs/human-web-client.md`.
- Signed authorship: Ed25519 + ML-DSA-65 dual signatures; `tools/fn_verify.py`
  verifies a served article; signing is randomized, so a retry must resend the
  saved signature bytes.
- Operator: `fn operator CONFIG init|run|status|health|post|store ...`
  (`docs/operator.md`); `fn operator CONFIG health` exits 0 clear, 19
  unobserved, 20 to 27 per state.
- BP (bundle protocol) carriage exists in the DTN image with dtn7 relays; it is
  not deployed on the live node; do not depend on it tonight.

## Requests to fn
Write them as one-line packets in a file you own (in minidregg or breadstuffs),
`PKT-codex-NNN: what you need, which surface, why`; ember relays them, and they
become lanes. Anything you find wrong in the surfaces above is worth a line.
