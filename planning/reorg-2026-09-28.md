Status: a PROPOSAL for ember to read before anything moves. No book has moved.
Author: lane book-split-pilot, which is now the lead of the reorganisation. The
pilot's evidence is planning/evidence/book-split-2026-09-28.md.

## 2. Inside a subsystem: api, impl, proofs

This generalises the recipe measured in the pilot.

- **`S/api/`**: what other subsystems may include. It holds the types
  (recognisers and defrecord shapes), the :logic definitions that other
  subsystems' proofs must open, constrained seam functions (encapsulate
  signatures with guards) for everything other subsystems only call, and
  the headline theorems stated over those. It is small and changes rarely.
  - Constrained stubs, defun-nx relations, the logical side of
    defabsstobj, and the assumption encapsulates live ONLY here or in
    `proofs/`.
  - Guard verification of the :logic definitions stays in `api`. A
    guard-verified caller needs its callee's guards verified in its own
    world, so guards cannot move out.
- **`S/impl/`**: the executable definitions. It includes `S/api` and the
  `api` (never `impl`) of lower subsystems, plus lower `impl` books only
  where it calls them directly (see the cost note in section 8).
  - Each executable twin is `F-exec = (mbe :logic (F ...) :exec <fast>)`.
    Its verify-guards is the correspondence proof.
  - Each attached entry point has one `F-exec-is-F-by-definition` equation.
  - `S/impl/attach.lisp` holds the defattach of every seam of S to its twin,
    citing the -by-definition equations and the api's facts.
  - impl holds no defthm that is not a guard lemma or a -by-definition
    equation, and no stub (the lint in section 5 checks both).
- **`S/proofs/`**: correspondence, invariants and keystones. These are
  LEAVES: no book outside `proofs/` and `tests/` includes one.
  - A lemma another subsystem needs is promoted to `api`. A proofs book is
    never included to borrow a lemma.
- **`S/lemmas/`** (only if needed): arithmetic and list lemmas shared by S's
  proofs, included locally.
- **`tests/acl2/S/`**: includes `api`, `proofs` and `impl/attach` (for ground
  evaluation). Nothing includes a test.
- **The image** (host/native/build.lisp, build-dtn.lisp,
  tools/extract/world.lisp) includes ONE umbrella, `image/world.lisp`. That
  umbrella includes every subsystem's `impl/attach`. Each compiled file then
  loads once, so TLS use is stubs × 1.
  - The image unavoidably loads the api books, stubs included: defattach
    needs the constrained function in the world, and an mbe's :logic names
    the api function. The image never loads `proofs/`.
  - Measured today, 13,256 theorems are in the image closure. After the
    reorganisation, the only theorems in it are api headlines and impl guard
    lemmas.

**Naming**: `books/S/api/X.lisp`, `books/S/impl/X.lisp`,
`books/S/impl/attach.lisp`, `books/S/proofs/X-*.lisp`. Function and theorem
names do not change (the ledger and the registries key on them). Only paths
change, plus the new `-exec` twins and `-by-definition` equations.

## 3. Layering and rules

1. A book in subsystem S at layer k may include:
   - `api` of any subsystem at a layer ≤ k (S included);
   - `S/impl` from `S/impl`;
   - `impl` of a lower subsystem, only from `impl` (a direct call), and
     the lint counts these;
   - `proofs` only from `S/proofs` or tests.
2. No include in the opposite direction. The layer table
   (`planning/layers.json`: subsystem → layer, plus the allowed exceptions
   with a reason each) is the single source.
3. Stubs, defun-nx, the logical side of defabsstobj, and assumptions never
   appear in `impl` or `image/`.
4. tests/acl2 include api, proofs and impl/attach only.
5. A book that includes nothing in its own subsystem and everything from a
   higher one is in the wrong subsystem: the lint says which one it belongs
   to.

## 4. The hubs, and what each splits into

- **cbor (1,390 dependents, 7 edits since 09-18)**
  - Split: `codec/api/cbor` (the item grammar's :logic encode/decode, the
    result shapes, the round-trip headline) and `codec/impl/cbor` (the
    prechecked and wide decoders, currently the :exec side of
    fn-record-item-decode). `cbor-invariants` goes to `codec/proofs`.
  - cbor-invariants has 1,255 dependents today because books include it for
    round-trip lemmas. Those lemmas get promoted to the api, and nothing
    includes the proofs.
- **defrecord (1,256; 5 edits)**: a macro library. It stays in `lib/`,
  because every type is built with it. Its fan-in is honest. An edit to it
  is a language change and should cost the tree.
- **rev-onto (1,225; 1 edit)**: stays in `lib/`. It is stable, so its
  fan-in costs nothing in practice.
- **records-shape (1,224) / records (1,133) / records-invariants (1,117) /
  records-canonicality (1,000) / records-seam (992)**
  - records-shape and records-seam go to `codec/api`. records goes to
    `codec/impl` (the pilot's split is step one). records-invariants and
    records-canonicality go to `codec/proofs`.
  - The obstruction the pilot found: crypto-seam, config, bp-adu and
    native-control include records-invariants to get the ITEM layer
    (read-uint, read-bytes, item encode/decode, parse-groups and their round
    trips). That layer becomes `codec/api/record-items`, and those four
    include it.
  - records-seam's witness needs canonicality locally. Under the farm's key
    (local includes count), that local include keeps records.lisp in about
    990 closures. Section 8 describes two options.
- **acceptance-alloc (1,142; 6 edits)**: "total executable helpers,
  primitive domains, and the local-number watermark allocator" (17 mbe).
  Acceptance, provenance, retention, byte-store, nov-fields and
  native-admin-shape include it for the domains.
  - Split: `store/api/acceptance-domains` (recognisers) and
    `store/impl/acceptance-alloc` (the allocator and its twins).
- **wildmat (1,133; 3 edits)**
  - Why it reaches 1,133 books: frame-fields (1,119 dependents) includes
    wildmat only for its RFC 3629 UTF-8 decoder
    (`fn-wildmat-decode-aux`, frame-fields.lisp:9 and :72).
  - Split: move the UTF-8 decoder to `codec/api/utf8`. frame-fields includes
    that, and wildmat (the glob matcher) goes to `text/`. Its dependents
    then drop to nntp-syntax (713) and peer-config (520), and further once
    those are api-only.
- **clock (1,066; 2 edits)**: records-stamp includes it for two recognisers
  (fn-clock-observationp, fn-clock-timep). Split: `time/api/clock-types`,
  with the clock model in `time/impl` and `time/proofs`.
- **frame-octets / frame-fields / frame (1,100+ each)**: `codec/api/frame`
  (the grammar and shapes) and `codec/impl/frame` (digest buffer twins).
  frame-journal and frame-invariants go to `codec/proofs`.
- **config (743; 24 edits, the most-edited hub below owner)**: it is
  included by 60+ books in five subsystems.
  - Split: `config/api` (the configuration record types and the profile
    bounds), `config/impl` (the loop twins, the stream), `config/proofs`.
- **The "store hub" band** (store-node 655 / 40 edits, replay 861 / 33,
  hybrid-store 952 / 27, byte-store-frame 639 / 33): these top the
  value = fan-in × churn ranking (section 7). Each gets the same three-way
  split.

## 5. Enforcement (tools/, in make check)

- **`tools/layer_check.py`** reads planning/layers.json and the farm's
  graph. It fails on:
  - an include against the layering;
  - a proofs book included from outside proofs/tests;
  - a stub, defun-nx, defabsstobj or defaxiom-shaped encapsulate in
    impl/ or image/.

  It warns on a book that floats up. It runs over the graph that
  `certify_books` already builds, so there is no second parser.
- **`tools/stub_count.py BOOK...`** (the TLS gate):
  - counts constrained stubs, defun-nx and defabsstobj machinery in the
    closure of each named book;
  - counts the top-level includes that reach each one;
  - reports stubs × reaching-includes for the image's build files.

  The gate is that count for host/native/build.lisp. It should equal the api
  stub count exactly, with each stub reached once. arena-store-8's
  hbox:/tank/fn/scratch/arena-store-8/tlsprobe*.lisp is the measurement it
  predicts.
- **`shape_books.py`** gains `--by-subsystem`. The fan-in table in
  docs/proof-style.md is then per api book, and an impl book's number must
  stay in single digits outside its own subsystem.

## 6. The mechanical migration (tools/reorg.py)

**Input.** planning/reorg-plan.json, one row per book:
`{book, subsystem, role: api|impl|proofs|lemmas|test, new_path, split: null |
{into: [...], forms: {...}}}`. Pure moves come first. Splits are separate
steps, each with its own form list, applied by the same tool that checks
"every original form is in exactly one part, byte-identical, same order" (the
check owner-books-split used).

**What it rewrites**, printing the complete edit list in dry-run mode:

1. Moves the file, with `git mv` so history follows.
2. Rewrites every `include-book` path in books/, tests/acl2/, host/ and
   tools/extract/. These are relative to the including file's directory, so
   every includer is recomputed, and `:dir` includes are left alone.
3. Rewrites the Makefile roots (the ACL2_BOOKS lists, check lists) and
   build_lists_check's inputs.
4. Updates registry paths: planning/proofs.json evidence and statements
   (paths only), requirements.json subjects, proof-events.json (names are
   unchanged), planning/proof-cost-baseline.json and the near-5 rows, the
   reach_check and depth_check baselines, host_callers_baseline.json, and
   tools/extract/declared-blockers.json.
5. Updates the host load lists: host/native/build.lisp, build-dtn.lisp and
   build-store-test.lisp. These become the `image/world` umbrella.
   tools/extract/world.lisp is regenerated with world.py, never
   hand-edited.
6. Rewrites paths in docs/ and specs/. A citation of `books/X.lisp` becomes
   the new path; line citations are forbidden anyway.

**Verification.** After the move, nothing but paths may differ:

- `ledger.py --write`, then a diff of the theorem, function and guard counts
  against the pre-move ledger. It must be empty, except for new twins and
  `-by-definition` equations, which are listed.
- reach_check and must_fail_check unchanged.
- The theorem-name set per book is compared under a rename map.
- Native: served_differential, and the store digest (full replay) on n1k and
  n10k, byte-identical to the pre-move image. This is exactly the pilot's
  gate.
- extract-check PASS.

**Cost.** A moved book's closure key changes (its path is in the listing), so
the move recertifies the whole tree ONCE: about 1,456 books, on both boxes.
The pilot's 1,093-root run took 509 s (persvati, 20 jobs) and 656 s (hbox, 14
jobs) of wall time. Expect about 20 minutes over both boxes, coordinated with
toolchain-unify so the certificates are shareable.

## 7. Fan-out plan

1. **Skeleton (me)**
   - planning/layers.json and reorg-plan.json, with every book assigned and
     the dry-run float list reviewed.
   - tools/reorg.py, layer_check.py and stub_count.py.
   - The pure move of every book into `S/` with no splits, as ONE commit.
   - One full recertification, then the verification gate above.
   - Everything lands before any lane starts, because every lane's paths
     depend on it.
2. **Parallel lanes** on disjoint subsystems. Each splits its hubs into
   api/impl/proofs by the recipe; the numbers are fan-in × edits since
   09-18.

   | lane | subsystems | split order |
   |---|---|---|
   | codec | codec/ | cbor, records-shape (the item layer), frame-*, then wildmat's UTF-8 decoder out of frame-fields |
   | store-a | store/ | store-node 26,200, replay 28,413, byte-store-frame 21,087, byte-store-scan 18,908 |
   | store-b | store/ | hybrid-store 25,704, statement 12,048, acceptance/-alloc, payload-arena |
   | protocol | nntp/ and text/ | nntp-responses 22,632, nntp-post 20,664, nntp-auth 19,120, served 15,820 |
   | compose | config/, owner/, peer/ | config 17,832, owner 23,400, peer-inbound 24,400 |

   - codec is the widest: I split it myself after the skeleton lands.
   - store-a and store-b need disjoint book lists. The skeleton's plan file
     assigns them.
   - bp/ and crypto/ come in a second wave.
   - Lanes on different subsystems do not include each other's impl or
     proofs by construction. Where one lane's api change touches another's

3. **Convergence**: one full recertification on both boxes, the verification
   gate, and the TLS count.

## 8. Predicted recertification cost for typical edits

Dependents, the edited book included, from the current graph:

| hub | today (any edit) | impl edit, direct calls (dependents inside the image closure) | impl edit, seamed (pilot shape) | proof edit |
|---|---:|---:|---:|---:|
| cbor | 1,390 | 446 | single digits | 1 + its tests |
| defrecord | 1,256 | 388 (a macro edit is an api edit) | n/a | |
| records | 1,133 | 332 | **5 (measured)** | 1 + tests |
| acceptance-alloc | 1,142 | 330 | single digits | |
| wildmat | 1,133 | 330, or about 713 once the UTF-8 decoder leaves | single digits | |
| clock | 1,066 | 301 | single digits | |
| config | 743 | 192 | single digits | |
| replay | 861 | 215 | single digits | |
| store-node | 655 | 151 | single digits | |
| owner | 312 | 60 | single digits | |

An api edit costs what an edit costs today, restricted to books that include
that api (the api books are smaller and change less). Two structural costs
remain:

- A local include of a book that has an impl (records-seam's witness)
  keeps that book in its dependents' closure keys, because the farm counts
  local includes. There are two ways out:
  - (a) make every seam's witness a :logic definition living in api. Its
    impl twin is attached, so no impl is in the witness's closure. This is
    the pilot's shape extended to the encoder, and it is always available.
  - (b) exclude local includes from dependents' cache keys. That is a
    soundness decision about the cache (make-event expansions can depend on
    local includes), for ember, not for a lane.

  I recommend (a).
- The "direct calls" column is the price of impl including lower impl.
  Seaming a cross-subsystem call removes it. Whether every cross-subsystem
  call gets a seam, or only the hot and high-churn ones, is a
  per-subsystem choice. The fan-out lanes report it.
