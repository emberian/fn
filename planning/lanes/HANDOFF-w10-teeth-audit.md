# w10/teeth-audit — the witnesses in `tests/acl2/` that do not bite

Branch `w10/teeth-audit`, merged with dev `99a348c`. Evidence for every number
below: `planning/evidence/teeth-audit-2026-09-20.md`, regenerated by
`python3 tools/teeth_check.py --report`.

## The tool, and why it is not a ledger lint

`tools/teeth_check.py`, with `tests/test_teeth_check.py` (33 cases) and one
line in `make check`.

It lives outside `tools/ledger.py` on purpose. The ledger's docstring promises
that "nothing is interned, evaluated, or macro-expanded, so reading a book
cannot run a book", and every caller of `make check` relies on that; its
teeth-form lint is a shape test on `must-fail` bodies. All three defects this
lane exists to catch are invisible in the source and need the VALUE, so the
new tool imports the ledger's reader and adds the evaluation the ledger may
not do.

Two placement facts are load-bearing and were each measured:

- The driver runs **in the book's directory**, because a test book's
  `include-book` forms are relative to it. At the tree root every include
  fails and the probes run in an empty world — the bug that made
  `tools/proof_profile.py` report over nothing for its whole life.
- The probes are spliced in **after the top-level form that holds the
  assertion**, not at the end of the book. `tests/acl2/crypto-seam-tests.lisp`
  runs the same assertions under two digest attachments; end-of-book
  evaluation called four true assertions false, and sixteen across the corpus.

Modes: default is the static pass (no ACL2, what `make check` runs, reports
and never fails); `--evaluate` runs one ACL2 per test book and saves
`build/teeth/values.json`; `--report` adds the evaluated findings;
`--evaluate --anchors` applies each flagged unary recogniser to every constant
its book defines and prints the ones it accepts, which is how the ten positive
anchors below were derived rather than typed.

## 2. Probably fine, with the reason

Each of these was a flag that a human read and dismissed; where the rule was
wrong rather than the book, the rule was tightened and the finding is gone.

- **`(:WANT NIL)` × 5** (`peer-inbound-tests` 205, 232, 234, 235, 257): a
  two-field decision whose reason is `NIL` is a real value and its equality
  separates `:want` from `:refuse`. Rule tightened: a record whose fields are
  `NIL` is not degenerate.
- **`0` × 4** (`anchor-tests:82` `*anchor-mint*`; `store-node-teeth-tests`
  82/84, two records built to share txid 0; `nntp-tests:499`
  `fn-nntp-group-low` of an empty group): `0` is a number, not an absence.
  Rule tightened; it had produced no true flag.
- **`(:RESTART)`** (`bp-workflow-records-tests:161`): a nullary event
  constructor, so a tag-only value is its whole value. Rule tightened.
- **`index-tests:71`**: the empty range is deliberate ("including an empty
  range") and sits between two non-empty ones at :65 and :69.
- **`no-subject` × 8, and 7 more suppressed**: the corpus uses a trivially-true
  assertion as the PREMISE half of a separating pair — `(equal (append '(97 98)
  '(99)) (append '(97) '(98 99)))` says the two concatenations are the same so
  that the next line, that their tagged preimages differ, separates something.
  The check now suppresses one whose successor uses a defined name. The 8 that
  remain are all in `assumptions-tests` and `identity-tests`; see list 3.
- **18 multi-valued flags in `byte-store-tests`**: wrapped in the macros
  `bst-res`/`bst-state`, which expand to `mv-let`. A static reader cannot see
  through a macro, so it no longer guesses.
- **16 `assertion-false` in `crypto-seam`, `lace`, `policy`, `principal`,
  `served`**: my own defect. Evaluating at the end of the book read the values
  in the wrong `defattach` world. Fixed by splicing the probes at the
  assertion.
- **`nntp-index-tests:206`, `scheduler-tests:521`**: also mine. The ledger's
  reader keeps `1/2` as the string `"1/2"`, indistinguishable from a Lisp
  string literal, so the probe compared against a STRING. A term holding an
  exact rational is no longer probed.

## What the check cannot see

Stated so nobody reads a clean run as a clean corpus.

- It cannot tell an intended refusal from an accidental one. A refusal test
  SHOULD assert `NIL`; the tool reports the pair (claim, value) and leaves the
  reading to a human. Every degeneracy rule here was tightened by a human
  reading a flag, and each tightening could equally hide a true one.
- It says nothing about whether a theorem is TRUE, whether a hypothesis is
  NECESSARY, or whether a witness is the RIGHT witness for its keystone. It
  has no view of the theorem statement at all.
- **The two classes are different and it covers them differently.** "The book
  never ran" is `multi-valued-in-evaluation` (static) and `book-does-not-run`
  (from the survey's ACL2 errors); "the assertion ran and did not bite" is
  everything else. A book in the first class produces no evidence about the
  second, and `owner-tests`'s 156 assertions are currently unjudged for that
  reason.
- `--anchors` covers arity-1 recognisers over constants defined in the same
  book. An n-ary recogniser, or one whose positive witness lives in a sibling
  book, is not anchored by it and shows as a residual flag.
- Values were read with `include-book` falling back to UNCERTIFIED source for
  books the cache had no certificate for. That loads the book with proofs
  skipped: the VALUES are the book's own, but **no proof in this run is
  evidence**, and none is claimed.
- One flag per hypothesis is not checked. AGENTS.md wants a `must-fail` per
  hypothesis; the tool can see that a hypothesis of an `(implies P Q)`
  assertion is `NIL`, and nothing more. Counting a keystone's hypotheses
  against the teeth in the section that cites it is the obvious next check and
  is not written.
