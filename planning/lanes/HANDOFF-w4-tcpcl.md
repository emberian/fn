## What landed

- `books/tcpcl-records.lisp` (generated by `gen_records.py`, reproduced
  below in spirit: every record is a tagged list with shape, total
  accessors, constructor, record lemmas, forward-chaining shape facts, and
  withdrawal of every `:definition` rune). Fifteen records: the seven
  messages and the Contact Header, extension items, params, negotiated,
  inbound, outbound, session, result, and the decoder's parse outcome.
- `books/tcpcl-octets.lisp`: the exact octet grammar of every RFC 9174
  message, bounds checked before every take, per-decoder and message-level
  keystones (round trip, canonicality over arbitrary input, prefix
  determinism, consumption, exhaustive outcomes, MRU bound, need bound).
  The keystone section is generated by the lane's `gen_keystones.py`; the
  generators live in the lane's scratchpad and are quoted in this handoff's
  history (they are pure templating over the decoder table; regenerate by
  hand if needed).
- `books/tcpcl-session.lisp`: the §3.3 session machine with one inbound
  and one outbound transfer, negotiation, refusal, keepalive/idle timeout
  from `fn-clock-observationp`, SESS_TERM, MSG_REJECT; `fn-tcl-drive` as the
  served path; `fn-tcl-sessionp` carried and preserved by every transition;
  guards verified.
- `books/tcpcl-invariants.lisp`: C1 partition independence with the carry,
  C2 final ack means every segment, C3 exactly one outcome and TCP close
  never completes, C4 no interleaving, ending refuses, refused sends no
  more, keepalive zero, negotiation min/and/peer, retained input bounded.
- `tests/acl2/tcpcl-tests.lisp`: golden vectors, a full session both ways,
  a refused transfer, the chunk-size sweep, interleaving, TCP close,
  version, TLS, unknown type, MRU, wrong node ID, and the teeth.
- Makefile roots after `tests/acl2/clock-tests`; `docs/prefixes.md` row
  `fn-tcl-`; `specs/tcpcl.md` with the clause matrix.

## Proposed host surface: `host/native/tcpcl.lisp`

Over `build/lanes/w3-native-host/host/native/io.lisp` (`fnn-recv`,
`fnn-send-all`, `fnn-graceful-close`, `fnn-call`, exit codes
`+fnn-exit-uncertain+` 3 and `+fnn-exit-refused+` 1). One session global
keyed by session id, marshalled like `fn-sched-host-install`.

```
(fnn-tcl-listen port)                 ; AF_INET6 listener, no TLS
(fnn-tcl-connect host port)           ; active open
(fnn-tcl-session fd role params now)  ; the loop below, one per connection
```

The loop, per connection, with `carry` initially nil and a monotonic
millisecond source shared with the clock observation:

1. `role :active`: `(fn-tcl-open s now)`, write its `:send` events.
2. `(fnn-recv fd timeout)`: `:timeout` or empty means the peer closed or
   the contact/idle timer fired; call `fn-tcl-tcp-closed` (peer close) or
   `fn-tcl-tick` (timer) and act on the events.
3. Otherwise `buf := (append carry chunk)`, `r := (fn-tcl-drive s buf now)`,
   `carry := (fn-tcl-result-unconsumed r)`, `s := (fn-tcl-result-session r)`.
   `fnn-recv` reads at most `+fnn-max-read+` octets, so with
   `fn-tcl-retained-input-is-bounded` the buffer is below
   `fn-tcl-max-message + +fnn-max-read+` while the session is open.
4. For each event in order: `(:send m)` → `(fnn-send-all fd (fn-tcl-encode m) t)`
   tracking partial writes per HST-002; `(:bundle-received id octets)` →
   hand to `fn-bpn-receive` (bp-node) and barrier the FNBS record **before**
   writing the XFER_ACK that follows it in the same event list (the model
   emits the ack in the completing step; the host holds it until the
   barrier, bp-design §2.4); `(:close)` → `fnn-graceful-close`;
   `(:session-up n)` → tell the scheduler the contact is open;
   `(:outbound-sent/-refused/-failed id ref)` → `fn-bpn-forward-result`;
   `(:inbound-failed id)` → drop the staged object.
5. Node sends: `(fn-tcl-send s ref octets now)` then `fn-tcl-pump` after
   each successful write until it emits nothing; `:send-refused ... :busy`
   is retried after the current transfer settles.
6. Every `fnn-recv` wakeup also calls `(fn-tcl-tick s obs)` with the
   observation taken at the wakeup, so keepalive resolution is the read
   timeout (choose it below half the negotiated interval).

`fn-tcl-encode` has guard `fn-tcl-messagep`; every message the model emits
satisfies it (the host may `assert` it in `:program` mode, cheaply).

## What the interop lab (I1, bp-design §3) needs

- Two fn processes in two netns on hbox, `fnn-tcl-listen` on one,
  `fnn-tcl-connect` on the other, params with the peer's node ID as
  `expected-peer`.
- The chunk-size sweep of `tests/acl2/tcpcl-tests.lisp` reproduced on real
  sockets by `tc netem` (delay, loss, reordering is not applicable to TCP)
  and by `+fnn-max-read+` set to 1, 7, 1500, 65536.
- Link cut (`ip link set down`) inside a transfer on each side: the
  expected events are `:inbound-failed` / `:outbound-failed` and no
  `:bundle-received`, `:session-down` on both.
- Restart both sides mid-transfer and after the final ack: the ack after
  the barrier is what makes a retried transfer answer `Completed`
  (`fn-bpn-forward-result` counts it as sent).
- Evidence record under `tests/evidence/` with the octet traces of every
  message kind and the events per step.
