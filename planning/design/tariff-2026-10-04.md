## Q1. One ledger in one stobj: the typed components

**Options.** (a) Keep N private instances, each a `fn-resource-ledger` with its own
policy number (today). (b) ONE root ledger in ONE stobj, the tree layout of
`resource-vector-tree.lisp` made executable (an owner column; a sub-bank is a phase-2
row whose draws are rows owned by it), the four private instances re-expressed as
sub-banks OPENED from the root's budget at startup, connections opened at accept and
destroyed at close. (c) One flat ledger with role-prefixed slot ranges and no
sub-bank relation.

**Lean: (b), as the DIRECTION; the slice path below does not depend on it (advisory review A/Q1, accepted: its preconditions are a list, not a consequence).** Preconditions, each a named slice before any instance is re-expressed: exec `fn-rl-refund`/`fn-rl-grow`/`fn-rl-destroy` with correspondences; the tree layout as a `def-representation` instance with `fn-rl-install/draw/settle-correspondence` RE-PROVED over `fn-rt-step` (new theorems, not the flat ones renamed); one lock domain for the shared stobj (today the output ledger has its own mutex, `owner.lisp:1936`; the draw is nine u64 ops, but the contention is measured, not assumed). The output rows' free-chain columns (`fn-rl-idsi/cidsi/filesi/eoffsi/elensi/trailersi`) are already columns of `fn-resource-ledger`, so the chain lives where it lives. The budget vector of the root is the launcher's reservation, typed:
`:resident` = the figure the launcher already computes and `exec`s SBCL with
(`fn-heap-figure-octets` extended by `fn-orv-extend-reservation`,
`fn-prstartup-extend-operation-reservation`, the peer contribution — the SAME number,
not a second one); `:disk` = the profile's durable bound (T·R + H and the two image
generations of the checkpoint reserve); `:descriptors` = the observed RLIMIT_NOFILE
less the runtime's own; `:workers` = the fixed thread count the figure already holds;
`:read-ids`, `:txids`, `:config-gens`, `:conn-ids` = each space's representable
range (u64 − 1), so exhaustion is `:resources-unavailable` by name, never a wrap;
`:work` = the operator's metered-work allowance for the run (default the u64 maximum:
a METER, a cap only when the operator sets one — "QoS-operable"). `fn-rv-install`'s
slot 0 is the owner's baseline (core, static tables, the five native tables and the
reusable decoder backing DEFAULT prepays today), slot 1 the maintenance reserve
(recovery workspace, next image, active segment: `R ≥ W(P, Ω)` as a static worst case
first, grown by `dW+` before every acceptance that raises it). The roles are sub-banks
opened in order: output pool, cold pool, syncer, peer flights, then one per
connection. The partition theorems come for free: `fn-rt-sub-bank-steps-keep-the-root`
is exactly what a "private instance" buys today, with the root relation it lacks. Each
instance's `install` becomes an `open` on the root; its `fn-orv-startup-grant`-style
machine validation collapses into the root install's one check (the figure fits the
machine: PRF-198). What does NOT change: the slot/token discipline (`(SLOT . GEN)`),
the receipts (`:physical` / `:outcome`), the free-chain protocol of the output rows
(they become the output sub-bank's rows).

**Executable layout (the `def-representation` instance).** One stobj
`fn-resource-ledger` with: budget and drawn u64 columns for the root; per-row columns
PHASE, GEN, OWNER (the root for a top-level row; the sub-bank's slot for a draw
inside it), one u64 demand column per coordinate, and for phase-2 rows a drawn vector
(nine u64 columns) — the "one table, an owner column, per-row drawn columns for
sub-bank rows" already named at `specs/resource-vector.md` §"The executable
representation". `fn-rl-bank` generalises to `fn-rl-tree`; the correspondence theorems
are re-stated over `fn-rt-step` (the exec book's three stay, as the root's case).

**What would change my mind.** A measured cost of the owner column on the served draw
path (one extra u64 read; I expect none). A reason the output pool's free-chain rows
cannot be a sub-bank's draws (the chain is per-instance metadata; it survives as the
sub-bank's). If ember wants `:work` to be a hard per-connection cap by default rather
than a meter, the budget default flips; the mechanism does not.

## Q2. How `definterface :operation` charges every entry; what one generator emits

**Options.** (a) Keep the clause a linkage check and write every wrapper by hand
(today's `fn-ros-issue` shape: the body itself calls `fn-rl-draw`). (b) The clause is
a GENERATOR: the entry's body is the un-charged step; the macro emits the charged
entry the host calls, the settle consumer, the theorems, the registry row and the
teeth. (c) A separate `def-operation` macro beside `definterface`.

**Lean: (b)**, as `specs/resource-vector.md` §"For `definterface :operation`" already
specifies, with three amendments learned from the one instance. Per entry NAME, from the
loaded world, the macro emits:

1. `NAME$tariff` — a vector-valued function of the entry's inputs, SUPPLIED
   (`:tariff FN`) with a lane-proved bound — the NORM, as `owner-host.lisp:5512` says
   ("a derived logical graph count alone is not a complete physical
   allocation/collector/root-custody tariff"; advisory review A/Q2, accepted). The
   census (`def-cost`'s `:conses` twin × the cons layout constant, plus the entry's
   declared vectors, one spent identity per identity issued, the quantum's work)
   supplies the LOGICAL-constructor dimension of the bound and nothing more; a
   tariff rests on it only with the collector and native vectors named as its
   unaccounted part. `NAME$tariff-bound` (item 4) is what makes either a claim.
2. `NAME$charged` — the host-called entry: `(mv-let (word gen ledger) (DRAW slot
   (NAME$tariff args) ledger) (if (eq word :drawn) (body …) (mv word … unchanged)))`.
   The declared NAME becomes internal (`reach_check` sees the wrapper as the subject;
   the keystones about NAME transfer `:via`). A refusal returns the ledger's word with
   every stobj unchanged — generated, not written per entry.
3. `NAME$settle` — the completion consumer by token; a stale, replayed or duplicate
   completion is `:stale` and changes nothing (instances of `fn-rv-settle-once`,
   `fn-rv-replayed-completion-is-stale`). `:retention :physical-and-operation` keeps
   today's two receipts, both required.
4. Theorems: `NAME$charge-before-effect` (refused ⇒ the result is the named word and
   every stobj formal is the input); `NAME$tariff-bound` (the derived conses/visits
   twin's physical projection ≤ the tariff's `:resident`/`:work` coordinates — proved
   by the census for derived tariffs, by the lane for supplied ones); `NAME$settle-once`.
5. The dispatch row: `interface_emit.py` emits `operation: {stage, principal, slot,
   tariff, coverage, unaccounted}` into `planning/interfaces.json` (today it emits
   nothing); `cost_obligations.py` counts an entry with a `:operation` row and an
   empty `:unaccounted` as `proved`, with a non-empty one as `partial`.
6. Teeth: `defkeystone` over the four theorems with the `:witness` the entry's own
   fixture (`tests/acl2/generated/<kind>-tests.lisp`), one removal witness per guard
   conjunct, the refusal witness asserting the ledger unchanged.
7. The build check: an allocating dispatched entry without `:operation` refuses the
   image build — the END state; until then `cost_obligations.py --check`'s ratchet is
   the gate (no downgrade; the undeclared baseline shrinks).

**Amendments.** (i) `:slot` is today a fixed natural (`fn-ros-issue` slot 2). A
connection's operation draws on the connection's sub-bank, a dynamic row: `:principal
:owner :slot N` keeps the fixed form; `:principal :connection` takes the sub-bank token
from the entry's own arguments (the response identity `(:connection CID CGEN)` that
`fn-rid-connection` already produces), and `def-operation-check` checks the draw is
addressed by it. (ii) `:stage :accounted` is admitted only when `NAME$tariff-bound`
exists in the world with an empty unaccounted set — the check that today refuses
`:accounted` unconditionally becomes the check of that theorem's presence. That set
is empty for no entry today: the one instance's own `:unaccounted` holds
`fn-rl-draw` (`host/interfaces.lisp:43`), so the ledger's own operations get their
`def-cost` rows FIRST (constant-time typed stobj ops: derivable, provable), the first
move of Q6; until then `:accounted` is unreachable by construction, stated as such. (iii)
Entries that allocate NOTHING (pure classifiers such as `fn-ocap-at`) get `:operation
:none` with a `def-cost` row proving zero conses; the build check accepts that.

**What would change my mind.** If the census cannot derive a conses bound for the
served renderers in bounded prover time (PRF-1274's one instance took a source
recurrence), supplied tariffs stay the norm and item 1's "derived" is a goal, not a
default; the generator still emits 2-6. If `reach_check` cannot follow the `$charged`
indirection, NAME keeps its name and the wrapper takes NAME's old name — a renaming,
not a design change.

## Q3. A served read's tariff from the pages it touches (D41)

**The principle.** The tariff of a served read is a function of the ROW the factory
will serve (its extent descriptor: ELEN, resident or cold) composed with the
REPRESENTATION's cost model; both are read by the SAME lookup the factory uses
(`fn-cnx-view-seq` → `fn-cat-at` → the handle → `fn-arena-payload-len`), one probe and
one row, never a walk. The preview computes it before the factory; admission draws it;
the factory runs only on `:drawn`. The theorem with content is that the preview priced
the article the factory serves: same group, number, version ⇒ same seq ⇒ same ELEN.

**ARTICLE n, in the vector (the target, after ST2-4: frames filled by `pread`).**
`:resident` = ⌈ELEN/P⌉ frames of P octets pinned for the response plus the reply's
framing bound; `:work` = ⌈ELEN/W⌉ + 1 windows (W = 16,384 today); `:workers` = 1 and
`:read-ids` = 1 for a cold handle, 0 for a resident one; `:descriptors` = 0 (the
registered file owns its credit; a read borrows it); `:disk` = 0. This is literally
"the pages it touches". In slice 1 the cold handle's worker and read identity are
charged where they are charged today — the page-read pool's `(0 0 0 1 1)` draw at
cold issue (`books/decoded-worker-backing.lisp:77`) — not by the scalar descriptor;
the vector descriptor unifies the two draws later, it does not make them free now.

**ARTICLE n, in TODAY's representation (what slice 1 prices).** The exec reply is one
list cell per reply octet plus the realized extent in the bounded cache:
`:resident` = 2 · c · (L0 + 2·ELEN + 3) + c·k + ELEN, where c is the SBCL cons layout
constant of the trusted base (16 octets; `*fn-cost-contracts*` convention: measured,
stated as such), L0 the initial line's bound, 2·ELEN + 3 the dot-stuffed section
bound, the factor 2 the exec arm's TWO spines (`fn-nntp-response-block-rev`'s
accumulator, then `revappend`'s copy — advisory review D, accepted: the draft charged
one), k a constant for the effect wrapper and the cursor update. It is a cumulative-
constructor tariff: a cell is charged when consed and never credited when collected;
the collector is unmodelled and NAMED as the unaccounted part. The coefficient comes
from the representation (a list), not from an operator or a declaration; it is the
reason D41 replaces the list. The bound obligation is stated over the arm that RUNS:
`def-cost ... :conses` costs `(return-last 'mbe1-raw EXEC LOGIC)` as EXEC, so the
derived twin of `fn-nntp-article-response-of-bytes` is the exec arm's, and the
slice's `reply-within-tariff` theorem is proved of that twin, not of the `:logic` arm
(advisory review A/slice, accepted). `:work`, `:workers`, `:read-ids`
as above. The descriptor stays `(:tariff FAMILY OCTETS)` in slice 1 — OCTETS the
resident coordinate, compared to the output window's capacity exactly as today — and
becomes `(:tariff FAMILY VECTOR)` when Q1's root ledger lets admission draw the vector
on the connection's sub-bank. A big article under a small quantum is REFUSED by name
(`:output-tariff-unaffordable`): correct behaviour ("bounded"), and the measure of
why ST2's windowed renderer is next.

**LIST.** Priced per cursor quantum (`def-cursor`'s instance): `:resident` = Q rows ×
the row's rendered bound; `:work` = ⌈G/Q⌉ with G the CARRIED group count (a field
read, not a walk; `def-cost` refuses the walk by name). Second family; it needs the
LIST cursor's `def-cost` row first.

**Order of the 28 families** (each moves from `fn-ocap-unpriced-tariff` to a producer
named in a `:producer` column added to `*fn-ocap-command-families*`; the count of
`:unpriced` rows is the ratchet): ARTICLE → HEAD/BODY/STAT (same row, smaller
sections) → GROUP/LISTGROUP/NEXT/LAST (one row or a dense-run quantum) →
CAPABILITIES/DATE/HELP/MODE/QUIT (constant replies: a proved-constant conses row) →
LIST → OVER/HDR/XPAT/NEWNEWS/NEWGROUPS (cursor quanta; NEWNEWS has its `8n+2` bound
already) → POST/IHAVE/CHECK/TAKETHIS (input side: PRF-380's credits, Q4) →
AUTHINFO/STARTTLS/COMPRESS (transitions; TLS has no bound in the contract, so they
stay refused-by-name in accounted mode until one exists — stated, not hidden).

**What would change my mind.** If `fn-arena-payload-len` of a handle is not O(1) on
the served path. Its five arms (`books/payload-arena-extent.lisp:429-441`): an extent
`(nth 4 e)`; an LZ extent `(nth 6 e)`; a staged handle the stage page's length
(`fn-arx-stage-len`, one array length); a resident handle the paged arena's size
entry (`fn-arena$p-sizei`, `payload-arena-paged.lisp:405`); a `:forgotten` handle 0 —
each one field read, none realizes. A forgotten handle prices ELEN 0, which is the
reply the factory then gives (the reclaimed line, `fn-nntp-article-tombstonep`); the
slice's row keystone states that case explicitly. If the
reply bound L0 + 2·ELEN + 3 is not provable over `fn-nntp-stuff-lines` in a few
lemmas, slice 1 states it as `proof-owed` and the native still discriminates.

## Q4. The credit ledger (PRF-380) and the heap figure: related by theorem, retired

**Facts.** PRF-380: `M_base + M_cache + Σcredits + E_completion + E_runtime ≤ B`;
B is the launcher's reservation; rows keyed `(:conn . ID)` resized by `fn-mca-read-span`
to `fn-mca-need` (one article reserve while mid-article, one per queued submission);
`fn-mca-read-span-keeps-funded` is the keystone the host subject has. The figure

## D. The ARTICLE tariff, honestly

`resident = c·(L0 + 2·ELEN + 3) + ELEN` is not an honest tariff for the exec arm shown. Against the excerpt (`nntp-responses.lisp:65-100`):

- **One full spine is missing.** `fn-nntp-response-block-rev` builds `acc` (the file's own claim: one cell per octet, ≈ stuffed length). `revappend acc '(46 13 10)` allocates a **fresh spine** of length `|acc|` — revappend copies. So allocation is ≈ `c·(|acc|)` for block-rev **plus** `c·(|acc|)` for revappend, plus the `append` copying the initial line (`c·L0` — append copies its first argument), plus `fn-nntp-crlf`'s own conses, plus the `fn-nntp-reply-effect` wrapper and the outer `list`. The formula charges `c` once per reply octet; the code pays it at least twice for the section. Honest version: `c·(2·L0 + 2·(2·ELEN + 3) + k)` for small constant `k` — roughly double the proposed charge on the section.
- **Garbage retention.** `acc`'s spine is dead after revappend but heap-occupying until collection. Peak live resident during the response is `acc + reply` ≈ 2× the final reply, and post-settle the process still holds the garbage. The tariff neither charges the peak nor models when the octets are actually returned. This is exactly the "collector/root-custody" gap the tree's own frontier comment names.
- **Session update.** The `updatep` arm calls `fn-nntp-set-cursor` — uncharged allocation.
- **The bound itself is unprovable as stated for the code that runs.** `2·ELEN + 3` is a bound on `fn-nntp-stuff-lines` (the `mbe` :logic arm). The exec arm's output is `fn-nntp-response-block-rev`'s, whose length and stuffing behavior are UNSEEN; no lemma connecting them is in the slice.
- **Everything except `:resident`.** The lookup (`fn-cnx-view-seq`, whose probe is possibly a walk), the visibility test, the row read, the cold-handle worker and read-id (Q3's target includes them; the scalar slice-1 descriptor cannot express them), and the window `:work` count.
- **The +ELEN cache term** charges the realized extent once with no statement about cache admission/eviction of *other* entries — the bounded cache's occupancy changes, and that is uncharged.

As a conservative over-estimate the formula is roughly half the true cons cost; as a claim of honesty it fails on the spine duplication alone.
