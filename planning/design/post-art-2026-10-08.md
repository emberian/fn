### Hardening contracts (before ART)

`fn-pb-fixed-linep n x` recognizes a nonempty header line occupying exactly N
initial octets: no CR/LF before its final CRLF. Merely checking octets N-2 and
N-1 is insufficient: an earlier blank line could still put those octets in BODY.
The same mechanism must guard the fixed drops in `fn-pb-block-agent` and its
buffer refinement. Any generated Message-ID prefix consumed by the walk must
also be one header line: an unrestricted MSGID can otherwise contain CRLF and
reintroduce the same crossing through `fn-ipp-at-msgid`.

The per-stage compatibility statements use the unchanged downstream continuation;
full old/new agreement is asserted on the injector's actual output, which
establishes every generated-line premise. A good first stamp alone cannot
justify preserving an independently malformed later Date line.

```lisp
(implies (fn-pb-fixed-linep 49 x)
  (equal (fn-ipp-at-stamp x agent msgid params)
         (if (fn-pb-opensp *fn-inj-injection-date-field* x)
             (fn-inj-append (fn-inj-take 49 x)
               (fn-ipp-at-msgid (fn-inj-drop 49 x) agent msgid params))
           (fn-ipp-at-msgid x agent msgid params))))
(implies (fn-pb-fixed-linep 39 x)
  (equal (fn-ipp-at-date x agent params)
         (if (fn-pb-opensp *fn-inj-date-field* x)
             (fn-inj-append (fn-inj-take 39 x)
               (fn-ipp-at-info (fn-inj-drop 39 x) agent params))
           (fn-ipp-at-info x agent params))))
(implies (fn-inj-injectedp (fn-inj-decide source config obs))
  (equal (fn-ipp-with-params
           (fn-inj-decision-octets (fn-inj-decide source config obs))
           (fn-inj-decision-msgid (fn-inj-decide source config obs)) params)
         (fn-ipp-with-params-old
           (fn-inj-decision-octets (fn-inj-decide source config obs))
           (fn-inj-decision-msgid (fn-inj-decide source config obs)) params)))
(implies (fn-art-separated-headp head)
  (equal (fn-ipp-with-params (append head body) msgid params)
         (append (fn-ipp-with-params head msgid params) body)))
```

The last premise is only the location of the first blank line; it assumes
nothing about recipe validity, BODY, MSGID or PARAMS. It is the nonempty-body
arm of `fn-art-headp`; the empty-body arm is immediate. Its must-fail old-form
witness is the concrete obstruction below. Compatibility witnesses must use a
real `fn-inj-decide` result and assert `fn-inj-injectedp`, equality, and a
nontrivial parameter insertion, not merely a no-parameters case. The exact
old implementations survive only as book-level specifications/test controls.

## Concrete obstruction

In `books/injection-info-params.lisp:100`, `fn-ipp-at-stamp` recognizes only
the `Injection-Date: ` prefix and then drops 49 octets. At line 86,
`fn-ipp-at-date` similarly drops 39 octets after recognizing only `Date: `.
Neither checks a line boundary. `fn-pb-block-agent`
(`books/poster-bytes-source.lisp:91`) uses the same drops, so recognizing an
agent does not establish that the skipped material is a header line.

Use HEAD = ASCII `Injection-Date: x\r\n\r\n` (21 octets), BODY = 28 `A`
octets followed by ASCII `Injection-Info: a\r\n`, AGENT = `(97)`, MSGID =
`(60 120 64 121 62)`, PARAMS = `(59 120)`. HEAD is a proper octet list
ending at its first CRLFCRLF. BODY is valid CRLF-framed text, packable by
`fn-bch-pack`. Dropping 49 consumes HEAD and 28 body octets, leaving the
body's Injection-Info line. The rewrite inserts `;x` into that body line.
For the date case HEAD = ASCII `Date: x\r\n\r\n` (11 octets), and the same
28-octet padding meets the 39-octet drop.

The selected production DEFUN bodies were evaluated, without ACL2, by:

```sh
timeout 20 sbcl --script planning/evidence/post-art-head-local-counterexample.lisp
```

Both cases assert the entire concrete octet/separator premise, exact changed
result, and inequality to editing HEAD alone and appending unchanged BODY.
Both controls use the expected 31-character date plus CRLF; head-only editing
then agrees with whole-input editing. Output:

```text
FN-IPP-AT-STAMP: body changed after first separator; fixed-length control passed.
FN-IPP-AT-DATE: body changed after first separator; fixed-length control passed.
```

The top-level `fn-ipp-with-params` consequence is a source trace, not an
additional executed test: `fn-pb-path-line-agent` finds no Path;
`fn-pb-block-agent` drops 49, finds no matching Message-ID or Date, and reads
agent `a` from the body line. `fn-ipp-with-params` then takes its no-Path arm
and calls the tested `fn-ipp-at-stamp`. This refutes a theorem with only the
ART shape premise. It does **not** establish that this malformed injection
recipe is produced by the served injector or constitutes a remotely reachable
bug. An injected-recipe invariant could distinguish it, but the brief permits
only `fn-art-headp`; no such additional premise is silently inserted here.

Independently, with HEAD a true list of octets and BODY a packed natural,
`(append HEAD (fn-bch-unpack BODY))` is always an octet list. It cannot equal
the ACL2 object `7`, an improper list, or a list containing `:bad`.
`fn-bch-unpack-of-pack` already requires `fn-bch-octetsp`; its unconditional
counterpart returns `fn-bch-bytes`, which normalizes. Substituting that
normalization for X would change statement 2 and is not done here.

## Vocabulary for the six statements

The following are Lisp **proposition text**, not admitted events. New names
are proposed interfaces, not existing definitions. Free variables are universally
quantified. Each block is the statement to audit; the octet domain and hardened-walker references incorporate S's rulings.

ART is `(HEAD . BODY)`; empty packed BODY is **1**, not 0 or nil.
`fn-art-head`, `fn-art-body`, and `fn-art-octets` project HEAD, BODY, and
`(append HEAD (fn-bch-unpack BODY))`. `fn-art-headp` must include octet HEAD,
canonical `fn-bch-packedp` BODY, and the first-separator split (or all input
in HEAD and BODY = 1 when absent). Merely ending in CRLFCRLF is insufficient
for canonical keys. An initial CRLF is the empty-header separator, as in the current parser;
HEAD then contains those two octets and BODY remains packed. This is the
empty-header case of the first-blank-line predicate.
No new arbitrary header size ceiling is proposed.

`fn-art-decision-down`, `fn-art-sub-down`, `fn-art-owner-down`,
`fn-art-carry-down`, and `fn-art-parse-down` are logical representation maps:
replace ART payloads/parse bodies by their octets and preserve **all** other
fields, tags, statuses, ordering and errors. They may not execute on the host
path. A decision's ART payload is `fn-art-decision-payload` (slot 4).
`fn-art-sub-of`/`fn-art-record-of` convert model submissions/records to the
proposed representation; each conversion must discharge the octet premise for its payload at its caller.
`fn-art-buffer-down` is the logical byte sequence of a returned buffer/range.
These maps must be defined independently of the functions being refined;
defining a map to call its reference would prove nothing.

### 1. Split at the first separator — octet domain

Subject: `fn-art-split`, before packing. The decomposition is exact; the
separator predicate means the *first* CRLFCRLF, not an arbitrary occurrence.
This adds location to recomposition, since recomposition alone also accepts
a last-separator split.

```lisp
(implies (fn-bch-octetsp x)
  (mv-let (head body) (fn-art-split x)
    (and (equal (append head body) x)
         (or (and (true-listp head)
                  (fn-art-first-separator-headp head))
             (equal body nil)))))
```

Positive witness: X = `(88 58 32 97 13 10 13 10 65 13 10 13 10 66)`;
HEAD = its first eight octets, BODY = `(65 13 10 13 10 66)`.
The witness asserts `fn-bch-octetsp x` too. Mutation must fail: choose the last CRLFCRLF; exact
recomposition still holds, but the first-separator assertion fails.
Octet-premise removal must-fail: X = `7`. With BODY nil APPEND returns a true list;
with the other arm HEAD must contain a separator, so APPEND is a cons. Neither
can return 7. A guard declaration would not restrict ACL2's theorem domain.

### 2. ART round trip and invariant — octet domain

Subject: constructor and abstraction. Exact original octets, including binary
body bytes and trailing zeros, are required; no fixer is substituted for X.

```lisp
(implies (fn-bch-octetsp x)
  (and (equal (fn-art-octets (fn-art-of x)) x)
       (fn-art-headp (fn-art-of x))))
```

Positive witness: statement 1's X, extended with `(0 255 0)` in BODY; the
packed sentinel must preserve the final zero; assert the octet premise.
Premise-removal must-fails: X = `7`; X = `(88 58 32 97 13 10 13 10 :bad)`; or an encoder
mutation omitting the sentinel on a body ending in zero. The first two refute
the removed-premise variant, independently of proof search. The retained
premise is discharged at the wire boundary described above.

### 3. Edits commute and retain BODY — hardened reference

Subjects: the executed replacements for injection parameters, Cancel-Lock,
carried Cancel-Lock, and peer relay. All return values, including refusing or
unchanged arms, must agree; body preservation is a separate assertion.
The carried variant compares against its existing carried reference on the
same lowered carry, not against the non-carried reference under an invented
cache-validity premise. Its composition with that reference uses statement 4's
produced carry invariant and the existing `fn-apc-p` theorem.

```lisp
(implies (fn-art-headp (fn-art-decision-payload d))
  (let ((r (fn-ipp-injected-art d secret login cfg)))
    (and (equal (fn-art-octets r)
                (fn-ipp-injected-octets
                 (fn-art-decision-down d) secret login cfg))
         (equal (fn-art-body r)
                (fn-art-body (fn-art-decision-payload d))))))
(implies (fn-art-headp a)
  (let ((r (fn-cl-served-payload-art ring account msgid a)))
    (and (equal (fn-art-octets r)
                (fn-cl-served-payload ring account msgid (fn-art-octets a)))
         (equal (fn-art-body r) (fn-art-body a)))))
(implies (fn-art-headp a)
  (let ((r (fn-apc-cl-served-payload-art ring account msgid a carry)))
    (and (equal (fn-art-octets r)
                (fn-apc-cl-served-payload ring account msgid
                  (fn-art-octets a) (fn-art-carry-down carry)))
         (equal (fn-art-body r) (fn-art-body a)))))
(implies (fn-art-headp a)
  (let ((r (fn-peer-relayed-art cfg peer a)))
    (and (equal (fn-art-octets r)
                (fn-peer-relayed-octets cfg peer (fn-art-octets a)))
         (equal (fn-art-body r) (fn-art-body a)))))
(implies (fn-art-headp a)
  (let ((r (fn-pu-relay-article-art a identity expected)))
    (and (equal (fn-art-octets r)
                (fn-pu-relay-article (fn-art-octets a) identity expected))
         (equal (fn-art-body r) (fn-art-body a)))))
```

Positive fixtures, to assert each entire antecedent and both conjuncts:
injection with a generated-length stamp, plain Injection-Info and nonempty
complaints parameters; Cancel-Lock with ring/account nil (unchanged payload);
carried variant with nil carry; relay with Path and Xref in HEAD, identity
`(97)`, expected nil, and Path/Xref-looking lines also in BODY. Exercise a
nonempty ring/account and insertion as an additional Cancel-Lock control.
All use canonical ART with the body containing another blank line.

Premise-removal fixture for each head-only editor: HEAD ending in the middle
of its relevant field and the field's suffix/separator in packed BODY. The
whole reference must read across that boundary; an editor confined to HEAD
cannot agree and preserve BODY. Invalid packed sentinels separately test key
canonicality; do not demand a counterexample for a redundant type conjunct.
The concrete obstruction above retains the complete shape premise and
defeats the OLD injection member; the hardened form must leave that payload
unchanged. The five equalities below/above use the hardened list references. Proposed `def-cost` bounds must count only header-sized
cons allocation, with explicit additional dependence on configuration/key-ring
output; O(HEAD) independent of an arbitrarily large key ring is not justified.

### 4. Packed-body validity, parse and carried take — proposal

Subjects: packed scan, entire parser result, and take's stored value and carry.
Matching only stored octets would omit parse errors and leave the carried
consumers unconnected. The packed scan must carry a pending CR across block
boundaries, without materializing BODY. No premise assumes the body valid.

```lisp
(equal (fn-art-body-crlfp b)
       (fn-article-body-crlfp (fn-bch-unpack b)))
(implies (fn-art-headp a)
  (equal (fn-art-parse-down (fn-article-parse-art a))
         (fn-article-parse (fn-art-octets a))))
(let ((r (fn-apc-take-art cfg (fn-art-sub-of sub) secret)))
  (and (equal (fn-art-octets (car r))
              (car (fn-apc-take cfg sub secret)))
       (equal (fn-art-carry-down (cdr r))
              (cdr (fn-apc-take cfg sub secret)))
       (fn-apc-p (fn-art-carry-down (cdr r)))))
```

Positive scan witness: B packs `(0 255 13 10 65 13 10)`. Reject witnesses:
packed `(13)`, `(10)`, `(13 65)`; cross a packed-word boundary with CR/LF to
detect an incorrectly reset scanner. Scan and take have no explicit premise
to remove. Parser's sole premise-removal fixture: HEAD split in a field as
in 3. Positive take fixture: a local decision containing a valid article,
nil secret/account, with submission octets equal to decision octets; additionally
test peer relay and changed injection. Compare the complete returned pair and
carry invariant, not just an extracted field. Take's conversion must establish the octet premise for each payload;
its caller bridge must preserve both returned fields. These are future ACL2 witness obligations,
not executed witness claims.

### 5. Buffer fill and record encoding — proposal

Subjects: the ACL2 buffer writer behind `fnn-octets-fill-art`, and the range
encoder behind `fnn-log-publish`. The host is an I/O adapter for these entries.
The logical buffer equality describes the complete resulting byte content;
the record equality includes metadata, framing, and invalid-record results.

```lisp
(implies (fn-art-headp a)
  (equal (fn-art-buffer-down (fn-art-fill-buffer a buffer))
         (fn-art-octets a)))
(equal (fn-art-buffer-down
        (fn-rcon-record-encode-art (fn-art-record-of record)))
       (fn-rcon-record-encode-impl record))
```

The host bytes must equal `fnn-octets` of that same abstraction. ACL2 cannot
prove a raw SBCL function correct merely by naming it in a theorem; bind the
guard-verified writer through the existing representation/interface generator
and test the raw realization. No new hand-written representation twin.
Positive fill fixture: statement 2's binary/trailing-zero BODY, both empty and
nonempty initial buffers, and an exact packed-word boundary. Premise removal:
HEAD contains 256; the logical append can hold it but an octet buffer cannot.
Positive encode fixture: an existing valid record fixture with that article
payload; mutation must fail if one body octet, length, or metadata field changes.
Encode has no explicit premise; invalid record must yield the reference's nil.
Its conversion must establish statement 2's octet premise for valid records;
invalid records must retain the reference rejection.

At this base, the handoff's `io.lisp:9400` is the publish caller, not a literal
vector-to-list expression. The list conversions are `fnn-octet-list` calls in
`fnn-log-take-verdict` at 9223 and `fnn-log-take` at 9236, reached from publish.
Both must be replaced; neither moving a conversion nor bypassing its verdict
satisfies this statement. Arena page-down must also leave the executed publish
path. Error, fence, durability and recovery decisions remain unchanged; byte
equality alone is not evidence that the host integration preserved them.

### 6. Wire assembly and queue identity — proposal

Subjects: the ART payload of the terminal wire event and ART queue insertion.
The existing `fn-bch-held-lines` and `fn-post-body-octets` remain the logical
line/dot-unstuffing reference, including its totalization, not executed helpers.
The owner map includes every owner field, so enqueue agreement is not just
an article-content claim.

```lisp
(equal (fn-art-octets (fn-wire-body-art b n))
       (fn-post-body-octets (fn-bch-held-lines b n)))
(equal (fn-art-owner-down (fn-own-enqueue-art o sub))
       (fn-own-enqueue (fn-art-owner-down o) (fn-art-sub-down sub)))
(equal (fn-art-queue-unpack (fn-art-queue-pack sub)) sub)
```

Positive wire fixture: completed lines for a header, blank line, a body line
starting with a literal dot, another blank line, and binary non-CR/LF octets;
wire input doubles the leading dot and ends with a separate dot terminator.
Assert the entire resulting payload, and compare state, effects and reply lines
in the composed wire/served scan. No premise to remove. Mutations must fail:
last-separator split (check canonical HEAD too), missing CRLF, retaining the
stuffing dot, retaining the terminator, or changing line-limit behavior.
Queue positive fixture includes nontrivial id/version/account/decision fields;
must-fail mutation changes any field or swaps two queue entries. Pack/unpack
identity by itself is definitional and is **not** a keystone; enqueue/take
composition and preserved metadata supply the consequential obligation.
