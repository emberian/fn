## 1. What slice 2 is

- **Three profile fields** (D27: policy belongs to the profile): the live
  configuration's `barrier-deadline-ms` (D), `barrier-stall-ms` (H) and
  `clock-event-ms` (the committer's cadence) rows, set by `policy set SLOT
  N` (books/native-admin.lisp: positive, under the row ceiling; ACL2
  decides), read at each barrier's issue (host/owner-host.lisp
  fn-owner-barrier-limits -> books/owner-time-model.lisp fn-otm-limits:
  defaults 5,000 / 30,000 / 1,000 ms, H read as at least D). A batch in
  flight keeps the limits it was issued with.
- **The stall (H) and the posters' uncertain answer.** Past H the disk is
  `stalled` (fn-otm-disk-mode); once per barrier the committer tells every
  member of the batch in flight and of the batch prepared behind it ACL2's
  uncertain reply and closes it (fn-otm-stall-releases, the release under
  the action :stalled: never :rendered), and refuses the queued POSTs behind
  them try-later in a :reader quantum (fn-owner-shed-outcome), and journals
  the counts. A member told at the stall is dropped from the COMPLETE's
  releases (fnn-owner-unreleased): it is never answered again.
  **The documented ambiguity**: the barrier is pending, not failed; when the
  device returns, the batches complete and the told articles ARE stored.
  RFC 3977 section 6.3.1 is written for exactly this: a client that did not
  get a clear answer "SHOULD either check whether the article was
  successfully posted before resending"; the uncertain reply says so. fn
  never tells such a poster "accepted" or "refused".
- **440 at the POST command** (RFC 3977 section 6.3.1's initial refusal)
  while the disk sheds, before the article is sent: the served read runs with
  the owner's posting bit off and the bit is put back after it
  (books/owner-time-admission.lisp fn-otm-read-span); the configuration is
  never touched. An article whose POST got 340 before is still 441 (slice 1).
- **Mutating control is BUSY** (the control protocol's try-later status,
  class refused) while the disk sheds: an operator post, a live
  configuration change, a moderation request, decided before the request
  waits for the gate (host/native/control.lisp).
- **Time.** Every clock reading is an event on the scheduler's value: the
  committer's (at every wake while a barrier is pending, so a wait is never
  measured from a stale time), a status render's, and now every served
  read's (fnn-owner-advance-clock: a `:served` event whose monotonic
  reading is the owner's own observation for that read; N3 of lane
  proto-determinism). The wall clock's validity is ACL2's
  (books/clock-wall-reading.lisp fn-otm-wall-reading; the host compared the
  sign before).
- **The decision journal** (HST-028, PRF-322): each event and note is one
  entry `SEQ OP READING A B C WORD`, rendered by ACL2
  (books/owner-time-journal.lisp fn-otm-disk-step, fn-otm-note-step,
  fn-otm-start-line) and offered to the service-log writer thread, which
  appends it to `STORE/journal/decisions.fnj`.

## 2. The journal: where it goes, what it costs, what a death loses

- Never on the owner and never waited on: the entry is offered to the
  writer's queue (host/native/io.lisp fnn-journal-line, the PKT-508 queue),
  whose bound is ACL2's (books/log-sink.lisp); a stalled disk under the
  journal costs queue space up to that bound, then entries are dropped and
  counted (health's `log-sink` line), and a drop is a gap in SEQ that replay
  names, `(:gap SEQ)` -- never a silently different history.
- Replay (fn-otm-replay) of a segment (a start entry, SEQ 0, per run)
  reproduces every word and ends at the run's disk and clock; every decision
  the host asks of the value (admission, mode, wait, 441 and 440 lines,
  health's disk lines, log lines) reads only those. So the record log (the
  durable fold, lane proto-determinism) and the journal together determine
  every decision this lane owns.
- A process death with entries unflushed loses exactly those entries: the
  replay of decisions that stored nothing (a disk event keeps the pipeline;
  a refusal stores nothing; the uncertain reply promised nothing). No
  record, acknowledgement or reply depends on an entry. The file is not
  fsynced for the same reason.
- Volume: one entry per served read (the `:served` reading) plus the
  committer's while a barrier is pending: about 30 octets a read.

## 6. Packets

**PKT-861 (N2 of lane proto-determinism): reclaim's instant as a
record-log event.** Trace: host/native/checkpoint.lisp
fnn-log-reclaim-steps reads the clock (fnn-store-prepare-observation), ACL2
decides the released set (fn-lgr-decide-stream) and the records are
rewritten into tombstones; the rewritten log is checkpointed and the old
segments dropped. A decision that STORES something belongs in the record
log, not the journal. Constraints: D34 (one store format; a format change
rebuilds the fixtures); the released octets must leave the disk. Default:
a reclaim record (a new record kind, the next store format) carrying the
instant and the rule, from which ACL2 derives the released set; the fold
applies it by turning those records into tombstones, and the physical
rewrite becomes a representation change under the same logical history, so
a peer holding the pre-reclaim log plus that record computes the same
state and a bisect can place it. Rejected: journaling the instant (the
journal is for decisions that store nothing; a peer does not receive it).
Affects: the record format and codec, PRF-271's keystone, fn-cpr-replay,
reclaim_lifecycle_native, the fixtures. Not built here: it is a store-format
change of the reclaim lane's book, beyond this slice; nothing else waits on
it.

**PKT-862: IHAVE 436 / CHECK 431 during `slow`.** Today a peer's read is
the :transit class, which the gate does not admit while a barrier is pending
(a transit quantum commits inline, PKT-825 (c)), so a peer's IHAVE waits
for the barrier: pending, honest, but not the protocol's retry code. The
design: while the disk sheds, admit a transit read as a reader-class
quantum under a posture in which fn-peer-decide-offer and
fn-peer-decide-transfer answer :defer :disk-slow (436 "retry later; the
disk is slow" for IHAVE, 431 for CHECK, 436 for TAKETHIS's article: the
code class innfeed retries), so nothing is stored inline. Cost: an edit to
books/peer-inbound.lisp's two decisions (17 books call them) and to the
gate's in-flight admission (fn-ocs-next; PRF-267's keystones): a lane that
certifies itself. Rejected: presenting the node as fenced for the read (the
reply would say "recovery pending", which is false). Continues without it:
everything; peers wait for the barrier as in slice 1.
