## Process rules (learned this session)
- **Few agents.** About 5 to 8 total, mostly Sonnet; Opus for design and review; Fable only for generator/design work.
- **Long-lived lanes own code areas**, not finding lists. A lane finishes an item to LANDED before the next; WIP 2.
- **One queue** (the ledger) and **one way in** (the merge train: origin/next -> dev). Lanes base on origin/next.
- **Each check runs once** (planning/landing-pipeline.md): lanes certify their closure and run natives
  only for host changes; reviewers read evidence; the runner runs fast checks and one native/image run per promotion.
- **Cap concurrent hbox jobs per lane** (hbox reached load ~30 with ~15 REPLs and 8 certifies, slowing every check
  5-10x). Make ledger and reach incremental (X17: 21 of 25 minutes of each fast-check pass).
- **REPL and source reading before code.** Several fixes this session rested on a wrong framing a short read would
  have caught.
- **Discovery only between phases**, as a deliberate sweep, not continuously.
- **Design questions** go to a decision file and an Astra consultation (decisions/README.md); ember is asked only
  for intent, disagreements after two rounds, or irreversible / outward-facing steps.
