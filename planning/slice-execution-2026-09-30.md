# Completing whole slices

Ember's 2026-09-30 correction changes the execution practice: identify the obstruction to a complete capability, remove it confidently, and close its associated original work together. This does not change the finite scope, completion criteria, evidence standards or model policy (Sol execution, Astra only architectural synthesis).

Each owner keeps one coherent assembly and drives its first actual failure. Available source components are imported under exact leases and tested together early; unavailable definitions, incompatible APIs, failed proofs and resource-lifetime gaps remain distinct. Helpers work on the specific failure the assembly exposes. Private assembly can be NOTREADY; source publication remains the runner's responsibility and final claims still require matching evidence.

The shared P2 obstruction is assigned to `sol_index_integration` and `sol_physical`: preserve the rows-only catalog abstraction, add an operational source abstraction that carries the actual keyed layout and generation, and capture a separate iterator whose logical schedule can correspond exactly to concrete yields/candidates. Concrete backing uses funded fixed-size chunks and a bounded persistent directory/root, copy-on-write for leased generations, incremental unpublished growth/reinsertion and atomic publication. Old backing remains charged until its final query release. An eager flat resize or generation ID around mutable backing does not satisfy this contract. Query confirmation and minimum selection are shared with peering; binding projects article and binding from the same selected row.

Healthy owners checkpoint in place. The earlier automatic roughly-150-tool handoff is superseded; a real ownership/context handoff still preserves full NEXT, stops or explicitly transfers jobs, and maintains one worktree owner. This avoids synchronized restart/reorientation cycles while retaining cold-resume safety.

No new broad audit or isolated generalization is required. Existing source and evidence are inputs to completing these paths. Intermediate image construction is not the pacing step. Original requirements and terminal units remain intact; a complete slice may discharge many of them only when its evidence actually covers them.

## Account creation implementation direction

The coordinator selected a durable account creation identity derived from the committed creation-stage transaction coordinate and durable history/authority-incarnation namespace, rather than an independent creation counter. One new-account stage per coordinate gives direct uniqueness; batching requires a proved unique row ordinal. Pending rows never authorize before the final durable fence. Unchanged adopted accounts preserve identity; deletion and recreation obtain different identities. Recovery and restore must preserve or explicitly fence the namespace, never silently reuse it.

The authority envelope may represent a u64 coordinate, but admissibility follows the actual Store allocator. In the inspected consumer tree, `fn-bs-frontier-next` and the profile transaction ceiling still use `*fn-cbor-max-uint*` (u32), despite the frontier frame's u64 representation. No u64 allocator or lifetime-extension claim follows from the frame codec. The actual codec, staged producer, replay and adoption fence must land together, with structural credential bounds derived from the grammar rather than an arbitrary expanded byte allowance. This is an implementation direction under the existing identity/nonreuse contract, not a new user-ratified feature or a completed proof.

## Concrete joins resolved during assembly

The account implementation uses a 48-octet creation token: the existing served consumer incarnation (32 octets), the persisted authority-begin coordinate (8), and the persisted new-account row-stage coordinate (8). The request/cursor independently binds the durable history. Existing account tokens remain literal across adoption; a restored authority must establish the required new scope before remote use. Random bytes or inequality with only the current incarnation do not themselves prove historical namespace nonreuse. Preparation has an explicit tagged descriptor carrying its old cursor, reversed rows, forward root and phase; individually funded durable transitions establish the complete candidate before its constant-work final fence. A preallocation expectation is never a committed creation coordinate.

The producer's exclusive snapshot payload lease is not a concurrent index-query lease. Physical and index owners must attach a typed arena-incarnation grant to each query's existing ticket/slot, include all active grants in reset/join exclusion, and preserve owner-to-lifecycle lock ordering. Retaining the row and table roots alone does not retain their payload arena. Fixed reusable buffers remain charged at the pool high-water allocation after a job returns them; logical relinquishment is not evidence that garbage collection freed physical bytes.

The real long-scan/growth fixture uses distinct Message-IDs whose actual keyed tags map to one home bucket. For power-of-two growth, filtering at the largest tested home count retains the home collision at earlier generations. It exercises actual captured-layout correspondence, quantum yields, growth and old-query retention without searching for thousands of identical full 64-bit tags. Injected identical-tag tables remain separately labeled abstract or corrupted-state stress; they do not establish the faithful operational-source antecedent. Universal worst-case statements and their literal witnesses retain their original scope.

The real native admission path has an earlier duplicate precheck in `fnn-owner-attempt`, before reservation and `fn-owner-prepare-buffer`. Both must consume the same captured incoming binding/query/input lease. Repairing prepare alone leaves an observable bypass. SAME scenarios retransmit the same immutable submission profile: original POST to POST, or unchanged received relay ADU to relay. The funded runtime path must name the actual executed callback. A standalone compiled parser measurement does not bound an interpreted `fnn-call`/`*1*` fallback. Missing required callbacks or invalid carries cannot silently choose an unfunded fallback; the actual availability/refusal boundary must precede the work. Diagnostic interpreted execution remains separately scoped.

The actual source-reader scenario must continue across at least two based rows and a physical page boundary, rebinding row-specific tokens under the same captured root and exercising release/select transitions. Cancellation during byte feeding or digest work also needs its own transition to definite joined cleanup before physical settlement; normal page-change release does not prove this cancellation case.

## Segmented registry implementation candidate

Inspection of the actual extractor/runtime confirmed that growing a resizable nested array allocates and copies its whole pointer directory. Calling resize repeatedly or moving it to startup does not establish bounded allocation/work. The replacement candidate uses stock ACL2 recursive stobj-tables: the ACL2 system test `books/system/tests/stobj-table-tests-input.lsp`, section "Recursive stobj-tables", demonstrates recursive access/update through congruent table stobjs. The index owner is testing the concrete implementation; this reference is not evidence that the fn provider is already implemented or guard-verified.

Each registry node has a fixed initial table size and a fixed finite set of child-name keys (two recursive branch types and the required fixed-size page types). Thus it avoids a growing global directory and an unbounded hash population. Existing fixed table/row chunks are leaves. Published generation directories carry scalar physical page IDs rather than aliasing mutable child stobjs between parents. Ordinary missing reads must refuse before a default creator allocates; only an admitted allocation action may create a node or page.

Address the registry by recycled physical pool slot, not the lifetime query ticket. Derive the maximum slot count and radix depth from the admitted memory profile and actual runtime/codec representation. A fixed address width is acceptable only when it covers every supported profile. Charge the complete bounded root-to-slot walk as a scheduling action, with at most one fixed node/chunk allocation per construction action. The minimum executable action allowance must cover that traversal; a scalar continuation cannot falsely claim to retain a nested child pointer, and retries must not starve by repeating an unbounded path. Slot reuse waits for the final release, while retained allocated registry capacity remains charged.

The extracted-product owner checks actual exported stobj-table semantics and implements any missing backend support with a real ACL2/export/backend differential. In particular, child creators are conditional, stobj-let registration is an effect, and congruent child types and constant table sizing matter. An ACL2 foundation theorem alone does not verify a new native representation or its allocation cost. Per-query arena grant segments use this same bounded registry rather than adding another eager resizable array.
